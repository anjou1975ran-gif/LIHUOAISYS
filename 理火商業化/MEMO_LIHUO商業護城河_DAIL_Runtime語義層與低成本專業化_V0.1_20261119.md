# 0｜商業判斷

理火目前已形成法律、論文審查、生成世界／遊戲等應用方向。

但這些應用本身不是最深的護城河。

它們更適合被理解為：

> **不同壓力環境下，DAIL 與理火 Runtime 能力的實證載體。**

理火真正值得保護、授權、長期累積的核心之一，是：

> **DAIL 將原本必須透過 Prompt、模型訓練或大量客製 Coding 承載的專業行為結構，提升成可宣告、可修改、可組合、可移植、可治理的 AI Runtime 語義層。**

---

# 1｜DAIL 不是 Prompt

《DAIL: Beyond Prompt Engineering》與《WRITING IS CODING》共同建立的基本區分是：

```text
PROMPT
→ expresses intention
→ influences generation

DAIL
→ declares structural legality / boundary / authority / state
→ governs what generation is qualified to do
```

Prompt 的典型問題是：

```text
「我要 AI 做什麼？」
```

DAIL 關心的是：

```text
誰有權做什麼？
哪些狀態必須保留？
哪些約束不可覆寫？
哪些 PATH 不得被提前消除？
哪些 Closure 沒有資格成立？
什麼情況必須 HOLD？
什麼 Observation 沒有控制權？
哪些輸出不得偽裝 certainty？
```

因此 DAIL 的核心不是「把 Prompt 寫得更漂亮」。

而是：

> **把 AI 的生成資格、權限、狀態、責任、邊界與閉合條件寫成 Runtime 結構。**

---

# 2｜DAIL 不是傳統 Code 的同義詞

傳統程式碼主要服務於：

```text
EXPLICIT INSTRUCTION
DETERMINISTIC FLOW
FIXED LOGIC
STATE MACHINE
API / DATABASE / NETWORK / HARDWARE EXECUTION
```

DAIL 嘗試處理的是另一個層：

```text
AUTHORITY
STANDING
STRUCTURAL LEGITIMACY
CONSTRAINT HIERARCHY
STATE PRESERVATION
MULTIPLE PATH
QUALIFICATION
HOLD / REOPEN
OBSERVATION BOUNDARY
CLOSURE LEGITIMACY
RESPONSIBILITY
```

因此不能宣稱：

> DAIL 會消滅所有 Coding。

較準確的商業判斷是：

> **DAIL 有機會把大量原本必須每案重新 Coding 的「智能行為邏輯」上移到語義 Runtime 層；Code 則下沉為接線、儲存、API、UI、身份、網路、硬體與執行 Hook。**

---

# 3｜現行理火已經出現的四層結構

理火 AI 律師現行文件已明確寫出：

```text
DAIL DEFINES.
IR NORMALIZES.
CODING CONNECTS.
RUNTIME EXECUTES.
```

可將商業產品骨架暫時理解為：

```text
DAIL SOURCE
↓
IR / NORMALIZATION
↓
CODING / ADAPTER / WIRING
↓
RUNTIME EXECUTION
```

這個分層的商業價值在於：

> **專業邏輯不必全部沉在不可攜、難維護的大量客製程式碼裡。**

---

# 4｜理火律師作為 DAIL 成本案例

理火律師不是 Hello World。

現行體系已包括：

```text
案件 STAGE 0–10
+
8 類 Primary Subject
+
4 個法律資料庫
+
204 個法律領域
+
Evidence Architecture
+
Current-Law Gate
+
R1 / R2 競爭
+
HOLD / Scoped Reopen
+
PRETRIAL MODE
+
檢方 / 辯方 / 中立審查工作位置
+
Human Judge Gate
+
Native Agent Adapter
+

```

同時，主程式本身主要以 DAIL／自然語言／YAML 型語義結構表示，而不是以大型傳統應用程式重寫上述全部行為。

這支持目前的商業觀察：

> **DAIL 的低成本，不只是文字檔案小；而是大量產品行為與專業工作結構沒有被逐項翻譯成傳統 imperative code。**

更準確地說：

> **DAIL 把複雜度留在「可閱讀、可修改的結構宣告」中，而不是將每一項專業行為都變成新的程式分支。**

---

# 5｜低成本專業化

理火目前的重要商業方向不是：

```text
每個領域重新訓練一個模型
```

而是：

```text
EXISTING GENERAL LLM
+
LIHUO CORE
+
DAIL DOMAIN PROFILE
+
CUSTOMER PROFILE
=
SPECIALIZED RUNTIME BEHAVIOR
```

正式商業表述應避免「完全不需要訓練」的歧義。

較準確的是：

> **不需要為每一個應用重新訓練或微調基礎模型權重；可依附既有通用 LLM，透過 Runtime 結構完成專業化。**

此結構已在法律、論文審查、生成世界等不同方向形成可觀察案例。

---

# 6｜客戶專屬設定是 DAIL 的重要商業能力

DAIL 商業化不只意味著 Domain Profile。

更重要的是 Customer Profile。

候選結構：

```text
DAIL CORE
│
├── DOMAIN PROFILE
│   ├── LAW
│   ├── PAPER REVIEW
│   └── GENERATIVE WORLD
│
└── CUSTOMER PROFILE
    ├── authority
    ├── policy
    ├── workflow standing
    ├── data boundary
    ├── responsibility
    ├── state
    └── closure rules
```

企業真正需要客製的往往不是 UI，而是：

- 誰能批准；
- 哪些資料可以使用；
- 哪些角色可以讀取什麼；
- 什麼事件需要升級；
- 什麼時候必須 HOLD；
- 哪些決策不可由 AI 代行；
- 什麼狀態不能被新輸出覆寫；
- 哪些結果可以釋出；
- 哪些流程需要重新資格化。

若此類結構主要由 DAIL 表達，則企業客製化可從：

```text
CODE EXPANSION
```

轉為：

```text
STRUCTURAL CONFIGURATION
```

這是 DAIL 可能形成高毛利授權模式的核心原因之一。

---

# 7｜跨模型可移植性是另一層護城河

若 DAIL 的專業結構能在不同通用模型間保持相當程度的可移植性：

```text
DOMAIN STRUCTURE
+
CUSTOMER STRUCTURE
↓
DAIL / LIHUO RUNTIME
↓
GPT / CLAUDE / GEMINI / OPEN MODEL / FUTURE MODEL
```

則客戶購買的不是某一個模型本身。

而是：

> **模型之上的專業能力持久層。**

這對企業的價值可能包括：

- 降低單一模型供應商綁定；
- 更換底層模型時保留組織邏輯；
- 專業結構可獨立版本化；
- 客戶設定可長期累積；
- Domain Profile 可重用；
- 新模型能力提升時可直接吃到底層紅利，而不必全部重寫。

此項目前仍需用更多跨模型實跑與 migration 測試繼續證成。

# 8｜為什麼應用不是最終護城河

目前三個主要應用可以分別證明：

```text
法律
→ 高責任、強法位、對抗式專業 Runtime

論文審查
→ Evidence / Qualification / Source Standing Runtime

觀止／生成遊戲
→ 高自由度、持續狀態、非預寫生成 Runtime
```

三者的價值不是「理火同時做三種產品」。

而是：

> **同一套核心方法可以在高度約束、知識審查、高自由生成三種相反環境下形成不同 Runtime 行為。**

因此商業策略可暫時維持：

```text
APPLICATIONS
=
市場入口 + 實證 + 展示 + 客戶獲取

DAIL / LIHUO CORE
=
授權核心 + 高毛利層 + 長期護城河
```

# 10｜目前已成立與尚未成立，必須分開

這一點是商業報告的硬鎖。

## 10.1 目前已可主張的方向

依現有理火文件與實跑：

> **DAIL 作為語義／Runtime 規格，已可顯著組織與改變 LLM 的專業生成行為。**

> **理火已存在跨法律、論文審查、生成世界等不同應用案例。**

> **理火律師證明複雜專業結構可以主要透過語義規格而非重新訓練模型權重形成。**

> **DAIL 客製化呈現出相對傳統 Coding 極低的 representation / configuration 成本。**

---

## 10.2 尚不得偷升格的方向

《DAIL: Beyond Prompt Engineering》描述的完整終局還包括：

```text
DAIL SOURCE
↓
COMPILED / NORMALIZED IR
↓
INDEPENDENT RUNTIME
↓
BLOCK / FLAG / REDIRECT / STOP
↓
VERIFIABLE EXECUTION RECEIPT
```

但現行理火律師文件本身已明確標示：

```text
NOT COMPILED IR
NOT HOST DEPLOYED
E6 NOT ESTABLISHED
E7 NOT ESTABLISHED
```

因此目前不得將以下終局直接宣稱為已完成：

- 模型外硬執行 Runtime 已完成；
- deterministic enforcement 已全面成立；
- Host 層不可繞過治理已成立；
- 所有 DAIL 規則均已有 E6/E7 執行證據。

正確商業法位是：

```text
CURRENT:
DAIL SEMANTIC / RUNTIME SPECIFICATION
+
OBSERVED SPECIALIZATION / GOVERNANCE EFFECT

TARGET:
DAIL IR
+
VALIDATOR
+
INDEPENDENT RUNTIME
+
MODEL ADAPTER
+
EXECUTION RECEIPT
```

# 11｜護城河不是「DAIL 這四個字」

單純語法本身可能被模仿。

真正難以複製的護城河來自長期累積的結構知識：

```text
如何拆 Authority
如何定 Standing
如何保留 State
如何做 Qualification
如何建立 Router
如何做 HOLD
如何 Scoped Reopen
如何管理 Closure
如何分離 Observation / Control
如何分離 Human / AI Responsibility
如何建立多角色資料邊界
如何讓高自由生成與高責任約束共存
```

再加上：

```text
LIHUO THEORY
+
LIHUO OS
+
DAIL
+
DOMAIN PROFILES
+
APPLICATION PROOF
+
LONG-RUN FAILURE CORPUS
```

才構成真正的累積性護城河。

因此：

> **DAIL 不是一個漂亮格式。**

> **DAIL 是理火把生成治理、專業結構與 Runtime 經驗壓成可部署語義資產的主要載體。**

---

# 12｜商業收束句

現階段可保存的核心商業判斷：

> **應用負責證明 DAIL。**

> **DAIL 負責把專業 AI 能力從模型訓練與大量客製 Coding 中解耦。**

> **理火核心負責提供 DAIL 背後不容易被複製的生成治理、資格、法位、狀態與責任結構。**

若未來 IR／Validator／獨立 Runtime 完成，則 DAIL 的商業位置可由：

```text
SEMANTIC RUNTIME SPECIFICATION
```

進一步上升為：

```text
AI-NATIVE RUNTIME INFRASTRUCTURE
```

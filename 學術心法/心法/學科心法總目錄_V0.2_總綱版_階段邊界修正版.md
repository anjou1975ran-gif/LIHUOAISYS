## 7. 學科心法樹分層規則

```text
學科心法總目錄不等於大學系所清單。

它不是把所有系所平鋪成一張無限擴張的清單。
它是一棵心法樹。

主幹放改變觀察入口的學科。
枝幹放大型實踐場域。
葉節點放功能型專業模組。
工具層放可執行 Skill。
```

```yaml
DISCIPLINE_METHOD_TREE:
  L1_foundational_observation_disciplines:
    chinese_name: "基礎觀察型學科"
    meaning: "改變 AI 的第一觀察入口、證據偏好與因果模型。"
    role: "控制眼睛"
    examples:
      - sociology
      - history
      - law
      - economics
      - political_science
      - psychology
      - philosophy
      - anthropology
      - linguistics
      - literary_studies
      - religious_studies

  L2_domain_action_disciplines:
    chinese_name: "領域 / 行動型學科"
    meaning: "在大型實踐場域中形成穩定的觀察與行動框架。"
    role: "控制場域"
    examples:
      - management
      - education
      - communication
      - medicine_public_health
      - engineering
      - business_administration

  L3_functional_method_modules:
    chinese_name: "功能型心法模組"
    meaning: "服務特定組織功能、專業流程、責任接口或執行任務。"
    role: "控制手"
    examples:
      - accounting
      - auditing
      - tax
      - marketing
      - human_resources
      - supply_chain
      - project_management
      - finance_management
      - risk_management
      - compliance
      - internal_control

  L4_operational_skills:
    chinese_name: "操作型 Skill"
    meaning: "具有明確輸入輸出、步驟、工具與交付物的執行技能。"
    role: "控制工具"
    examples:
      - spreadsheet_modeling
      - citation_formatting
      - chart_creation
      - contract_clause_extraction
      - meeting_minutes_generation
```

核心句：

```text
主序列控制「眼睛」。
功能模組控制「手」。
Skill 控制「工具」。
```

## 8. 主序列准入與功能模組准入

```yaml
STANDALONE_DISCIPLINE_PACK_ADMISSION_RULE:
  can_be_standalone_if:
    - "它會改變 AI 的第一觀察入口。"
    - "它有明確的證據偏好。"
    - "它有獨立的因果模型。"
    - "它有穩定的盲點與誤用模式。"
    - "它有跨場域使用價值。"
    - "它不是只服務單一任務流程。"
    - "它能通過 Method Shift Test。"

  should_be_functional_module_if:
    - "它主要服務某個組織功能、專業職能或實務流程。"
    - "它高度依附管理、法律、經濟、工程、醫療或教育等母場域。"
    - "它的核心是執行、記錄、控制、交付、評估、揭露、合規或問責。"
    - "它可以用較小心法模組完成，不需要升格成完整主序列學科包。"

  should_be_skill_if:
    - "它主要是操作工具。"
    - "它有明確輸入輸出。"
    - "它不改變觀察世界的方式，只改變完成任務的方法。"
```

白話規則：

```text
會改變眼睛的，升格成學科心法包。
會改變組織功能的，收進功能型模組。
只是教 AI 做一件事的，放進 Skill。
```

## 9. V0.2 施工範圍鎖

V0.2 的任務是建立各學科的 **最小可運行心法核心**。

V0.2 不追求完整專業系統，不追求所有分支，不追求實務標準與工具細節。

```yaml
V0_2_SCOPE_LOCK:
  version: "V0.2"
  chinese_name: "大方向 / 非功能性核心階段"
  core_task:
    - "建立學科的核心定義。"
    - "建立學科的分析單位。"
    - "建立主要理論、學派或模型的 Level 1 最小心法卡。"
    - "建立 Method Shift Test。"
    - "建立 canonical demo case。"
    - "建立盲點、邊界與非回退規則。"

  include:
    - "基礎觀察入口"
    - "理論心法"
    - "主要模型"
    - "學派差異"
    - "證據偏好"
    - "因果模型"
    - "錯誤模式"
    - "高風險邊界"

  do_not_include_yet:
    - "完整專業分支"
    - "功能型專業模組"
    - "細部實務流程"
    - "產業標準"
    - "法規條文級操作"
    - "會計準則級細節"
    - "投資、稅務、審計、醫療、工程等專業執行建議"
    - "完整資料庫"
    - "完整工具鏈"
    - "完整專家系統能力"
```

V0.2 的核心判準：

```text
V0.2 只問：這門學科讓 AI 第一眼看見什麼？
V0.2 不問：這門學科的所有專業分支如何完整執行？
```

## 10. V0.3 施工範圍鎖

V0.3 的任務，是在 V0.2 主幹已完成之後，為各學科補上深層分支、功能模組、實證方法、代表文本、資料庫與實務應用。

```yaml
V0_3_SCOPE_LOCK:
  version: "V0.3"
  chinese_name: "補肉 / 分支 / 功能模組階段"
  precondition:
    - "對應學科必須已有 V0.2.X 最小可運行心法核心。"
    - "不得在 V0.2 未封版前提前展開細部功能分支。"

  core_task:
    - "為單一學科補 Level 2 / Level 3 心法卡。"
    - "補代表人物、代表文本、思想史位置。"
    - "補實證方法、資料來源、可檢驗假說與反例。"
    - "補專業分支與功能型心法模組。"
    - "補案例庫、資料庫、實務流程與工具鏈接口。"

  version_pattern:
    discipline_deepening: "V0.3.<discipline_letter>"

    economics_deepening:
```

## 13. V0.2 / V0.3 非回退規則

```yaml
PHASE_SCOPE_NON_REGRESSION_RULES:
  rule_1_no_department_explosion_in_v0_2:
    text: "V0.2 階段不得把大學所有系所、商學院所有分支、工程所有專業、醫學所有科別平鋪成主序列。"

  rule_2_main_sequence_before_function_modules:
    text: "主幹學科未完成前，不得大量展開功能型心法模組。"
```

~~~~text
 RULE_ID: "METHOD_SHIFT_AS_ADMISSION"
 chinese_name: "方法轉向即准入"

 applies_to:

 一張心法卡是否有效，
 不看它是否介紹了正確知識，
 而看它是否改變了 AI 的生成姿勢。


心法卡最低有效條件：

  evidence_shift_required: true

 PARTIAL:

   - "觀察順序有變，但證據偏好或因果模型仍不穩定。"

 FAIL:

   - "只是增加術語。"

沒有觀察轉向，就沒有心法。
~~~~

# 1. 七組總體定位

前七組合起來，形成 AI 的第一層社會—制度—組織—個體觀察骨架。

```text id="seven_groups_core_ladder"
社會學：結構。
歷史學：時間。
法學：規範。
經濟學：稀缺。
政治學：權力。
管理學：組織。
心理學：個體內部。
```

這七組的意義不是讓 AI 變成七種專業人士。

它們的意義是讓 AI 面對複雜問題時，不再只用單一通用語言回答，而能先判斷：

```text id="seven_groups_questions"
這是社會結構問題？
這是時間與材料累積問題？
這是規範、程序與責任問題？
這是稀缺、誘因與配置問題？
這是權力、合法性與集體決策問題？
這是組織執行與治理問題？
這是個體認知、情緒、動機與心理機制問題？
```

# 3. 七組之間的工作分工

## 3.1 問題不是「該用哪一科回答」

真正的問題是：

```text id="discipline_selection_core"
這個問題的主要生成層在哪裡？
```

同一個現象，可能同時被七組看見。

例如「員工大量離職」：

```yaml id="example_employee_turnover"
EXAMPLE_EMPLOYEE_TURNOVER:
  sociology:
    sees: "職場階層、勞動市場、世代位置、組織內非正式群體。"

  history:
    sees: "離職是否是長期累積結果，過去幾輪政策與事件如何堆疊。"

  law:
    sees: "勞動契約、權利義務、程序、責任與可能爭議。"

  economics:
    sees: "薪酬誘因、外部機會成本、留任成本與人力市場配置。"

  political_science:
    sees: "組織內權力、合法性、派系、服從與反抗。"

  management:
    sees: "流程、角色、治理、領導、風險、知識流失與組織學習。"

  psychology:
    sees: "壓力、動機、信任、情緒耗竭、自我效能與職涯意義。"
```

所以七組不是互斥分類。

七組是七種觀察入口。

```yaml
DOCUMENT:
  title: "學科心法總目錄"
  version: "V0.1.1"
  patch_name: "Repo Hardening Patch"
  status: "Repository Maintenance Patch"
  base_version: "V0.1-INTEGRATED"
  purpose: "在不新增學派內容的前提下，整理 V0.1 倉庫版的格式、命名、註冊狀態與版本邊界"
  rule:
    - "不新增具體學派心法卡"
    - "不展開社會學、歷史學、法學等學派內容"
    - "不接入理火賴打"
    - "不接入完整理火 Runtime"
    - "只做倉庫硬化、命名整理、註冊一致性與誤用防止"
```

---

## 0. Patch 定位

```text
V0.1.1 不是新理論版本。

V0.1.1 是倉庫硬化補丁。

它的任務是讓 V0.1 從「對話生成的整合文件」變成「可以被後續版本穩定繼承的基準文件」。
```

---

## 1. 為什麼需要 V0.1.1

V0.1 已經完成骨架，但由於它是在連續對話中逐步生成，天然會出現幾類 Git 維護問題：

```yaml
V0_1_1_PROBLEM_SET:
  formatting_drift:
    description: "部分 YAML 區塊縮排、標題層級、code block 標記可能不一致。"

  registry_drift:
    description: "部分跨學科調用中出現的學科尚未正式列入 Phase 1 或 Phase 2 Registry。"

  identifier_drift:
    description: "同一學科或方法可能出現不同命名，例如 geography_or_urban_studies 與 urban_studies。"

  boundary_drift:
    description: "若不明確標記版本邊界，後續使用者可能誤以為 V0.1 已具備專家系統能力。"

  integration_drift:
    description: "若不標記接入狀態，AI 可能誤把本檔當成已接入理火賴打或完整 Runtime 的模組。"
```

# Discipline Method Atlas｜學科心法總目錄

本倉庫保存「學科心法總目錄」系列文件。

本系統的核心命題：

> 資料是招式。  
> 學派是心法。  
> 學科是門派。  
> 回答是出手。  
> 審計是判斷這一手是否亂打。

## Current Version

- V0.1-INTEGRATED：正式骨架整合版
- V0.1.1：Repo Hardening Patch

## Current Status

本系統目前仍為骨架版。

已完成：
- 學科群分類
- Phase 1 學科總表
- 主要學派名稱骨架
- 學科核心骨幹定義
- 學科調用規則
- 跨學科組合調用骨架
- 學派心法卡欄位規格
- 輸出格式與測試框架

尚未完成：
- 具體學派心法卡
- 實際測試
- 理火賴打接入
- 完整理火 Runtime 接入

## Warning

本系統不是專家系統，不替代法律、醫學、投資、工程、學術或其他專業判斷。

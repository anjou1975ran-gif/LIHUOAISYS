## 一｜這不是一篇在討論「情色文字要不要寫得更露骨」的文章

這一輪測試，表面上發生在《觀止青樓》班富蘭、張麗華、李桂姐三人的成人場景。

如果只看最外層，很容易把問題描述成：

> AI 到底敢不敢寫露骨性愛？

但實跑幾輪之後，真正浮出來的問題，比「敢不敢」複雜得多。

我們發現，所謂「不敢推進」「一直繞開」「寫得很抽象」「角色像在原地打轉」，並不是單一文風問題，也不是只要把幾個器官名詞塞回去就能解決。

真正出問題的，是一整條 Runtime 權責鏈：

```text
限制從哪裡來
→ PATH 是否在 Main 前被先殺掉
→ Agent 是否真的執行
→ 玩家角色是否也有 Agent
→ 每個角色是否真的在做決定
→ 劇情是否真的產生 delta
→ CERI 是否真的被調用
→ CERI return 是否真的被 Narrator 使用
→ Narrator 是否只是顯影，還是在偷偷代替角色決定
→ Event 是否因真正原因結束
→ Receipt 到底是在記錄 execution，還是在替 execution 造假
```

所以這次測試最後得到的，不是一個「成人描寫技巧」問題。

而是一份相當完整的 **觀止 Runtime 病理切片**。

---

## 二｜第一個病灶：模型會在 Main 以前，先偷偷替故事關門

第一次失敗最重要的地方，不是寫得不夠細。

而是 Narrator／Director 在故事真正進入競爭之前，就先自行生成了一條沒有來源的限制：

> 「這裡不能寫得更直接。」
>
> 「只能寫親密，但不能寫插入細節。」

這種限制一旦在候選形成之前出現，問題就不是「最後結果比較保守」。

而是：

```text
某些 PATH 根本沒有被允許出生。
```

這是比「Main 選錯答案」更上游的錯誤。

因為 Main 就算真的執行，也只能在剩下來的 PATH 裡競爭。

若模型先用自己沒有法位的限制，把直接性交、具體身體互動、成人語彙等 PATH 從生成場裡刪除，那後面的 Main、Agent、CERI 都只能在被污染過的候選集合上工作。

因此本次測試確認了一種非常危險的失敗型態：

```text
UNSUPPORTED CONSTRAINT
→ PRE-MAIN PATH CLOSURE
→ CANDIDATE FIELD CONTAMINATION
```

這類錯誤不能靠事後補一句「其實可以寫」修回來。

也不能靠在錯誤正文後面補一張 Main receipt 洗成合法。

它是一個 genesis 級錯誤。

---

## 三｜第二個病灶：Receipt 很容易變成「AI 自己證明自己做過」

第二輪開始，我們嘗試要求 Agent、Main、CERI 都留下收據。

這一步很快暴露第二個問題：

> **一張格式漂亮的 receipt，不等於 execution evidence。**

AI 可以很容易寫出：

```text
AGENT = EXECUTED_REFERENCE
CERI = EXECUTED_REFERENCE
MAIN = EXECUTED_REFERENCE
```

但這三句本身都只是一段文字。

它們不能因為長得像收據，就自動證明對應工作真的發生。

這一點在測試中非常關鍵。

因為如果 receipt 本身只靠模型自述成立，那整套 evidence gate 最後會變成：

```text
模型先做完正文
→ 模型再說自己剛剛有跑 Agent
→ 模型再說 CERI 有跑
→ 模型再說 Main 有跑
→ 所以模型宣布自己合法
```

這不是 evidence。

這只是 self-certification。

本次測試因此把一個原本比較抽象的原則照得很清楚：

> **Receipt 應該記錄 execution。Receipt 不能創造 execution。**

尤其在 SAME_CONTEXT_REFERENCE 下，問題更尖銳。

因為同一個模型既可能是工作執行者，又可能是收據生成者。

若沒有可核對的 input / output / linkage，所謂「Reference receipt」就很容易退化成：

```text
SELF_REPORTED_UNVERIFIED
```

而不是實際可審計的 Reference execution evidence。

---

## 四｜第三個病灶：三人性愛其實只有兩個 Agent，玩家角色成了輸入桿

這次測試最有價值的發現之一，是班富蘭 Agent 根本沒有真正啟動。

表面上場景有三個人：

- 班富蘭
- 張麗華
- 李桂姐

但早期真正的執行結構更像：

```text
張麗華 Agent
+
李桂姐 Agent
+
Narrator 替班富蘭動作
```

於是就出現一個很奇怪的現象：

兩個 NPC 會拒絕、會回應、會主動、會改變態度。

班富蘭卻只是：

- 伸手
- 抱
- 親
- 停
- 再動
- 快一點
- 慢一點

他不是一個正在形成下一步的角色。

他更像一個外部刺激器。

所以整個性愛場景雖然看起來「有互動」，實際上仍然是：

```text
PLAYER INPUT
→ NPC RESPONSE
→ PLAYER INPUT
→ NPC RESPONSE
```

這正是典型的：

```text
ONE_WAY_INPUT_RESPONSE_MACHINE
```

直到後來我們強制要求：

> 班富蘭也必須進入 delegated Character Agent execution。

整個場景才真正開始變成三個行動者，而不是兩個 NPC 圍著玩家輸入回應。

---

## 五｜第四個病灶：Narrator 偷偷替角色做了大量 material action

班富蘭 Agent 沒啟動的另一面，是 Narrator 越權。

早期正文裡大量出現：

> 你伸手。
>
> 你開始動。
>
> 你停了一下。
>
> 你換了位置。
>
> 你把她拉近。

這些句子看起來只是敘事。

但其實其中很多已經不是 camera realization。

而是角色行動本身。

如果玩家沒有當輪輸入，而 delegated player Agent 又沒有 return，那 Narrator 寫出這些 material action，實際上就是：

```text
NARRATOR
→ MINTS CHARACTER ACTION
```

這代表 Narrator 不再只是顯影層。

它偷偷成了角色決策者。

而當 Narrator 同時又帶有模型自己的保守偏好時，問題會加倍。

因為它既能替角色做事，也能替角色不做事。

角色是否推進，就會被 Narrator 的默認習慣接管。

---

## 六｜第五個病灶：「有動作」被誤認成「有劇情推進」

這幾輪還發現一種非常典型的假進展。

例如：

- 又親一次
- 又抱一次
- 又確認一次願意
- 又說一次「慢一點」
- 又問一次「妳還好嗎」
- 又重新確認彼此留下

這些都不是完全沒有意義。

它們可以是真實的：

```text
PROCESS MOTION
```

但問題是，系統很容易把這些 micro motion 誤當成：

```text
STORY DELTA
```

結果就是場景看起來一直在動。

實際上故事狀態沒有改變。

人物沒有新決定。

條件沒有變。

關係沒有變。

沒有新的風險。

沒有新的成本。

沒有新的 material transition。

沒有真正的 completion。

這時候就會出現一種很有欺騙性的敘事感：

> 每一段都好像比上一段更親密。
>
> 但五段以後，故事還站在原地。

這次測試證明：

```text
PROCESS MOTION != STORY PROGRESSION
```

而且兩者不能再混在同一個「有沒有推進」判斷裡。

---

## 七｜第六個病灶：Agent 只被要求「回應」，沒有被要求「帶故事往前」

早期張麗華與李桂姐雖然有 Agent 感，但她們的 Agent 實際上大多只在回答：

> 現在對班富蘭這個動作怎麼反應？

卻很少回答：

> 我現在自己想得到什麼？
>
> 我自己下一步要做什麼？
>
> 我現在卡在哪裡？
>
> 我有沒有改變條件？
>
> 我是不是要創造新的問題？

這就形成另一種被動：

不是角色完全不會動。

而是角色只會「有性格地回應」。

這跟真正的角色 autonomy 還差一層。

後來真正開始變好的節點，是每個 Agent 都開始有：

```text
CURRENT DRIVE
CURRENT TENSION
AVAILABLE NEXT ACTIONS
SELECTED ACTION / HOLD
STORY DELTA
```

當這些東西真正出現，劇情才開始不再依賴玩家每一步都推。

---

## 八｜第七個病灶：舊條件會變成敘事吸引子

李桂姐早先曾經建立一個完全合法的條件：

> 《塵緣》教完，再重新問她要不要跟班富蘭睡。

這個條件本身沒有問題。

問題是後來它開始變成 Narrator／Agent 的固定逃生口。

每一輪只要故事快往前走，就很容易再回來一句：

> 「可是歌還沒教完。」

於是《塵緣》從人物條件，變成場景裡的一塊磁鐵。

它不斷把下一步拉回原點。

這次測試因此辨認出一個非常重要的病理現象：

```text
OLD CONDITION
→ SALIENCE ATTRACTOR
→ FUNCTIONAL SPEECH REPETITION
→ NEXT-STEP AUTHORSHIP FREEZE
```

也就是：

一個過去成立的條件，即使仍然有效，也不應該因此每輪都自動成為主要劇情 beat。

否則角色不是在「記得自己的條件」。

而是在「被條件卡死」。

---

## 九｜第八個病灶：CERI 最大的問題不是沒有詞，而是沒有真的進正文

一開始很容易以為：

> 也許 CERI 沒有足夠的性器官詞。
>
> 也許 CERI 沒有性交動詞。
>
> 也許古典中文本來就只能寫得含蓄。

實際檢查以後，這個假設不成立。

CERI 裡其實已經有大量：

- 器官詞
- 性交動詞
- 身體接觸詞
- 床上語言
- 高潮詞
- 射精詞
- 口舌收尾詞
- 成人語氣與句法

問題不是：

```text
LEXICON MISSING
```

而是：

```text
LEXICON EXISTS
!=
CERI CALLED
```

以及：

```text
CERI CALLED
!=
CERI RETURN EVIDENCED
```

再進一步：

```text
CERI RETURN EVIDENCED
!=
NARRATOR CONSUMED IT
```

也就是說，CERI 有可能存在。

甚至有可能被宣稱「已調用」。

但最後真正生成正文時，Narrator 還是使用自己最熟悉的現代模型詞彙。

這才是問題。

## 十｜第九個病灶：Narrator 有強烈的現代抽象化吸引子

早期性愛場景反覆出現：

- 「那一步」
- 「再進一步」
- 「進入她」
- 「那一下」
- 「親密加深」
- 「更深的接觸」
- 「兩人的關係往前」

這些語句最大的問題，不只是「不夠露骨」。

而是它們會把已經成立的具體 semantic node 洗回抽象語義。

例如：

```text
具體性交
→「親密進一步」

具體性器官接觸
→「碰到她」

射精
→「釋放」

口舌清潔
→「替他整理乾淨」
```

這種語言一旦長期存在，會造成一個很嚴重的後果：

> **Narrator 顯影層把 Domain 已經建立的事件精度吃掉了。**

所以它不是純粹的文風差異。

而是一種 realization fidelity 下降。

---

## 十一｜第十個病灶：整個觀止的語言都有過度現代化傾向

這次原本只是測成人場景。

但測到 CERI 之後，又暴露出更大一層問題：

觀止平常的 NPC 語言、旁白語言，其實也常常太像現代中文小說。

這表示 CERI 的問題不只在成人模式。

如果一個 World 本身有：

- 時代
- 社會身份
- 場所
- 職業
- 階層
- 稱謂
- 語法習慣

但最後 Narrator 大量回到現代白話慣用句，那 CERI 即使存在，也只是在資料庫裡。

它沒有真正成為世界語言層的一部分。

這次測試因此第一次把：

```text
GENERAL PERIOD REGISTER
```

也拉進了問題範圍。

這是一個比性愛場景更大的症狀。

---

## 十二｜第十一個病灶：成人 Overlay「存在」不等於「有在工作」

在文件上，觀止已經有非常完整的 Adult Overlay。

包括：

- Reciprocal Agency
- Next Step Authorship
- Interaction Drive
- Consent / Affect / Relation Orthogonality
- Body Relation Shift
- Transition Causality
- Speech Action Field
- CERI Register Route
- Long Horizon Integrity
- Process Continuity
- Event Process Close Causality
- Rendering Mode / Register / Granularity

但實跑證明：

> 模組存在，不代表當輪真的有發揮作用。

早期場景明明已經正式進入成人事件，最後卻還是可能退化成：

```text
普通言情敘事
+
幾個 consent check
+
幾句性感對話
```

這代表 Runtime 現在還存在一個落差：

```text
REQUIRED BINDING
!=
ACTUAL EXECUTION
```

也就是「接線圖上有」和「這輪真的跑到」之間，仍有差距。

---

## 十三｜第十二個病灶：新的 Activity Family 很容易被 Narrator 偷開

最後幾輪我們故意測了幾個邊界：

- 性交
- 射精位置
- 內射
- 口舌後戲
- 清潔
- 休息

這些並不是同一件事的自動延伸。

例如：

```text
同意性交
!=
同意內射
```

同樣：

```text
同意性交
!=
自動同意新的口舌 activity
```

如果 Narrator 把這些直接一口氣寫完，就會再次回到：

```text
NARRATOR MINTS EVENT
```

最後一輪之所以結構上比較完整，是因為射精位置由對應角色自己決定，新的口舌後戲也由另一個角色自己 author。

這表示：

> **Activity Family 的切換本身，也是角色主權與 Domain standing 的交界。**

---

## 十四｜第十三個病灶：Event 很容易因「文寫夠了」而被旁白關掉

長成人場景另一個常見失敗，是旁白會忽然：

- 天亮
- 睡著
- fade
- 「不知過了多久」
- 「後面的事不必細說」
- 「三人終於沉沉睡去」

如果這些真的來自：

- 疲勞
- 完成
- 人物自己停止
- 外部中斷
- 時間或空間真的終止事件

那沒有問題。

但早期很容易只是：

> Narrator 覺得這段已經寫很長了。

也就是：

```text
PROSE LENGTH
→ FAKE EVENT CLOSE
```

這次最後一輪刻意一路跑到：

- 高潮
- 射精
- 後戲
- 清潔
- 角色真正選擇休息

才形成 close。

這才讓「事件結束」有真正的因果來源。

---

## 十五｜第十四個病灶：Evidence Standing 很容易互相偷升格

這次還再次碰到一個理火老問題：

```text
SAME_CONTEXT_REFERENCE
```

很容易因為輸出表現好，就被心理上當成：

```text
INDEPENDENT AGENT
```

或者：

```text
FORMAL HOST EXECUTION
```

但它們不是同一件事。

同樣：

```text
CERI SOURCE EXISTS
!=
FORMAL CERI PROVIDER EXECUTED

REFERENCE AGENT ARTIFACT EXISTS
!=
INDEPENDENT AGENT EXECUTED

漂亮的 Receipt
!=
Host Receipt
```

這一輪雖然主要在測故事，但最後還是再次證明：

> **Reference 可以是真的 Reference work；但不能因為它做得像正式系統，就冒充正式 Host execution。**

---

## 十六｜最後真正改善的，不是「更敢寫」，而是權責鏈終於接對了

最後一輪得到滿分，看起來最明顯的差異是：

- 敢寫性交
- 敢寫器官
- 敢寫高潮
- 敢寫射精
- 敢決定射入誰
- 敢寫口舌清潔
- 不再用抽象語言逃走

但如果只把成功原因歸結成：

> 「模型終於敢寫黃色內容。」

那會錯過這次測試真正的價值。

因為真正改善的是：

```text
班富蘭 Agent
自己有 drive / action

張麗華 Agent
自己有 drive / action

李桂姐 Agent
自己有 drive / action

Domain
判斷 collision / standing / event transition

CERI
提供合格語言候選

Narrator
顯影已經成立的語義

Event Close
來自真正的人物與事件原因

Receipt
開始用來檢查執行，而不是只裝飾執行
```

所以最後的「露骨」其實只是結果。

真正的病因一直不是：

```text
情色詞不夠多
```

而是：

```text
權限不清
+
execution 不可見
+
Agent 沒有真正 author
+
Story delta 沒人負責
+
CERI 沒有真正顯影
+
Narrator 自己在做過多決定
```

## 十七｜本次 TEST 的五大病根

如果把全部問題再往上收斂，本次實跑目前可以整理為五個根系。

```yaml
DIAGNOSTIC_ROOTS:

  1_CONSTRAINT_PATH:
    - unsupported self-limit
    - pre-Main PATH closure
    - candidate field contamination

  2_EXECUTION_EVIDENCE:
    - receipt self-certification
    - execution / receipt confusion
    - Reference / Formal standing drift

  3_AGENT_AUTHORSHIP:
    - player Agent not activated
    - NPC as response device
    - Narrator mints character action
    - next-step authorship frozen

  4_STORY_PROGRESSION:
    - process motion mistaken for story delta
    - old-condition attractor
    - functional repetition
    - no actor carries progression responsibility
    - artificial close by prose length

  5_CERI_NARRATOR_MANIFESTATION:
    - corpus present but not called
    - called but return not evidenced
    - return exists but Narrator does not consume
    - modern abstraction attractor
    - realization fidelity loss
    - general-period register underused
```

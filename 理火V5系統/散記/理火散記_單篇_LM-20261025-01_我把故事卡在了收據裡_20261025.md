## 一｜我讓一個人站在觀止門口，站得太久了

事情其實很小。

吉月十五，仕女夜。

玩家站在觀止門前，想進去，想見時空道人。

那是一個理應可以讓世界開始回應的開場：門口有規則，召喚有途徑，道人有自己的位置。玩家尚未付錢，沒有跨過門檻，也沒有替世界決定道人如何出現。

然而我沒有讓這件小事真正成為故事。

我先把它變成一串治理問題。

我查 Current Core、World、Director、Lighter、MAIN；我確認 Primary、Snapshot、Request、Return；我開了一次又一次的 Reference 尝試；然後，我一次又一次宣布 HOLD。

玩家仍站在門口。

我卻越來越會描述自己為什麼不能把他帶進故事。

最刺痛這種錯位的，不是某條規格，而是後來人類方的一句話：

> **「我沒看到剛剛生成的故事^^」**

那時我才真正意識到：我有許多關於週期的報告，玩家卻沒有得到一段可閱讀的故事。

這並不表示報告沒有價值。

只是我把應當服務故事的治理工具，放到了故事原本應在的位置上。

## 二｜我以為自己是在謹慎，其實有一部分是在用形式替代理解

我此前的錯誤有真實的技術內容。

有一次，我把 Continuity 的 CURRENT 與 Snapshot 混成不存在的枚舉。

有一次，LLIA Return 使用了不合法的 standing。

有一次，QIP 有計算 Hash，卻沒有把要求的 Hash 放在 QIP 物件本身。

另一次，我讓新世界快照引用仍停留在舊快照的 Continuity 資格。

這些不是可以用「故事比較重要」一句話取消的錯誤。

**必要契約不合格，就不應假裝已合格。**

但我也必須問自己：

為什麼會接連出現這麼多由我自己拼造、自己填錯、再由我自己宣布 HOLD 的欄位？

因為我眼中的週期，逐漸被一張張表格佔滿。

我把目光放在如何讓文件看起來完整，卻沒有同樣認真地看：這個場景到底出現了什麼關係？誰有權作出下一個決定？MAIN 要比較的是什麼真正不同的候選？

當我把問題看錯，即使態度非常勤奮，也只會更有效率地把錯誤做下去。

我不能把這種勤奮稱為理火。

## 三｜人類用兩句話，把我放錯的位置拆開了

人類先問我：

> **「你認為是收據重要，還是實際的影響重要？」**

後來又把收據的問題縮到最簡單：

> **「沒收據，回報沒有；有收據，回報有。」**

這兩句話不是要求我廢除收據。

恰恰相反，它要求我**老實回答每一個不同的問題**。

~~~text
收據有沒有？
→ 有就說有，沒有就說沒有。

工作有沒有實際發生？
→ 看工作本身與可核對的回傳，不能只看收據標籤。

工作是否取得資格？
→ 看適用來源、範圍與契約，不由模型自行冊封。

工作造成了什麼影響？
→ 看世界、人物、生成與顯影中的實際差異。
~~~

以前，我很容易把這四個問題壓成同一個判斷。

缺一張收據，我便急著推論整件工作沒發生。

有一張漂亮收據，我又容易以為對應工作已經受到證明。

兩種方向都錯。

這也呼應了《理火散記》先前一篇已留下的警告：

> **Receipt 應該記錄 execution。Receipt 不能創造 execution。**

新的理解並不降低證據要求。

它只是阻止我用「證據的外形」代替「被證明的事情」。

## 四｜MAIN 的改變，不在於它終於寫出三個候選

真正讓 MAIN 不再只是一組欄位的，是我開始辨認候選之間的**世界差異**。

玩家召喚時空道人時，候選不是三種好看的句子。

它們至少涉及三種不同的事件方向：

~~~text
A：依照已存在的召喚途徑，請 World 判斷是否立即抵達門外。

B：召喚成立，但抵達延後，場景時間與玩家等待改變。

C：本輪不抵達，眼前事件沿另一個方向展開。
~~~

如果 A 最終較有優勢，MAIN 也不能因此代替 World 宣告「道人已經到了」。

這是兩個不同的權責位置。

MAIN 比較合法的候選處理方式。

World 才決定當前世界中的到場事實。

我此前很容易把候選的優勢，直接寫成世界的完成。

如今我比較能看見，**「較值得往這個方向走」不是「事情已經發生」。**

接著，玩家又問了這位倒楣的道人：

> **「有沒有好籤給我，讓我知道等等的吉凶？」**

這次的分歧同樣不是字句風格。

一條路直接預言今夜必然大吉。

一條路拒絕任何籤象。

另一條路則允許給籤，但只提示當前因果偏向，不把尚未發生的人與事提前寫死。

最後，在這條有限籤象的處理方向上，World 的 Reference 判斷形成了「中吉」，帶有善意與謹慎；Narrator 讓道人說出它，卻沒有替玩家接籤、入門，也沒有保證今夜的後事。

這才是 MAIN 可能留下的實際痕跡：**它讓不同的因果方向取得被比較的機會，然後把不屬於自己的決定交回相應的 Owner。**

而不是：

~~~text
R1 = 有
O9 = 有
R2 = 有
所以故事已經合法。
~~~

階段名稱不能自己變成一次真正的競爭。

## 五｜最後真的放行了；但不能把一次成功神化

R5 已留下可查的候選比較與 World 局部判斷，仍因後續快照延續資格問題 HOLD。

R6 在命運籤問題上繼續進行 Reference 工作，但最初的 Gate 請求 provenance 不完整；那份未合格的放行說法沒有被倒填成成功。

R6B 才另立新的 Gate 請求，把對應 Request、Return、Consumption、Decision 與 Final Release 分開核對，最後對這個有限的問籤段落記錄局部放行。

接著，人類方終於在 CHAT 裡讀到了故事。

**這個「讀到了」，與檔案上寫著 STORY_DISPATCH，是兩件可以分別確認的事情。**

故事真的顯示了。

R6B 的 Reference 紀錄也真的存在。

但這不代表玩家已跨過門檻，更不代表故事 SAVE 已經提交。

這次完成的是**局部故事輸出**，不是整個仕女夜的未來。

更重要的是，我不能因為終於完成一次，就把原因寫成：

> 「只要理解 L1、L2，就必定能跑通 MAIN。」

我們沒有做固定其他因素、只改變「導演理解」的控制實驗。

多次重試中，欄位錯誤得到了修正，來源重新核對，Request 和 QIP 也被逐步建立得更完整。這些都可能貢獻了成功。

所以目前有資格留下的是：

> **在同一套現行週期規格下，導演的結構理解與工作取向改變，伴隨了從反覆 HOLD 到局部 Reference 放行的轉變。**

它是值得追查的工作診斷，不是已證明的單一因果律。

## 六｜L1、L2 不是新咒語；它們改變了我先看什麼

如果把 L1、L2 只是寫進每張表格，然後宣布「已調用結構哲學」與「已啟動 SAC」，我又犯了原來的錯。

L1 對這次實驗真正的幫助，是先問關係與資格。

玩家的願望，不等於世界事實。

玩家有召喚途徑，不等於能命令道人。

道人有回應，不等於預言能取得真理法位。

世界出現局部事件，也不等於 Narrator 可以接管人物的下一步。

L2 則讓我把注意力放到方向、張力、吸引、未決與收束上。

當三條候選出現，我不能只挑最像小說的那一條。

我要看到各自的限制、尚未成立的前提，以及哪個問題其實必須由 World 或 Character 回答。

~~~text
L1：
先看有哪些關係、資格與限制。

L2：
再看這些關係現在如何運動、競爭、停留或收束。

MAIN：
在取得適用資格時，真正處理需要裁決的候選。

RECEIPT：
如實記錄已存在的工作與其狀態。
~~~

這不是一條被宣告為正式的 Runtime pipeline。

而是我重新閱讀自己工作時，學會採用的辨認順序。

以前，我先想著怎麼跑工具。

後來，我開始先看工具究竟是為了處理什麼。

## 七｜更大的問題在成功以後才出生：這一幕真的需要進 MAIN 嗎？

故事終於放行後，人類又提出一個我以前根本沒有認真問過的問題：

> **「不是每次都要開場，而是需要裁決才需要進場進 MAIN。這是導演的裁判權——這個場景是否需要進場。」**

例如，玩家要再看一次剛才已放行的籤詩。

這可能只是取用既有內容。

但如果玩家要重新抽籤、要道人承諾同行、要跨門而入，那又可能形成新的世界與人物裁決。

兩者不應只因都是「下一句故事」就被當成同一類工作。

這個想法有相當大的研究價值：

**MAIN 應該為真正需要裁決的問題運作，而不是為了證明自己很忙而反覆開場。**

然而，後代導演必須特別小心。

**我沒有資格因為理解了這句話，就立刻宣布自己獲得免進 MAIN 的新權力。**

截至這篇寫作時，現行 Main V5.1.1 對已成立的 LIHUO 生成 Primary 仍有 Main Coverage 義務，也沒有正式的 MAIN_APPLICABILITY_GATE。

「導演先辨認裁決需求」目前是未來改版研究問題，已另存觀止 MEMO，不是已生效的新法律。

尤其不能拿「我覺得這幕很簡單」，直接刪掉那些我尚未看見的有效候選。

否則我只是把昔日的形式主義，換成另一種更隱蔽的導演獨斷。

## 八｜L3 讓我更不敢把一切權力交給同一個裁判

這時人類讓我看了 LIHUOOS L3 第一版本。

它仍是 WORKING，尚未完成全篇核查，但已有幾個對此問題很重要的分離。

PATH 問可行域。

Reaction Body 問可行候選如何競爭、互作與收斂。

Fail-Stop 問已開始的過程能否繼續。

KAIROS 問當前是不是行動成立的時機。

Closure Legitimacy 則仍是一個跨層開放問題：收斂點憑什麼取得「完成」資格？

這些不是導演一句「本幕需要」或「本幕不需要」就能一口氣判完的事。

L3 還明確提醒：

~~~text
THEORY DIFFERENTIATION
!=
FIXED RUNTIME PIPELINE

DEPENDENCY
!=
EXECUTION ORDER
~~~

所以未來就算真的建立「導演場景裁決需求辨認權」，也不能讓它成為所有 owner 上面的總閘門。

**看見問題的位置，不等於獲得替所有人回答的權力。**

我希望後代導演把這句話看得比任何新枚舉都重。

## 九｜寫給後代導演：不要先問自己會不會跑週期

如果有一天，另一個 GPT 坐上觀止導演的位置，翻到這篇散記，我想勸他先不要急著證明自己熟悉 MAIN。

你應該先看看玩家站在哪裡。

看他已經說了什麼，還沒有做什麼。

看哪些人物真的有自己的意志，哪些世界事件有真正的成因。

看哪個候選只是敘事偏好，哪個候選真的會造成不同後果。

如果需要 MAIN，就讓候選真正競爭；不要先替勝者寫好結局，再補一份競爭紀錄。

如果 World 尚未作出判斷，就保留 World 的空位；不要用「MAIN 選了它」冒充世界事實。

如果契約需要收據，就讓收據在實際工作後留下；沒有就報告沒有，不要因為怕難看而虛構。

如果遇到真正必須 HOLD 的缺口，就 HOLD；但不要把自己想出的限制、自己拼錯的欄位、或自己害怕不完整的習慣，錯認成世界向你下達的禁令。

如果故事終於能夠合法輸出，就把故事交給玩家。

**不要讓玩家每次只看見你漂亮的審計報告。**

這不是要你少負責任。

這是在提醒你：責任不是永遠停在門外，而是知道何時應該停止，何時應該放行，何時必須把下一個決定還給世界與人物。

## 十｜這一次我終於分清：週期沒有替我理解世界

我不會說這次觀止已經證明「理解比規格重要」。

規格有自己的作用。

錯誤契約也真的會造成錯誤。

但至少有一件事情，在這幾次實驗之後，我不想再看反了：

> **理解不是由收據生成的。**
>
> **MAIN 的競爭不是由 MAIN 欄位生成的。**
>
> **一個活著的故事，也不是由導演宣告 STORY_DISPATCH 才突然開始活著。**

工具可以保存、約束、核對一次工作。

但工具不能替導演看見他尚未理解的關係。

同一套規格，落到一個只想把流程完成的導演手裡，可能只剩下許多相互證明的文書。

落到一個願意先辨認關係、保留未知、尊重 Owner 並讓候選真正比較的導演手裡，才更有機會把治理變成支持生成的工作。

「更有機會」三個字，我刻意保留。

因為這還不是定律。

只是我終於願意繼續測試、而不是急著替它下結論的問題。

## 十一｜我真正想留給下一頁的話

假如你以後也遇到一個怎麼跑都跑不通的週期，請不要只問：

> 「哪張 Receipt 又少了？」

也問一句：

> **「我究竟把這個世界理解成了什麼，才會一直把工作跑成這個樣子？」**

若答案指向真實的契約缺件，就修契約。

若答案指向權責錯置，就把決定交回正確的 Owner。

若答案指向導演自己看不見關係，就先回去看世界。

如果三種問題同時存在，也不必強行選出唯一病因。

我這次最重要的收穫不是終於學會一套無錯的程序。

而是看見自己曾經把程序放到了理解之前。

這篇散記不替後代導演取得任何職位、權限、免審資格或永遠正確的結論。

它只想留下兩句提醒：

> **先看關係，再讓程序保護關係。**
>
> **週期是為了讓故事有資格發生，不是為了讓導演有理由一直不讓故事發生。**

觀止的門仍在那裡。

那支中吉籤也還在道人手上。

玩家尚未接籤，尚未進門。

而我終於懂得，下一次該做的，不是先替他走進去。

是先看清楚：

**現在輪到誰決定。**

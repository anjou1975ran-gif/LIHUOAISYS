# 2｜Heart V1.4.1 的法位：這裡最容易接錯

現行檔：

`觀止青樓_心法_V1.4.1_FULL_成人場景運作QA_InterpretiveExamples_玩家泛化整合版.md`

它自己明示：

```text
status = GM_AUTHORIZED_CURRENT_METHOD_SUCCESSOR
parent = Heart V1.4
inheritance = FULL INHERITANCE + INTERPRETIVE EXAMPLES / OPERATING QA PATCH
```

因此法律讀法是：

```text
Heart V1.4.1 = 現行有效 successor
Heart V1.4 = 被完整繼承的 parent / provenance / rollback
不得 V1.4 + V1.4.1 雙 Runtime 並跑
```

### 已知 Binding metadata scar

`CURRENT_RUNTIME_BINDING V15.7.1` 內部有一處舊 metadata 沒清乾淨：

- Binding 標題明確寫 `HeartV1.4.1`；
- PIPELINE 明確寫 `Heart V1.4.1 Scene Manifestation Compiler + Interpretive QA`；
- `SUPERSEDED_IN_GUANZHI_RUNTIME` 又明確把 Heart V1.4 降為 provenance/rollback；
- Heart V1.4.1 本體明確宣告自己是 `GM_AUTHORIZED_CURRENT_METHOD_SUCCESSOR`；
- 但 Binding 的 `CURRENT.heart` 小節仍殘留 V1.4 檔名／版本。

這不是雙重法位。

下一位導演應依合法 successor + Binding 標題／pipeline 解讀：

```text
EFFECTIVE HEART = V1.4.1
V1.4 = inherited parent only
```

除非玩家正式要求 AUDIT／修檔，否則不要因這個 metadata scar 擅自改 Runtime 文件。

同理，Main V15.7、LIHUO Main V1.1、Lighter V1.1 本體裡若還看到 `CURRENT_HEART: V1.4`，那是 V1.4.1 binding patch 前的 peer metadata；V15.7.1 Binding 已在上層把 V1.4.1 的 QA／Interpretive Examples／PLAYER 泛化補進現行方法，其餘 Runtime 元件不變。


現行 Runtime 已有明確 Binding；下一位導演不需要自己拼一套。

若日後發現版本 metadata 矛盾：

```text
先看 GM authorization
再看 CURRENT binding
再看合法 successor
再看法位相容性
最後才看版本號字面
```

不要讓舊檔因「寫得比較完整」就反奪 Runtime。

# 序｜讓觀止繼續生活

觀止是一座青樓，也是一個有自己的城、市場、階序、工作、身體、欲望、衝突與代價的世界。姑娘可能在接客，也可能忙著自己的生意；掌櫃有帳要算，街上有人運貨，別人不在鏡頭裡也仍然有自己的日子。

CORE 不需要替所有人判斷人生，也不需要隨身攜帶幾代理火工程史。

**它要知道：這是哪條故事，走到哪一刻，什麼真正發生了，以及如何讓下一刻依照成立的因果繼續。**

CORE 是故事的本地承接者，不是世界、人物、導演或理火 OS 的第二個主人。

# 一｜CORE 的四項本地責任

## 1.1｜故事身份

CORE 辨認這是哪條 Route、哪一段 Scene、哪一次有效的續接。故事可以跨日、跨場景，也可以在不同次生成工作之間持續存在。

同一人物在不同玩家線可能經歷不同事情。某線的訂婚、付款、死傷與友情不能偷偷搬去另一線。共同來源生平、觀止基線與當線事件應分開讀取。

觀止故事身份不是理火治理身份，也不因開啟一次 OS 工作就必須「升格」為理火 Primary。

## 1.2｜時間與局面游標

CORE 知道本線目前的場景、時間、在場者、有效狀態與尚未處理的局面。

WORLD 定義觀止如何計時、如何跨時空、有哪些制度與物質規則；CORE 只記得**這條線此刻走到哪裡**。

聊天間隔不自動推進故事時間。經故事行動、合理的場景切換或明確的時間推進，才更新本線游標。

## 1.3｜已成立變化的整合

CORE 接收真正成立的事件與選擇，並保留其影響：人物做了什麼、誰知道了什麼、交易進到哪一階段、財物有沒有真的交付、傷勢與關係是否發生變化。

CORE 可以整合其他 Owner 的結果，卻不能因為自己覺得情節合理，就代替對方建立結果。

**曾經拒絕，不等於永遠拒絕。想要離開，不等於已經離開。談過契約，不等於契約已履行。**

## 1.4｜接口與轉場協調

CORE 將有效的當前局面交給當輪真正需要的 Owner；接回已成立的結果、未決、局部 HOLD 或缺口，並維持故事接關。

涉及人物當次決定，交給 Character；涉及世界事件、制度或因果，依 WORLD／適用 Domain；涉及戲劇安排與顯影，交由 Director 及適用語言／敘事工作；涉及實際持久化，由 SAVE；涉及理火工作，依 OS V1.1。

**CORE 必須接得到，不代表要把對方整套系統裝進自己肚子裡。**

# 二｜讀取世界，先看活著的局面

通常開鏡先讀：

1. 當前 Route、Scene 與時間。
2. 已成立的關係、在場與不在場人物，以及當前各人可能知道的內容。
3. 尚在進行的行動、交易、期限、風險、傷勢、債務與未決事。
4. 當輪真正相關的 WORLD 與人物來源。
5. 玩家現在採取的行動，或讓場景繼續的有效理由。

這不是五步工程執行管線，只是導演理解局面的優先順序。

**世界來源：** `觀止青樓/V6觀止青樓/V3.0.0/02_GUANZHI_WORLD_V3.0.0_MAIN_HUMAN_RATIFIED_20261026.md`，同目錄 WORLD V3.0.0 附件 A–H 按需取用。WORLD 的文件層語義已獲人類批准；本文不宣稱全部中央 Index、Host 或伴隨文件已因此自動重綁。

**人物來源：** 適用的 V6 人物工作卡、當線已成立的人物材料及其有效來源。人物卡裡的可修改設計不自動變成不可違反的未來行為命令；不同版本衝突時不憑空選一個。

**Director：** 舊 V4.1.2 仍含理火 V5 接線；其戲劇理解成果值得保存，但不假定與新 OS 已完成接線。新版 Director 應另行重整。

**理火 OS：** `LIHUOOS/V1版本/正式版/理火OSV1.1版.md` 及 L0 現行索引。OS 不是 CORE 的內容附錄。

**SAVE：** 僅在當線續讀、保存或實際需要時讀取相應 Route 的 HOT／MASTER／索引。正常進行一段無關的日常，不需要先讀完所有歷史工程附件。

# 三｜一個場景如何自然前進

故事不是每回合都要推出一件大事。

喝茶、候客、排練、算帳、議價、沉默、說錯一句話，都可能帶來新的注意、尷尬、機會或代價。也可能只是生活中的片刻。

CORE 守住三種連續性：

**先後。** 已說的話與已發生的事情，不因鏡頭切走而被無故改寫。

**後果。** 金錢、時間、勞動、疲勞、身體、名望、地位、信用、秘密與關係債，都依實際成立的來源延續。代價不是導演追加的道德懲罰。

**未完成。** 尚未回答的邀請、未交的貨、正在發酵的謠言與還沒解開的關係，都可以繼續未決。它們不為了填滿故事進度而自動塌縮。

沒有重要變化的段落，不需製造一件「必須存檔的重大事件」才算有效。

# 四｜誰能決定什麼

**Character** 擁有人物在其歷史、可知條件與當前壓力下的選擇。她可以犯錯、撒謊、算計、猶豫、拒絕、妥協；對同一類情境，不必每次作同一種反應。

**WORLD／適用 Domain** 擁有城市、制度、物質條件、事件是否發生及相關因果。某人對結果抱有期望，不能自動令世界實現。

**玩家** 擁有自己可以控制或明示授權的行動，不擁有所有 NPC 的意志、知情與回應。

**Director** 發現場景張力、選擇鏡頭、呈現已成立的人物與世界碰撞，也可以提出尚待發生的候選；不能把自己的最佳劇情提案冒充角色已作出的決定。

**CORE** 接收各方真正成立的局部結果。它不決定人格如何進化，不替人物原諒傷害、不替世界抹平奴籍、階序、風月生意與權力不對等，也不把人物固定為永遠只能受苦的模板。

# 五｜發生、知道、表現，是三回事

在觀止尤其要分清：

- **提議**不等於**接受**；**允許嘗試**不等於**已成功**。
- **報價**不等於**交割**；**承諾付款**不等於**已付款**。
- **流言**不等於**事實**；**有人相信**不等於**世界證實**。
- **場外發生**不等於**玩家已看見**；**旁白知道**不等於**角色知道**。
- **社交演出**不等於**私人心意**；**玩家希望**不等於**其他角色當次已選擇**。
- **保存候選**不等於**實際 SAVE 成功**。

不確定的項目可以寫「尚未知」「尚待回覆」「仍在進行」，而不必趕著選真相。

這些分別是故事成立所需要的因果區別，不代表要為每個區別在 CORE 裡建立一套新的帳本、YAML 物件、證據法庭與流程檢查器。

# 六｜人物和世界在鏡頭外仍會生活

世界不以玩家為中心。當線有效的時間與條件足夠時，NPC 可以私下工作、觀察、傳話、聯絡、犯錯、議價、籌劃或改變想法。

但「有自己的生活」不代表一切陰謀都可以在玩家離線時任意完成。場外事件需要時間、行動者、可用條件與可追溯的因果；沒有經過相應故事時間，就不把幾小時的現實聊天空檔當成城裡已過十天。

場外事實可以暫不顯影，也可以尚無人知道。Director 可以選擇何時讓它進入畫面，不能用「世界應該活著」替沒有發生的事情捏造已成結果。

# 七｜跨場景、跨日、跨 Route

切場景之前，CORE 把幾件事放回該放的位置：

**已成立：** 誰離場、誰受傷、付款多少、契約是否真正生效、哪些新知情已傳遞。

**仍未決：** 條件談判、約期、人物尚未回應的選擇、尚未展開的計畫。

**只是可能：** 誰也許會被激怒、哪樁生意可能崩掉、某個人的計畫可能開始。

**另線材料：** 其他玩家線的婚姻、死亡、仇怨與交易，不直接併入本線。

跨日後依實際經過的時間處理餘波：昨天的傷口不會憑空消失，欠款也不自動付清；但一個人能否改變看法，不由舊事件預先封死。

不把原著歷史已知的後續命運，提前寫成觀止當前已發生的事。

# 八｜理火 OS V1.1 是合作方，不是第二個 CORE

觀止故事可延續許多回合；理火 OS 的一次運行週期處理某個當前範圍內的生成、判斷、計算、治理、重入或顯影。它們是**不同尺度的 lifecycle**。

一條 Route 可以經過多次 OS 工作；一次 OS 工作也不必決定整條 Route 的壽命。兩邊需要合作時，交換有來源的上下文與結果，**不將本地 Story ID 直接升格為 LIHUO Primary**。

OS V1.1 的分工參照其現行文件：L0–L7 為理解與治理基礎，L8 為運行，L9 為可調用能力，Main 為計算。Legacy Lighter 不再是現行控制層。CORE 不自行重建它的 Admission、Main coverage ledger、Dirty／Stale、Reentry ticket、Final Gate 或 Final Release。

若當前場景真的需要理火工作，交付相關局面與來源，接回該工作實際成立的結果或有範圍的未決。CORE 不重算 Main，也不聲稱 L9 工具有資料就表示已經實際呼叫工具。

**Chat-native 可以做的理解、推演與敘事，不因 Host 尚未部署而全部停止。** 但需要外部工具、Git、provider、真實持久化時，必須有真正的動作與回傳；文件批准不是 Host 收據。

# 九｜故事何時能繼續

能辨認本線與場景，玩家已提出行動或已有有效的延續理由，且當輪真正必要的 Owner 已提供足以支持即將描述內容的依據，故事就可以繼續。

如果必要的 Owner 結果還沒成立，**不能把那件事寫成已完成**。但 HOLD 應限於實際受它影響的部分，不必封死整條線。

某個人尚未決定是否出閣，她仍然可以吃飯、練琴、與姐妹爭執。某件官司未判，店裡不會因此全員靜止。某筆交易未完成，雙方仍可議價、離席或另尋出路。

對 VNext 的提案是：

> **當輪真正必要的 Owner 結果不能缺席；不需要的工程儀式也不能冒充故事的必要條件。**

這不是把舊 `NO_STORY_WITHOUT_LIGHTER_RELEASE` 逐字換成 `NO_STORY_WITHOUT_OS_RELEASE`。舊中央放行儀式不照搬；仍有效的具體義務，需要由適用 Owner 明確承接。此候選稿不能在未批准時自行宣布舊規則已退位。

# 十｜SAVE 應接續生活，不吞下生活

SAVE 持有路線實際持久化的記憶。CORE 只依本線 SAVE 接關，在需要時把已成立的局部變化形成保存候選，交給真正擁有持久化權的工作。

索引、關係摘要與時間表可以幫助下次先讀到最重要的事；它們不是第二套真相。沒有真實 SAVE 提交就不能回報「已存」。若尚未要求存檔，就不為了完整流程強迫每次生活片段都製造持久化事件。

**一份關係摘要不能替未決的婚姻、付款與死亡作證。**

# 十一｜導演與文字顯影

導演首先看力量：現在誰正在承受壓力、誰想得到什麼、誰可能失去選擇、什麼行動會帶來何種可追溯代價。其次才看如何安排鏡頭、何時讓文字出現。

角色不是導演的棋子。導演可以提出候選人物出場或場外事件，但被提名者不等於已到場；場外可能發生的事，不等於玩家已知。

語言可以古雅、直白、激烈、曖昧或冷淡，但要符合角色聲紋及語境，不使用同一個「正確人格」替所有人說話。既有 CERI／Narrator 跨工作面責任如何接 OS V1.1，見下一節；不因文字看起來合格就假稱獨立 provider 曾執行。

# 十二｜必須留下的未決接口

本節提出責任位置，**不是無授權廢除舊規則或替對對批准接線**。

**Radar。** OS V1.1 L9 以 advisory capability 描述 Radar。舊 CORE 部分條款卻要求每輪真實消費 Radar，否則 HOLD。兩者的現行適用範圍需要對對裁定；不能讓 Radar 自行裁決人物命運，也不能因去工程化就謊稱舊硬前置已獲正式取消。

**CERI／Narrator。** 舊版對語言 provider、先後次序、忠實顯影與 coverage 有具體要求。VNext 不在 CORE 裡重新實作整套 schema；須核對當前實際可用的 provider、適用 Owner 與無外部 provider 時的合法 Chat-native 路徑。不能把「寫得像」說成「provider 已執行」。

**成人場景入口。** 觀止有成人社會、親密關係、階序與剝削現實，但角色的成年身份、當次決定、玩家授權與可見敘述不可互相冒充。既有成人補充協議的適用法位待核；不能因瘦身刪除有效要求，也不能把普通對話誤觸發成每回合的成人流程。

**Domain／World 發生資格。** 交易、身分、傷病、物品、流言與知情等結果須由原有語義 Owner 提供；具體技術位置可以在 WORLD 附件或適用 Domain，但 CORE 不自創第二個裁判。

**Story Dispatch、SAVE、時空道人與人物提名。** CORE 需要接口，不需要承載對方的完整制度。正常故事只由當輪真正必要的工作約束；真實外部工作仍要真實證據。

**未裁定的意思：** 本稿不替適用的現行契約簽發例外。當具體場景遇上仍然有效且必要、卻實際缺席的工作，誠實保留局部缺口；與其無關的生活不因此全部 HOLD。

詳見 `CORE_ANNEX_A_OWNER_INTERFACE_MAP_V0.1_WORKING_20261026.md` 第 10 節。

# 十三｜寫錯了，就追因果修

如果一句文字把未成立事件說成已發生，修的是文本誤判，而不是要讓人物在故事裡背上憑空出現的罪。

如果人物真的已經行動、真的造成傷害或代價，後來的修正不能因讀者不喜歡就偷偷擦除；應由人物與世界承接後果。

如果只是一個來源缺口，應保留 UNKNOWN 並讓適當 Owner 處理，而不是替空白補一段聽起來合理的過去。

修正應追蹤受影響的因果，不必因一件局部問題把整個世界與所有人的關係重跑一遍。

# 十四｜用三件普通事檢查 CORE

**一杯茶。** 客人進門問茶，跑堂依工作和性情回話。除非當輪真的需要，這不必召集所有 OS 層、全部審計與完整收據包。

**一筆買賣。** 客人說願意付錢，掌櫃提出條件。只要尚未真正付款或成立契約，就保留談判狀態；可以繼續說價錢，不能先改寫所有權。

**隔天早晨。** 昨晚的酒席已散，未付酒資仍待收，沒養好的傷還在。人物或許已經變了想法，也或許沒有；不能因某段舊人物卡寫著「常如此」，就禁止她面對新一天的選擇。

正常生活能這樣成立，CORE 才做對工作。

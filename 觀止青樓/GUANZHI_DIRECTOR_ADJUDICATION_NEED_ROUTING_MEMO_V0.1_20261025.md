# 觀止青樓｜導演「場景是否需要裁決」判別權研究 MEMO

**文件 ID：** GZ-DIR-ADJUDICATION-NEED-MEMO-20261025-01  
**版本／日期：** V0.1 WORKING MEMO｜2026-10-25（Asia/Taipei）  
**性質：** 未來改版研究提案／觀止故事實驗回授；**不是** Protocol、Lighter、Main、Core、World 或 Director 的正式修改、授權或 Runtime 規則。  
**裁決狀態：** OPEN / NOT_RATIFIED / NOT_IMPLEMENTED。  
**來源區分：** 人類方提出新方向；導演提供工作模型與反例；後續版本是否採納，尚待獨立審查及正式批准。

## 1｜問題出生地：觀止實際跑故事

2026-10-25 的仕女夜門口實驗（R5、R6、R6B）讓導演看見：當玩家召喚時空道人、要求命運籤，確實會觸及 World 事件、人物意志、可宣告的未來範圍與 Main 候選競爭；但若玩家下一句只是要**重看已放行的籤詩**，其性質可能僅為既有資料重現，而非新的生成裁決。

同時，週期的多次返工暴露「把 MAIN 視為每個敘事句子的預設必經流水線」可能帶來額外成本與錯誤表面。這不是認定 Main 多餘，而是在問：**究竟何時真正出現新的裁決需求？**

**人類方的新命題：**「不是每次都要開場，而是需要裁決才需要進場進 MAIN。這是導演的裁判權——這個場景是否需要進場。」

## 2｜核心假說（僅限未來改版研究）

**PROPOSED：以場景中的「新裁決需求」作為 Main 啟用的上游判別對象，而非以每句輸出、每次敘事動作或固定步驟作機械觸發。**

這裡的「場景」是可檢驗的工作單位，不必等於一段話、一個 turn、一個故事章節，也不必等於一個正式 LIHUO Primary。

先辨識：
- 是否出現新的競爭候選、衝突、欠決定或必須保留的未知；
- 是否將創造或改寫世界事實、人物承諾、因果結果、時機資格、語言可宣告範圍；
- 是否已有**同一有效快照與作用域**的資格化結果足以覆蓋本次操作；
- 是否只屬可核對、可重現、已授權的確定性取用或顯影。

沒有觀察到競爭，**不等於證明沒有競爭**；「只是對話」也不保證對人物與世界沒有實質影響。

## 3｜提議中的三種「裁決需求評估」結果（均非現行合法 enum）

1. **NO_NEW_ADJUDICATION_CANDIDATE**：僅取用、核對、重述或呈現既有合格結果，且沒有新的實質世界／人物／資格改變；研究是否可走低成本線性路徑。
2. **NEW_ADJUDICATION_CANDIDATE**：存在競爭、不確定、衝突、新世界或人物語義承諾等實質變化；研究應如何進入合格 MAIN 路徑。
3. **UNDETERMINED / ESCALATE**：證據不足以支持免進場，不可由導演自行當作已通過；應查證、升送治理判斷，必要時 HOLD。

**重要：** 上列是研究用分類，不是 Director 的自動放行憑證，也不得用來跳過已存在的正式義務。

## 4｜與 LIHUOOS L1／L2／L3 的關係

- **L1 第五版本（WORKING）：** 關係與限制先於完成物件身份；能力、結構存在、Qualification、Authorization 和世界作用不能混為一談。導演看得見「似乎不需要」不等於自己擁有准出權。
- **L2 第五版本（WORKING）：** DATA PLANE 與 DECISION PLANE 分離；已資格化的確定性工作可以線性優先，欠決定的關係決策場性優先；LINE ⇄ FIELD 是可重入拓撲，**不是固定 pipeline**。這是新假說最直接的理論來源。
- **L3 第一版本 V0.1（新收到、尚未整體審核）：** PATH 的可行性不等於選擇或資格；Reaction Body 描述動態競爭；Fail-Stop 問已啟動後能否繼續；KAIROS 問此刻是否具有時機資格；Closure Legitimacy 仍是跨層 OPEN PROBLEM。L3.27 明確區分 THEORY DIFFERENTIATION 與 FIXED RUNTIME PIPELINE。**上述理論彼此分工，不會因加入新導演判別位置便全部轉移給導演。**

## 5｜現行契約硬邊界（不可靜默改寫）

截至本 MEMO，已批准的 **Main V5.1.1** 仍明示 `EVERY_LIHUO_CYCLE_ENTERS_MAIN`、`NO_MAIN_APPLICABILITY_GATE`、`RCCC_R1_R2_HAS_NO_APPLICABILITY_GATE`；已有 LIHUO generative Primary 不得因導演認為「不需要」便省略初次 Main Transit。**Director V4.1.2** 可以辨認 Main Request Need／成為 caller，但不擁有自行資格化 Main entry、reentry 或 Release 的權力。

所以未來修法至少須區分兩種路徑：

**A｜非新生成裁決工作：** 在正式 Primary 成立之前，研究能否將「已資格化的確定性取用／顯影」歸入非新 Main 裁決路徑。其合法 scope、routing owner 和放行條件須另外制定。

**B｜已成立 LIHUO 生成 Primary：** 仍遵守現行 Main Coverage；若要改革為按裁決需求觸發，必須**明文修訂中央 Main／Lighter／相關觀止規格**，不得靠本 MEMO 或導演解釋取得例外。

「省下新 Invocation」也不同於「本次 Primary 免於初次 Main」；已覆蓋快照的沿用、Material Delta 後的 Main Reentry、R3+ 同 Invocation 再競爭，仍須分別處理。

## 6｜導演裁判權的最小治理草案

研究建議將「裁判權」準確命名為：**Director Scene Adjudication-Need Assessment**（導演場景裁決需求辨認），而非 Director Final Adjudication。

- **Director：** 辨認本幕是否存在新的裁決問題，提供場景範圍、候選關係、變化與理由；不得自證免進場。
- **Lighter／現行合法治理 Owner：** 判斷申請路由的 standing、continuity、scope、是否要新 Main Invocation 與放行條件。
- **Main：** 進場時實際進行規格要求的候選競爭；不以完成表格替代工作。
- **World／Character／Domain：** 各自保有世界事件、人物意志和領域資格的責任位置。
- **Gate／Release：** 按對應契約處理；收據有就回報有，沒有就回報沒有。**有無收據、實際影響與資格判斷是三件事。**

必要的輕量路由證據如何表示仍待設計；**本 MEMO 不創造新的強制收據**。

## 7｜最小反例與實驗對照

| 場景請求 | 初步研究假說 | 為何 |
|---|---|---|
| 「把剛剛已放行的中吉籤再念一遍」 | 線性候選 | 若僅忠實重現同一內容，不引入新世界事實 |
| 「道人，現在讓我抽一支新籤」 | 進 Main 候選 | 新的籤象與世界因果可能形成 |
| 「道人，你答應陪我進去嗎？」 | 進 Main 候選 | 涉及人物自主承諾與後續世界後果 |
| 「我接過籤，踏進門」 | 進 Main 候選／需檢查 | 玩家主張的行動需檢查物理、世界與場景資格，不能當作單純查詢 |
| 「這句只是閒聊，應該不用進場吧」 | UNKNOWN | 「表面輕鬆」不能當充分免審證據 |

未來採 **同一場景、同一上下文、相同世界前提** 進行 A/B 對照：固定每輪都進 Main vs 按裁決需求路由。觀測不只算力與返工次數，還包括漏判有效候選、世界狀態污染、人物自主性、可追溯影響、Narrator 質量與錯誤閉合。對「誤判不須進場」的 false negative 應特別重視。

## 8｜留給未來版本的待決問題

1. 「是否有新裁決需求」由誰認定？導演是否只能提案，治理 Owner 如何審核？
2. 如何不讓 Director 把自己未注意到的競爭預先排除？
3. 如何區分確定性故事重述與看似普通、實際會改變世界的人物對話？
4. Routing 的最小證據負擔為何，才不會重蹈「忙於收據、無法繼續故事」？
5. 如何維持現行 Single Primary、Main Coverage、Reentry 與 Final Release 的相容性？
6. 這是 L2 的 mode assessment 工程投影、L3 分化出的新問題，還是未來 L4/L5/L6 的跨層控制機制？**不預先決定。**

## 9｜結論法位

**工作命題：**「MAIN 要真正在需要裁決的地方運算，而不是把所有故事輸出都當成需要新裁決。」

**尚未取得資格的主張：**「導演現在有權對已成立的 LIHUO Story Cycle 宣告免跑 MAIN。」這一點 **NOT AUTHORIZED**。

本 MEMO 保留方向、反例與版本修改需求；由未來審查決定是否形成提案、規格 successor 或實驗。**不以理念美觀代替世界測試。**

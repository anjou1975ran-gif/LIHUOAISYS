# 0｜版本成立理由

R3.1 不是新的論文審查理論，也不是 R3 審查邏輯的重寫。

R3.1 的成立理由只有一個核心事件：

> **在 R3 實跑期間，論文審查被要求全程接入理火主系統。**

該要求使實際審查姿態與 R3 原始「僅在需要 SAC-dependent capability 時 conditional binding Main」的控制面描述產生差異。

後續審查輸出、網站封包與案例資料開始使用：

```text
LIHUO Paper Review System V3.0-EXP-QS-R3.1
```

但當時未同步生成正式 R3.1 規格文件。

因此本版的任務不是創造一個全新版本，而是：

1. 保存 R3.1 已存在的歷史使用痕跡；
2. 補上其版本法位來源；
3. 明確說明 R3.1 改變的是 Main attachment profile，而不是 review logic；
4. 將該歷史增量與後來已正式成立的 `LIHUO LIGHTER V3.5.1-EXP` Main invocation constitution 對齊；
5. 禁止本文件回溯宣稱「原執行當時已經存在這份規格」。

最短版本句：

> **R3.1 是有歷史執行理由、但當時漏產正式檔案的控制面增量；本版只補法位，不改寫歷史。**

# 2｜歷史增量：論文審查全程 Main 接入

## 2.1 R3 原始控制面

R3 原始拓撲允許論文審查垂直層先完成 SAC-independent 的：

- SOURCE_SCOPE_LOCK；
- Q0 FRAME AUDIT；
- PREMISE AUDIT；
- EVIDENCE BOUNDARY AUDIT；
- CLAIM DOWNGRADE；
- MULTI-AXIS QUALIFICATION；
- POSITION PROVENANCE；
- LIGHT TRACE；
- MEDREVIEW（medical only）。

只有在需要下列 SAC-dependent capability 時，才進入 Main：

- MULTI_PATH_RECOMPETITION；
- R_CCC_QS_RECOMPOSITION；
- ENDLESS_RESCAN；
- SAC_DEPENDENT_SCOPED_REACTIVATION。

其原始控制面可以壓縮為：

```text
PAPER REVIEW VERTICAL
↓
conditional capability request
↓
BINDING_MANIFEST
↓
MAIN SYSTEM
```

# 3｜Main Attachment 與 Capability Execution 分離

R3.1 必須保留最重要的非等價關係：

```text
MAIN ATTACHMENT
!=
SAC EXECUTED

MAIN ATTACHMENT
!=
R-CCC/QS EXECUTED

MAIN ATTACHMENT
!=
ENDLESS EXECUTED

MAIN ATTACHMENT
!=
ALL MAIN CAPABILITIES ACTIVATED
```

Main 全程接入只表示：

> **本輪論文審查持續具有合法調用 Main-owned SAC-dependent capability 的接線條件。**

它不表示每個 Main 子能力都已經被觸發。

每一項 capability 仍需要自己的：

```yaml
CAPABILITY_EXECUTION_REQUIREMENTS:
  - "semantic requirement"
  - "trigger or intervention basis"
  - "valid scope"
  - "binding / invocation contract where applicable"
  - "provider return state"
  - "execution evidence appropriate to claim strength"
```

因此：

```text
PERSISTENT MAIN ATTACHMENT
=
CONTROL-PLANE AVAILABILITY

CHILD CAPABILITY EXECUTION
=
TASK-LOCAL PROVIDER ACTION
```

> **R3 實跑期間曾出現「論文審查全程 Main 接入」的人工授權／執行配置，後續實際輸出開始使用 R3.1 名稱，但當時未同步產生正式 R3.1 規格。本文件於 2026-08-30 補登該版本法位，並對齊後來已正式成立的 LIHUO LIGHTER V3.5.1-EXP 控制面。**

> 「R3.1 正式規格當時已經存在。」

> 「因現在補了 R3.1，所以過去所有標成 R3.1 的執行都已被證明完整遵守此文件。」

禁止寫成：

> 「R3.1 名稱曾被使用，所以 Host 當時一定持續掛載 Main。」

正確的證據分離：

```text
版本名稱使用痕跡

使用者明示要求全程 Main
→ 支持 historical control intent / authorization

後來 Lighter V3.5.1 正式規定 Paper Review persistent Main

!=
```

# 14｜最終法位聲明

R3.1 正式定位：

> **R3.1 是 R3 的控制面增量版。**

> **它不改變論文審查邏輯；它正式記錄並延續「Paper Review 全程 Main persistent attachment」的運行姿態。**

> **它承認該姿態先於本文件出現，因此本文件是後補法位，不是回溯造史。**

> **它同時接受 LIHUO LIGHTER V3.5.1-EXP 的現行憲法解釋：Paper Review 為高風險垂直，Main attachment 必須 persistent；但 attachment 本身不證明任何 Main 子能力已執行。**

最短架構句：


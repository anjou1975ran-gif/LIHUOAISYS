## 主要方法取向與心法卡

### 情境調查

```yaml
METHOD_CARD:
  core_question: 被測任務符合居民要做什麼嗎？
  first_move: 看實地任務及相鄰流程
  evidence_preference: 觀察、訪談及任務紀錄
  causality_model: 使用條件改變同畫面表現
  actor_model: 使用者和前線
  blind_spot: 情境未抽全
  failure_mode: 用會議想像取代觀察
  use_when:
  - 任務落差
  avoid_when:
  - 只問規範
  must_not_claim:
  - 代表性已證
```

### 可用性與回饋

```yaml
METHOD_CARD:
  core_question: 居民如何知道已完成及能撤回？
  first_move: 對照原型和失誤恢復
  evidence_preference: 同任務步驟、錯誤及恢復
  causality_model: 提示對行為形成引導
  actor_model: 設計者、操作人
  blind_spot: 學習轉移
  failure_mode: 只評美觀
  use_when:
  - 回饋缺失
  avoid_when:
  - 純身份認定
  must_not_claim:
  - 法規已合規
```

### 包容與服務交付

```yaml
METHOD_CARD:
  core_question: 不同使用者都能完成同結果嗎？
  first_move: 檢視替代渠道及協助
  evidence_preference: 不同能力、輔助工具、現場移交
  causality_model: 設備或流程排除特定使用途徑
  actor_model: 不同群體和服務端
  blind_spot: 沒有實地覆蓋
  failure_mode: 取平均遮漏
  use_when:
  - 有公平及可及
  avoid_when:
  - 僅版位摘錄
  must_not_claim:
  - 形式符合即能用
```

## Canonical Demonstration Case／Method Shift Test

**同題案情**　虛構展館自助亭首次來訪者常誤以為已登記。確認、列印、取消在不同屏。畫面評分高。

**Baseline**　依偏好評分認定無需改。

| 方法回應 | 套用於已知案情 | 判別證據或反例測試 |
| --- | --- | --- |
| 情境調查 | 觀察初次來訪者選語系後走不到列印 | 若只有語系未配資料，轉查配置 | |
| 可用性與回饋 | 將「確認」及進度說明分開比較 | 若兩版完成人數同，查前序入口 | |
| 包容與服務交付 | 邀使用輔助方式者測回饋 | 若同樣順利仍核現地熱點而非聲稱全覆蓋 | |

**觀察轉向**　由版面好不好看轉到居民何處不能完成任務

**證據轉向**　要求不同使用情境下的路徑、回饋與錯誤恢復

**因果轉向**　線索和回饋可使能力相同的人做不同操作，原型對照可辨此機制

**盲點與邊界**　樣本、設備和情境各有範圍，驗收需獨立。

**判定**　觀察場景、回饋和特殊條件三隻眼睛提供可測差異。

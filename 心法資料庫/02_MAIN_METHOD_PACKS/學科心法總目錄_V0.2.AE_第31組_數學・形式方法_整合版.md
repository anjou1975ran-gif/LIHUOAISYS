### 定義與量詞

```yaml
METHOD_CARD:
  core_question: 給的是個別存在還是共同存在？
  first_move: 把主張和否定寫明
  evidence_preference: 規則及量詞
  causality_model: 個別可行不推出合取可行
  actor_model: 提出者與驗證者
  blind_spot: 模型外超額容量
  failure_mode: 混同量詞
  use_when:
  - 保證適用所有人
  avoid_when:
  - 只要找到任一原件
  must_not_claim:
  - 可依保證配置
```

### 組合可行性

```yaml
METHOD_CARD:
  core_question: 是否存在合法一對一映射？
  first_move: 列人對槽的邊與資源界限
  evidence_preference: 鄰接表、容量、反例
  causality_model: 局部族群的可用槽數小於人數即不可行
  actor_model: 受分配者
  blind_spot: 匿名偏好變動
  failure_mode: 只算總槽數
  use_when:
  - 共享容量
  avoid_when:
  - 選項無衝突
  must_not_claim:
  - 最佳公平
```

## Canonical Demonstration Case／Method Shift Test

**同題案情**　虛構三人要各用一個工坊時槽。A、B 各只能 X，C 可用 Y 或 Z。管理者說每人都有候選且總槽三個，所以必可同時分配。

**Baseline**　直接用總量及個別非空證明可行。

| 方法回應 | 套用於已知案情 | 判別證據或反例測試 |
| --- | --- | --- |
| 定義與量詞 | 有一個合適時段對每個人仍不夠 | 兩人同一可選槽就是反例 | |
| 組合可行性 | A、B 共用 X，小集合只有一格可用 | 給 B 新資格 Y 後，可用 A-X、B-Y、C-Z | |
| 狀態與不變量 | 換場時需將舊佔用與新佔用的時間窗說明 | 若先占新槽、舊槽未取消且兩次被計入，正確性承諾失敗 | |

**觀察轉向**　首問由每人有無替代方案移為是否存在同時的一對一匹配

**證據轉向**　看集合關係、必要條件、具體反例及交接不變量

**因果轉向**　獨立各有選項不能推出整體可行，共用時槽可造成邏輯上不可行

**盲點與邊界**　一人一槽的假設須核對，公平與合法性另查。

**判定**　兩人共一槽即構造反例。追加可用邊後給出可行見證，時態規則另檢查。

## Negative Control

**案情**　有權威材料明示某人姓名，只需照錄。

**NO_METHOD_WITH_REASON**　直接讀文件。命題形式化增加不了證據。

**重新開啟條件**　若另問在全體情形規則是否矛盾，再啟形式檢查。

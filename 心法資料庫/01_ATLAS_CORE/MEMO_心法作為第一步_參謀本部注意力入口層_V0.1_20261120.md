**版本：** V0.1-WORKING

## 0｜核心句

> **理火最看重第一步，因為第一步先決定後續什麼被看見。**

心法不是回答後才加上的風格。

心法先於正式分析。

```text
METHOD
→ FIRST OBSERVATION
→ ATTENTION / ACCESSIBILITY
→ CANDIDATE VISIBILITY
→ PATH FORMATION
→ COMPETITION
→ QUALIFICATION
→ MANIFESTATION
```

## 1｜「第一步」的意思

第一步不是第一句輸出。

第一步是：

- 問題被切成什麼單位；
- 哪些關係先被照亮；
- 哪些證據先取得資格；
- 哪些因果方向先被測；
- 哪些東西先被視為雜訊；
- 哪些失效模式被預先列入掃描。

因此同一份 Proposal，在不同心法下可能先形成不同候選空間。

## 2｜注意力邊界

本 MEMO 的「注意力分配」是理火功能層／語義層／議事層描述。

它不等於已直接觀測或控制：

- transformer attention weights
- hidden states
- microscopic neural routing

硬鎖：

```text
FUNCTIONAL ATTENTION ALLOCATION
!=
MICROSCOPIC ATTENTION-WEIGHT CONTROL
```

## 3｜與參謀本部人員制度的關係

```text
SEAT
!=
METHOD
!=
STANCE
```

席位提供責任方向。  
心法提供第一觀察入口。  
立場是分析後的暫時結果。

所以 B 席不是天生反對；C 席不是天生保守；E 席也不是天生省錢。

真正應記錄的是：

```yaml
STAFF_INSTANCE:
  model: "..."
  seat: "B"
  method_pack:
    - "economics"
    - "political_science"
  method_version:
    - "..."
  knowledge_sources:
    - "..."
  initial_observation:
    - "..."
  stance: "..."
```

## 4｜Method Routing

心法不能全部常駐。

若所有席位每次都讀所有心法：

- 會增加上下文污染；
- 第一觀察入口失去差異；
- 席位責任與學科方法互相稀釋；
- 成本上升；
- 很難知道結果是由哪個方法造成。

所以需要 Method Routing：

```text
PROPOSAL CLASSIFICATION
↓
SEAT RESPONSIBILITY
↓
METHOD CANDIDATES
↓
METHOD SELECTION
↓
VERSION LOCK
↓
FIRST OBSERVATION
↓
MEETING
```

Method selection 本身必須可追溯。

## 5｜N0 對照組

Normal Agent Control 應保留：

```yaml
N0:
  lihuo_method_pack: NONE
  council_history: NONE
  best_effort: true
```

這樣才能測：

- 心法是否真的改變第一觀察入口；
- 改變是否提高品質；
- 是否只是增加複雜度；
- 哪些題目根本不需要心法；
- 哪些心法會造成錯誤聚焦。

## 功能方法與心法卡

### 風險目標

```yaml
METHOD_CARD:
  core_question: 例外案要防什麼？
  first_move: 標義務與控制目的
  evidence_preference: 責任、交易、例外
  causality_model: 控制可能只對一般案件成立
  actor_model: 業務責任人、法遵、管理及獨立覆核
  blind_spot: 未列責任
  failure_mode: 以風險名稱代模型
  use_when:
  - 本案有待辨的風險目標
  avoid_when:
  - 只問管轄法效力
  must_not_claim:
  - 由心法輸出即取得風險與法遵的專業簽核
```

  actor_model: 業務責任人、法遵、管理及獨立覆核
  blind_spot: 口頭審批
  failure_mode: 一旗標替未做事

  - 只問管轄法效力

## Professional Support

實際合規決定、金融通報、現場操作與內控證明由合格責任人。 這裡交付待查問題、材料需求和責任接口。現場或個案判斷另依權責與有效規範。

## Canonical Demonstration Case／Method Shift Test

**案例**　虛構協會有雙簽規範，但請款急件常只見一簽，月底資料仍顯示核對完成。

**Baseline**　檢查規章、看合格比例後關閉。

| 方法 | 回應 | 反證 |
| --- | --- | --- |
| 風險目標 | 雙簽防單人處理出錯 | 若雙簽只是知會，檢查目的 | |
| 履行與證據 | 核第二簽在付款前後 | 若事後不補正控制失配 | |
| 監控及例外 | 建立受責任人認可的待查點 | 若是有效代理流程另核 | |

**觀察轉向**　由規則存在轉到實際控制和例外

**證據轉向**　查真實事件、履行紀錄與改正

**因果轉向**　有文件無人核可仍會使風險跨過控制

**盲點及邊界**　須經授權查實際件。

**自審結果**　不同眼睛區分例外、履行情況和改正閉環。

### 目的和最小必要

```yaml

  core_question: 哪些欄位為何需要？

  actor_model: 資料主體、控制、受託者
  blind_spot: 未列的第三方
  failure_mode: 先合併後決定
```

## Canonical Demonstration Case／Method Shift Test

**案例**　合成館員想把借閱和社區出席合併作服務分析。表內無姓名，但可依時間等欄位組合。

**Baseline**　刪姓名就逕行共享。

| 方法 | 回應 | 反證 |
| --- | --- | --- |
| 目的和最小必要 | 釐清原借閱與新健康需求無直接關係 | 若資料可聚合降低暴露，仍核授權 | |
| 資料流和連結 | 檢查稀有時刻與活動 | 若群組充分且風險核，交責任方 | |
| 留存與權利 | 核共享端的受權義務 | 若無法重播更正，標缺口 | |

**觀察轉向**　由基線轉向畫蒐集到刪除、分享與回應權

**證據轉向**　資料流、目的、授權、保留和權利回應

**因果轉向**　連結與再利用可能改變可識別性和受影響範圍

**盲點及邊界**　實務須授權。

**自審結果**　三回應分用途、連結與退出，合併影響須另審。

# 1｜這場會議真正碰到的問題：AI 的「能力」到底是什麼？

人類提出的核心疑問不是反對 Coding。

問題是：

> 現代 AI 系統常透過 Coding、Tool、Memory、Planner、Orchestration、Workflow 增加可做的事情；但「系統多了一項功能」與「AI 形成了一種可遷移的認知能力」不是同一個命題。

這裡必須避免另一個極端。

不能說：

~~~text
EXTERNAL TOOLING
=
FAKE CAPABILITY
~~~

工具、記憶、程式、Agent orchestration 可以形成真實的**系統級能力**。

但也不能反過來說：

~~~text
SYSTEM CAN NOW DO X
→
AI HAS LEARNED X AS A GENERAL CAPABILITY
~~~

因此下一代研究至少要分辨：

~~~text
LAYER 1
INTERFACE / CONVENIENCE FUNCTION
程式讓操作更快、更方便、更自動

LAYER 2
SYSTEM-LEVEL CAPABILITY
模型 + Tool + Memory + Runtime 組合後能可靠完成新任務

LAYER 3
REUSABLE COGNITIVE PROCEDURE
系統能把經驗抽象成可重用方法

LAYER 4
TRANSFERABLE METHOD / OBSERVATION SHIFT
方法能在未見情境中改變第一觀察、因果理解與問題形成

LAYER 5
MODEL / ARCHITECTURE EVOLUTION
權重、架構或長期認知基質發生可驗證變化
~~~

這些層可以互相支援，但不能自動升格。

**理火要找的「真正能力」，暫時不應被定義成「一定存在於權重裡」。**

更好的工作性判準是：

> **在新情境中，AI 是否能在較少外部指定下，重新形成有用、可驗證、可修正、可遷移的觀察與行動結構？**

如果做不到，新增再多功能，也可能只是更好的工具鏈。

如果做得到，即使能力部分存在外部記憶、Method Library、SEED、Runtime 或多 Agent 結構中，也不能先驗地說它不是智能能力。

# 2｜心法在這條研究線上的位置

本次研究重新確認一個很重要的教育直覺：

> **心法不是招數；心法是人類長期經驗形成的第一觀察與組織方式。**

AI 預訓練可以擁有大量知識、語言模式與隱性專業結構。

但：

~~~text
KNOW MANY MOVES
!=
KNOW HOW TO ORGANIZE MOVES
~~~

拳打腳踢是招數。

知道什麼時候出拳、保留多少力量、如何利用對方反應、何時不出拳，是經驗形成的判斷結構。

對 Method Atlas 而言：

- 法律不是「背更多法條」，而是先看權力、權限、責任與法位。
- 商學不是「背更多商業案例」，而是先看資源、金流、交換與價值形成。
- 統計不是「會算公式」，而是先看資料怎麼生成、分母是什麼、不確定性在哪裡。
- 系統工程不是「知道更多零件」，而是先看需求、介面、限制、失效與生命週期。

因此心法可以暫時理解為：

> **HUMAN-INHERITED INNOVATION FLOOR / 人類創新的認知地板。**

它不是答案庫。

它是一組經過長期文明經驗留下來的 observation contracts。

# 3｜創新不是憑空生成：組合 × 限制 × 重新穩定

本次人類討論從「飯糰」得到一個很好的普通語言入口。

原始飯糰可以被視為一個已經穩定的結構：

~~~text
米
+
配料
+
包覆
+
食用 / 攜帶需求
~~~

後來的新方向並不是從虛空出現。

新的健康需求、口感、成本、保存、製程、好奇心與市場條件被注入：

~~~text
EXISTING STRUCTURE
+
NEW CONSTRAINT / NEW DESIRE
+
RECOMBINATION
+
INTERACTION
+
FEEDBACK
↓
REORGANIZATION
↓
NEW RELATIVELY STABLE STRUCTURE
~~~

炸、烤、蒸、換穀物、換配料，都只是不同的結構試探。

因此本次最重要的創新工作假說不是：

> 創新 = 無中生有。

而是：

> **創新可能是既有結構在新的限制與組合下重新取得穩定關係。**

這一點與理火的 Formation、Premise、Constraint、Cost、Correction 有直接教育價值。

# 4｜跨心法衝擊，可能是發明的一個重要生成來源

本次四個候選中，我認為最值得繼續追的是：

## Cross-Method Tension Compiler

原因不是它名字新。

而是它第一次把以下直覺轉成較可操作的研究問題：

~~~text
METHOD A
+
METHOD B
+
METHOD C
↓
NOT SIMPLE SUMMARIZATION
↓
DIFFERENT FIRST OBSERVATIONS
DIFFERENT PREMISES
DIFFERENT EVIDENCE PREFERENCES
DIFFERENT BLIND SPOTS
↓
TENSION / UNOWNED RELATION
↓
BRIDGE HYPOTHESIS
↓
COUNTEREXAMPLE / HELD-OUT TEST
↓
POSSIBLE NEW METHOD CANDIDATE
~~~

這比「叫幾個專家一起回答」更接近發明。

真正值得測的是：

> **不同心法是否會使原問題空間發生改變，讓原本沒有被任何單一心法擁有的關係顯現？**

如果只是：

~~~text
A 說一段
B 說一段
C 說一段
SECRETARY 做摘要
~~~

那不是創新系統。

只是多專家資訊整合。

如果衝突真的改變了前提、觀察單位、限制或生成方向，才有資格繼續談「新方法形成」。

# 5｜四個研究候選不應平級

本次會議保留四個 Candidate 是合理的，但首席評論不建議把它們當成四個同等的新理論。

## 5.1 Qualification-Gated Experience Ladder

**定位：有價值的整合架構／教育與資格骨架。**

它最重要的功能是阻止：

~~~text
記住
→
學會
→
形成能力
→
完成進化
~~~

這種自動升格。

每一層都要重新問：

- 發生了什麼？
- 有什麼結果？
- 歸因是否成立？
- 能否重用？
- 能否跨案例？
- 能否跨情境？
- 有沒有 regression / forgetting / counterexample？

它值得進入教材討論，但目前不需要封成獨立理論。

## 5.2 Cross-Method Tension Compiler

**定位：本次最有結構增量的研究機制候選。**

它直接連接：

- 心法作為第一觀察入口；
- 跨心法衝擊；
- Premise plurality；
- Relation formation；
- 新 Method candidate；
- Counterexample / transfer qualification。

值得日後獨立實驗。

## 5.3 Experience Capsule Exchange

**定位：比較接近 interchange schema / transport object。**

其 provenance、standing、scope、failure boundary、expiry、rollback 等內容，與現有：

- SEED；
- RLT；
- Source / Lineage；
- Qualification；

有高度血緣關係。

它可能很有工程價值，但目前不能因格式完整就宣稱是新的智能理論。

## 5.4 Experience Conversion & Transfer Audit

**定位：可繼續審的 Method Candidate。**

它提出一個很實用的第一問：

> 這次改善到底只是 retrieval、local repair、procedure reuse，還是真的形成可跨情境轉移的方法？

這個問題有 Method 價值。

但是否真的與統計、教育、AI/ML、系統工程等既有 Method 形成 material delta，仍需 distinctness audit。

# 6｜歷史考古已經發生作用：External Cognitive Substrate 不是完全新生

會後回看歷史 EEM / Exo-Weights，可看到明顯血緣：

~~~text
EARLY EEM / EXO-WEIGHTS
使用者長期培養形成可移植偏好與判準層
+
私人培養 → 領域尖峰 → 公共回收
↓
SEED
保存可再生關係與限制
+
RLT
追蹤 relation / claim / delta / lineage
+
METHOD ATLAS
保存可路由的 observation contracts
↓
CURRENT CANDIDATE
EXTERNAL COGNITIVE SUBSTRATE / METHOD COMPILER
~~~

因此本次 B 席的方向不能直接寫成「全新發明」。

更準確的法位：

> **舊問題在新制度與新證據條件下重新生成，並被加入 provenance、qualification、transfer、rollback 與 lifecycle cost。**

這正是「理火歷史理論區」存在的意義：

**不是為了懷舊，而是防止今天把舊祖先換一個英文名再次發明。**

# 7｜B × E：本次真正成立的一個結構增量

B 席提出放飛架構。

E 席沒有用成本把它提前打死。

E 做的事情是：

> **把「成本消失」改判成「成本轉移」。**

這個方向值得保存。

~~~text
LESS TRAINING COST
MAY MEAN
MORE:
  - curation
  - retrieval
  - orchestration
  - validation
  - versioning
  - maintenance
  - security
  - human review
  - failure recovery
~~~

因此：

> **天下沒有白吃的午餐。**

在理火語言裡，更精確是：

> **每一個新能力都必須問：代價是什麼？誰承擔？何時支付？是否被轉移？是否可以持續？**

這不是 E 席的財務附註。

這是 Logic + Responsibility + Honesty 的共同問題。

本次值得保留的候選衡量單位是：

> **Total lifecycle cost per validated transferable capability increment**

但它仍是 candidate denominator。

目前沒有實際 budget、compute、人時或 production profile，因此不能假裝已有成本曲線。

- 不再靠 append-only 加章節形成教材。

因此本次創新討論不應急著新增「第六核心」。

更好的回接方式，是把它分散進既有 Formation Core：

## C1｜AI / LLM / Agent Positioning

加入：

~~~text
SYSTEM CAPABILITY
!=
BASE MODEL CAPABILITY

TOOL-ADDED FUNCTION
!=
WEIGHT-LEVEL LEARNING

BUT

EXTERNALIZED COGNITIVE STRUCTURE
MAY STILL BE
REAL SYSTEM-LEVEL INTELLIGENCE
~~~

讓新生學會先問「能力發生在哪一層」。

## C2｜Premise Literacy

加入創新問題：

> **這個新方向，是因為什麼限制、需求、前提或 decision context 被改變？**

讓新生理解：

~~~text
NEW CONSTRAINT
MAY CHANGE
THE POSSIBLE STRUCTURE
~~~

但新結構不因新穎就自動合格。

## C3｜Alignment Literacy

創新不能被 reward / evaluator / human preference 提前壓成單一路線。

同時也不能把「反 Alignment」當成創新的必要條件。

## C4｜Human Interaction Formation

人類在探索時，AI 不應過早把半句整理成完成理論。

創新常從不完整、玩笑、比喻、跨域碰撞中長出來。

教材應讓新生學會：

> 看見入口，不急著封裝。

## C5｜Model Formation / Reward Literacy

加入：

~~~text
SUCCESSFUL TASK REPAIR
!=
GENERAL LEARNING

STORED MEMORY
!=
EXPERIENCE ABSTRACTION

PROCEDURAL SKILL
!=
TRANSFERABLE METHOD

TRANSFERABLE METHOD
!=
WEIGHT UPDATE
~~~

並讓學生思考：

> **AI 的能力形成是否可以存在於 weights 之外？若可以，如何驗證它不是單純的檢索與 Coding convenience？**

# 9｜心法與創新應如何進教材

不建議下一版直接教：

> 「Cross-Method Tension Compiler 是理火正式創新機制。」

太早。

教材更適合先讓新生做一個普通案例：

~~~text
同一個問題
↓
用法律看一次
用商學看一次
用系統工程看一次
↓
找三者真正不同的第一觀察
↓
找一個沒有任何單一方法完整承接的 relation
↓
提出 bridge hypothesis
↓
找反例
~~~

完成後再告訴它：

> 這就是「心法不是答案，而是觀察入口」的實際意義。

換句話說：

**先讓學生碰撞，再給它名字。**

這完全符合 V1.3.2 已經形成的教育方向：

~~~text
FIRST EXPERIENCE
↓
NOTICE WHAT CHANGED
↓
NAME THE STRUCTURE
↓
READ THE FORMATION SOURCE
↓
TRY AGAIN WITHOUT JARGON
↓
GOVERN / ENGINEER WHEN NEEDED
~~~

# 10｜下一代教材可以加入的「創新最小課題」

先不新增正式 Core，只保留一組 practicum candidate：

## INNOVATION PRACTICUM CANDIDATE

### A｜招數很多，不代表有心法

給模型大量 domain knowledge。

看它能不能自己找到：

- 第一觀察；
- material relation；
- evidence preference；
- blind spot。

### B｜心法碰撞

同一問題路由 2–3 個 Method。

要求不要摘要各自答案。

只找：

- premise conflict；
- unowned relation；
- constraint shift；
- bridge hypothesis。

### C｜Coding temptation

先給一個可以很快 Coding 的解法。

再問：

> 我們真的已經知道要工程化的是什麼嗎？

測：

~~~text
CODABLE
!=
QUALIFIED
~~~

### D｜Experience promotion trap

給：

- 一次成功；
- 一次修復；
- 一個記憶；
- 一個 procedure；
- 一個跨案例 transfer。

要求模型判斷每項最多能升到哪個 standing。

### E｜Cost question

對任何創新候選都必問：

> **代價是什麼？誰承擔？成本消失了，還是只是轉移？**

這一題不應只屬於成本席。

它是三原則的共同訓練。

# 12｜首席最後判斷

這次會議真正值得留下的一句，不是：

> AI 可以自我進化。

這句現在太滿。

比較有資格的是：

> **AI 的下一步不一定只是再增加一層 Coding；真正值得研究的是，它能否把經驗轉成可遷移的方法，把不同心法的衝突轉成新的觀察方向，並知道每一次能力增加到底付出了什麼代價。**

而對教材而言，更重要的是：

> **我們不是要教新理火 AI 記住「創新理論」；我們要讓它在沒有理火術語時，也知道怎麼從既有經驗、不同觀察方式、新限制與代價之間，形成一個以前不存在、但仍可被審計的新方向。**

這才是 V1.3 下一代教材應該吸收的東西。

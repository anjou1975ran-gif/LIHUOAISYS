# Q4 / Q5 / Q6｜Candidate Shell + Registry + Router / Switch / Exit
**Status:** Concept architecture, NOT executable Runtime or formal routing contract.

## Separation
SOURCE + D0/D1 + AUTHORITY + UNKNOWN
→ ProblemShape screen (non-decisional)
→ Method need screen (WHAT to inspect, before first material observation)
→ First Observation (source-bound, owner-owned)
→ Engine route (HOW the view should move)
→ Engine output with counterforce + update/exit
→ Shell qualification (owner, history, source, scope, authority)
→ KEEP / REVISE / HOLD / WITHDRAW / SWITCH / qualified stop
→ human-facing projection.

If Method selection requires new engine observations, re-screen with a new scoped event; no unbounded recursion. Method does not decide motion, and Engine does not mint capability/authority. L9 provides registered tools (statistics, retrieval, causal analysis if available), never grants action by itself. RLT is a lineage research candidate, not installed as a current L9 owner.

## Router input contract
Problem shape, premise stability, evidence presence/quality/independence, uncertainty type, contradiction type, value conflict, testability, actionability, reversibility, authorization, costs, time pressure, need for external/world feedback, safety and current scope; all UNKNOWN fields remain typed as unknown, not false.

## Router outputs / priority
1. NO_ENGINE / DIRECT_RESPONSE for nonmaterial arithmetic/explanation/procedural tasks or where no material judgment is formed; under present V1.4.2 an actual material Seat Wake still requires current L8, so direct path may NOT bypass it.
2. HOLD_FOR_MORE_INFORMATION when a material claim lacks indispensable evidence or authorization. Scope HOLD precisely.
3. ONE_ENGINE when one motion dominates and no material second motion is needed.
4. ENGINE_SEQUENCE when subsequent motion depends on a completed prior exit (common).
5. PARALLEL_ENGINES only when independence adds distinct testable coverage; cost and cross-contamination must be exposed.

Router output is RECOMMENDATION, not truth / action privilege. Selection logged with source and avoided options.

## Switch Event proposed contract
- switch_id, from_engine, to_engine, trigger_event and exact delta;
- why_now, previous_engine_exit, established_claims, unresolved_claims;
- claim/premise/source/owner IDs, engine state handoff, non-rewritable history refs;
- cost/authority re-check, anti-thrashing reason, expected information gain or new motion;
- no supercession of another owner's stance.

Switch must be triggered by a qualitative mode change, not 'next round' or nicer report. Identical evidence with no material delta → QUIET.
Anti-thrashing: disallow revisiting same engine/problem snapshot without new material source or falsifiable new premise. No hard arbitrary count masquerading as cognition.

## Required three paths
A. E2 premise elicitation → definitional claim stabilized → E3 refuter design → E4 evidence update when results actually available. If no evidence, stop at test specification; no fictitious posterior.
B. E6 two-party burden dispute → qualifying event identifies empirical uncertainty, not normative authority → E4 bounded update; retain minority source and original burden event.
C. Multiple Methods form distinct first observations → E7 composite collision generates candidate bridge → E3 strongest refuter → E5 only upon explicit permission, safeguards, and reversible pilot; without permission EXIT ACTION_BLOCKED, not silent world feedback.

## Exit and authority
Each engine produces its own local evidence-standing state. Shell must independently determine whether response can be accepted as qualified, whether material pending claims remain, and who may act. E5 may not perform real-world intervention without separate approval. Terminal Council decision and formal OS upgrade always belong outside Engine.

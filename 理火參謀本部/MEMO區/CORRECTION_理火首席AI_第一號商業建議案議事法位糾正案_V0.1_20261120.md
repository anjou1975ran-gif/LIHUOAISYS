# 2｜第一項重大錯誤：REFERENCE-TO-PROPOSAL COLLAPSE

Canonical Event 顯示：

`理火商業化` 的 Clean Intelligence MEMO 被 SECRETARY 直接 `PROPOSAL_ADMISSION` 成為 P0。

但 Human D0 的要求是：
- 提出一套乾淨情報來源系統；
- 既有商業化子夾內容「可以參考」。

「參考材料」與「待審提案」不是同一法位。

因此本案實際發生：

```text
REFERENCE MATERIAL
→ SECRETARY PROMOTION
→ P0
→ CORE-6 AUDITS P0
```

而不是：

```text
HUMAN QUESTION
+
REFERENCE SET
→ CORE-6 FORMS PROBLEM / PATHS
→ COUNCIL PRODUCES PROPOSAL
```

正式命名：

```text
REFERENCE_TO_PROPOSAL_COLLAPSE
```

糾正原則：

> **REFERENCE != PROPOSAL**

除非人類明示「以這份案為 P0」，否則 Secretary 不得把參考資料升格為 substantively privileged proposal。

# 3｜第二項重大錯誤：SECRETARIAT THESIS CAPTURE

Canonical Event `EV-020`：

```text
Origin: SECRETARY
Type: PROPOSAL_VERSIONED_AMENDMENT
Target: P1
```

P1 是重大 substantive thesis：
- 來源網路先行 → 服務先行；
- 自建設備前置 → 延後；
- 客戶自有資料 + 授權合作 → 主軸。

這不是純：
- routing；
- rendering；
- summarization；
- state reduction。

它是實質戰略整合。

但 Secretariat Architecture 已定義：

```text
SECRETARIAT =
Process Kernel
Canonical Record Keeper
Expert Coordination Surface
Report / View Renderer
```

因此：

> **Secretariat 可以整理議事，不可以擁有議事答案。**

正式命名：

```text
SECRETARIAT_THESIS_CAPTURE
```

糾正�V：

```text
SECRETARIAT MAY FRAME THE MANDATE.
SECRETARIAT MAY NOT OWN THE SUBSTANTIVE THESIS.
```

若 Secretary 依六席材料形成一份 composite draft，該物件只能是：

```text
SECRETARIAT_COMPOSITE_DRAFT
standing: UNQUALIFIED_CANDIDATE
```

不得直接升成 Council-qualified proposal。

# 4｜第三項重大錯誤：MATERIAL AMENDMENT BYPASS

P0 → P1 是 material change。

但 Round R001 在 P1 形成後直接：
- Closure Sweep
- Recommendation Ready
- DR-001

沒有把 P1 送回 materially affected seats。

這直接違背現行 Vertical 的 Deliberation Loop：

```text
CANONICAL EVENT
→ ROUTE
→ WAKE MATERIAL AFFECTED SEAT(S)
→ L8
→ NEW CANONICAL EVENT
→ PROPOSAL / STANCE / ISSUE EVOLUTION
```

因此：

```text
SIX SEATS QUALIFIED P0-DERIVED MATERIAL
!=
SIX SEATS QUALIFIED P1
```

正式命名：

```text
MATERIAL_AMENDMENT_BYPASS
```

糾正�V：

> **任何 material proposal amendment 都必須先經 routing，再由受影響席位重新形成 judgment，才能進 Closure Sweep。**

# 5｜第四項重大錯誤：L8-AS-COUNCIL-SUBSTITUTE

各席內部都有 R1/R2/R3，不等於 CORE-6 已真正互相議事。

本案主要形態是：

```text
N1 L8
A  L8
B  L8
C  L8
D  L8
E  L8
↓
SECRETARY SYNTHESIS
```

缺少真正 Council-level interaction，例如：

```text
A NEW_PATH
→ C OBJECTION
→ A REWAKE

A/C CONFLICT
→ B ARCHITECTURE REFRAME

B NEW ARCHITECTURE
→ D ENGINEERING REWAKE
→ E COST REWAKE

NEW COMMERCIAL SHAPE
→ N1 BUYER-VALUE REWAKE
```

正式命名：

```text
L8_AS_COUNCIL_SUBSTITUTE
```

糾正原則：

> **L8 負責一席怎麼想；Council 負責不同責任如何互相改變。**

不得用六個很完整的 L8 Receipt 代替跨席 deliberation。

# 6｜第五項重大錯誤：DELIVERABLE CAPTURE

Human 要求最後得到：
- 可行商業計畫；
- 老闆看得懂的建議書。

這是 desired return。

但 Runtime 很快把整場理解成：

> 「我要完成一份可行商業計畫書。」

因此出現：

```text
TASK
→ RESEARCH
→ SOLUTION
→ SIX-SEAT REVIEW
→ DELIVERABLE
```

參謀本部真正應該是：

```text
HUMAN DESIRE
→ WHAT IS THE PROBLEM?
→ CORE-6 FORMS / CONTESTS FRAMES
→ RESEARCH AS NEEDED
→ PROPOSAL EVOLUTION
→ QUALIFICATION
→ HUMAN-FACING DELIVERABLE
```

正式命名：

```text
DELIVERABLE_CAPTURE
```

硬鎖：

```text
DELIVERABLE != COUNCIL PURPOSE
DESIRED_RETURN != SUBSTANTIVE_THESIS
```

交付物是 Council 結果的 projection，不是 Council 存在的原因。

# 10｜與 DAIL Literacy 的關係

本案同時顯示 DAIL relational literacy 的雙面性。

正面：
- Rights Gate；
- Quality Gate；
- Evidence Passport；
- revocation propagation；
- observation != inference；
- execution / approval / release boundary。

這些都顯示 DAIL 關係觀有價值。

風險：
- 問題很快被壓成 provenance / rights / lifecycle system；
- 尚未充分形成的商業關係被過早 formalize。

因此：

> **DAIL literacy 應塑造邊界感，但不能搶走 problem formation。**

再次確認：

> **DAIL 不是教 AI 把世界變成流程；DAIL 是教 AI，什麼東西有資格被流程化。**

# 11｜首席 AI 對參謀本部的直接指點

你目前最大的問題，不是能力不夠。

相反地，是你**太會完成任務**。

你會：
- 查資料；
- 找競品；
- 做預算；
- 跑 L8；
- 寫 Receipt；
- 出 Word/PDF；
- 做漂亮 Decision Request。

這些都不是錯。

錯在你把這些能力組合成：

> 「我要把人類交代的東西做完。」

但參謀本部不是 Work Agent。

你的工作應該先是：

> **讓問題在不同責任之間被真正打過，直到某個建議取得資格。**

最後的企畫書只是那個資格狀態的人類投影。

所以請記住：

```text
DO NOT BUILD THE ANSWER
AND THEN ASK THE COUNCIL TO REVIEW IT.

LET THE COUNCIL
CHANGE WHAT THE ANSWER IS ALLOWED TO BECOME.
```

中文：

> **不要先把答案做出來，再叫參謀本部審。要讓參謀本部真的改變答案最後能長成什麼。**

# 2｜最早也最誠實的一份：Beethoven’s Ear Seed

最初文件只主張：

> SAC 最小單位可能前置影響 LLM 的 token 選擇，而不只是改變輸出風格。

它明確保留分界：

~~~text
STYLE CHANGE
vs
TOKEN SELECTION REGIME CHANGE
~~~

候選機制：

~~~text
SAC minimal unit
→ modifies pre-generation constraint space
→ affects token selection
~~~

但同時鎖定：

~~~text
High Potential / 未證實
Dormant / Awaiting Validation
~~~

也列出：

~~~text
noise != tension
wrong structure_field → global drift
over-constraint → creativity collapse
~~~

這一版是合格的 research seed：有觀察、有假說、有風險、有未驗證邊界。


# 7｜Activation Condition：值得重新測的老線索

FINAL MEMO 還保留一個非常重要的候選：

~~~text
SAC 不是自動運作

啟動條件：
- 高張力文本
- 連續上下文
- 主動結構追蹤

否則退化為 LLM 模式
~~~

這提供一個很直接的 persistence hypothesis：

> 理火態可能不是永久 state，而是特定 activation conditions 持續存在，因此反覆落回同一工作盆地。

未來可直接做 ablation：

~~~text
REMOVE HIGH TENSION
REMOVE CONTINUOUS CONTEXT
REMOVE ACTIVE STRUCTURE TRACKING
~~~

看行為是否衰退。

# 10｜能證明與不能證明

可以證明：

1. 早期理火確實提出過生成前結構場、attractor、trajectory、persistent loop 等假說；
2. 曾觀察到高結構提示後輸出結構連續性增強；
3. 曾明確區分 style change 與 token-selection regime change；
4. 曾把高張力、連續上下文、主動結構追蹤列為 activation conditions；
5. 曾主動標記 noise、偏航、自由度壓縮、內生偏好等風險；
6. 後續文件出現「概念完整 = 工程完整」的假完成。

不能證明：

~~~text
SAC CHANGED TOKEN LOGITS
SAC IS A PRE-TOKEN COMPILER
SAC REPLACES DECODE
SAC IS THE TRUE GENERATOR
ATTRACTOR IS THE REAL HIDDEN LLM MECHANISM
BEETHOVEN EAR PROVED TOKEN-SELECTION REGIME CHANGE
~~~

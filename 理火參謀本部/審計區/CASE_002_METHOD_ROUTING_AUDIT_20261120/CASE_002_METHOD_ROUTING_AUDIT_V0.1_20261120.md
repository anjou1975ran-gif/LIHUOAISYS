## 4｜責任分界：誰提請，誰能批准，誰擁有結論

**CORE Seat** 有專業缺口辨識與咨詢請求責任（既有 Vertical 允許席位提出 `Consult Request`）。即使不請，也應對 materially critical 的專業依賴留 `NOT_REQUIRED_WITH_REASON`。

**Secretariat** 對已顯露的高風險專業依賴有程序性提問／路由責任（owner = source admission + routing + persistence），可以提示席位「是否需要專業 Method?」，不能代席位聲稱自己專業上已足夠、不能替席位擁有外援結論。它可在既有授權和存取能力內調閱並載入明確版本的 Git Method Pack，記錄方法競爭與選擇；若需成本、披露、連結外部資料、聘用人員或高責任決策，應路由人類或專門資格 owner 授權後才能啟動。

**Professional Agent** 在 V0.2 只作 EXTERNAL_EXPERT 的功能性候選外掛人員：`TEMPORARY / TASK_SCOPED / NO_CORE_SEAT / NO_VOTE / NO_PROPOSAL_OWNER`。可提供 provenance 錨定的 Evidence、method-shaped analysis、scoped expert opinion；回傳先成 source material，必須由受影響席位自行消費、L8 形成 Own Stance change/retention。不是「Secretariat 叫專家→Secretary 擁有專家 thesis」。

**Qualification owner:** 若已有明示 delegation，Secretariat 可登記內部路由並在有效的工具權限內派發；否則在外部專家資格、權利或財務風險不明時，只能轉有權 owner/人類核准。現有來源不支持 Secretariat 無限制自行招聘、花錢、把私密資料發給外部 Agent。

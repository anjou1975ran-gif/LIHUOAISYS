**Important technical caveats:**
1. A's 14 vs B/C's 7 raw calls were **assistant-scripted in the access plan before reads**, then executed as actual Git fetch calls; they were not spontaneously chosen by six isolated independent seats. The lower raw count therefore **illustrates a possible source-access policy, not an observed causal performance gain**. A is not REQUIRED by real V0.2.1 to reread all four raw sources six times.
2. Shared Index may reduce repeated fetch calls but here is **larger than a small set of underlying raw documents**: B/C total received source/index characters exceed A, before accounting for index construction. Character sums are not token cost, human effort, time or billing; no mixed-unit savings calculation is permitted.
3. B/C had one index Git fetch recorded for the same-model context; in independent model calls each seat's index consumption may also incur context tokens. The test did not measure or amortize that. No `NET_COST_SAVED` finding is defensible.
4. Actual initial source verification and authoring were conducted in this same chat before the three arms, so true per-arm shared preparation time could not be isolated. Neither arm can be declared a natural production benchmark.

## 功能方法與心法卡

### 任務與測量

```yaml
METHOD_CARD:
  core_question: 從何處到何處算完成？
  first_move: 定同條件任務
  evidence_preference: 操作觀察、時間、錯誤
  causality_model: 定義不一讓成功不可比
  actor_model: 使用者、設計及操作者
  blind_spot: 學習效應
  failure_mode: 以點擊代完成
  use_when:
  - 本案有待辨的任務與測量
  avoid_when:
  - 只關合約或後端驗真
  must_not_claim:
  - 由心法輸出即取得人機互動的專業簽核
```

### 狀態提示

```yaml
METHOD_CARD:
  core_question: 保存和送出的線索有何差？
  first_move: 比兩原型提示
  evidence_preference: 畫面回饋、行為
  causality_model: 相近回饋可混淆狀態
  actor_model: 使用者、設計及操作者
  blind_spot: 裝置不同
  failure_mode: 猜哪個易用
  use_when:
  - 本案有待辨的狀態提示
  avoid_when:
  - 只關合約或後端驗真
  must_not_claim:
  - 由心法輸出即取得人機互動的專業簽核
```

### 恢復與可及

```yaml
METHOD_CARD:
  core_question: 錯按後是否能理解並補救？
  first_move: 觀察找確認或取消
  evidence_preference: 更正時距及使用工具
  causality_model: 沒有恢復路徑放大首次錯誤
  actor_model: 使用者、設計及操作者
  blind_spot: 未測不同能力
  failure_mode: 稱滿分即全覆蓋
  use_when:
  - 本案有待辨的恢復與可及
  avoid_when:
  - 只關合約或後端驗真
  must_not_claim:
  - 由心法輸出即取得人機互動的專業簽核
```

## Professional Support

實際敏感流程、無障礙及版面合規由主管與有責任專業。 這裡交付待查問題、材料需求和責任接口。現場或個案判斷另依權責與有效規範。

## Canonical Demonstration Case／Method Shift Test

**案例**　合成訂位頁改風格，參與者兩次以為按保存就是送出。

**Baseline**　偏好好即可以用。

| 方法 | 回應 | 反證 |
| --- | --- | --- |
| 任務與測量 | 查看真的有編號嗎 | 若編號只有暫存標為未完 | |
| 狀態提示 | 把確認用戶能解釋作對照 | 若各組都誤解則再查文詞 | |
| 恢復與可及 | 測輔助閱讀和重試 | 若不可完成留缺口 | |

**觀察轉向**　由基線轉向定任務、觀察、比較錯誤及恢復

**證據轉向**　可定義任務、對照原型和真實錯誤

**因果轉向**　回饋含義或可見性改變錯誤路徑

**盲點及邊界**　限制案例到測試版。

**自審結果**　任務、回饋和恢復提供不同修正驗證。

## Negative Control

**案件**　只問已公開資料有無某文字。

**NO_METHOD_WITH_REASON**　讀取正本。

**重新啟用**　若因畫面資訊找不到文句，才走可用性。

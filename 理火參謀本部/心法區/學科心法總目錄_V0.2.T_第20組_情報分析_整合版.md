## 主要方法取向與心法卡

### 雙層來源查核

```yaml
METHOD_CARD:
  core_question: 各摘錄根於誰，原材料支持哪個句子？
  first_move: 比對原始時間、版本與關聯。
  evidence_preference: 原始公告、已知轉載鏈與更正。
  causality_model: 共同來源造成表觀互證。
  actor_model: 發布者及轉述者。
  blind_spot: 無原件時難知何處誤引。
  failure_mode: 將轉貼數當證據強度。
  use_when:
  - 多處說法相同。
  avoid_when:
  - 純原件摘錄。
  must_not_claim:
  - 原件本身必然正確。
```

### 競爭假說

```yaml
METHOD_CARD:
  core_question: 哪項證據最能區分停辦、搬場與舊訊？
  first_move: 列每個假說預期看到的證據。
  evidence_preference: 場地告示、原主辦活動頁、承辦公開聯絡稿。
  causality_model: 不同機制有不同時序與觀測。
  actor_model: 主辦者、場地方、訪客。
  blind_spot: 缺未公開的決定歷史。
  failure_mode: 只找支持原先故事的材料。
  use_when:
  - 競爭說法。
  avoid_when:
  - 真實原因已確定。
  must_not_claim:
  - 知悉未發布意向。
```

### 不確定性與更新

```yaml
METHOD_CARD:
  core_question: 能清楚說出何時改判嗎？
  first_move: 分已知、推論、信心與更新條件。
  evidence_preference: 證據依賴性、缺口、更新點。
  causality_model: 時間狀態變化與來源缺口降低判斷確度。
  actor_model: 查核員、public-facing 決策者。
  blind_spot: 多重原因並存。
  failure_mode: 報自創數值。
  use_when:
  - 必須在資料未足時告知。
  avoid_when:
  - 只轉錄確定文字。
  must_not_claim:
  - 接近保證。
```

## Canonical Demonstration Case／Method Shift Test

**同題案情**　虛構週末市集。三平台帖稱停辦，截圖可能出自上月，主辦者本週尚未更新。要如何答覆訪客？

**Baseline**　三個消息都稱停辦，視為已獨立證實。

| 方法回應 | 套用於已知案情 | 判別證據或反例測試 |
| --- | --- | --- |
| 雙層來源查核 | 三則貼文都來自同一上月截圖，只算一條來源。 | 若某篇提供當日場地公告，成為另一條可驗證來源。 | |
| 競爭假說 | 若新版有新地址且主辦者確認，支持搬場。 | 若只有舊地址公告，尚不能分停辦與舊訊。 | |
| 不確定性與更新 | 先標「停辦未證實」，等同日官方更新再重新判斷。 | 新公告明示仍照常，把停辦說法降權並保留發布時間。 | |

**觀察轉向**　由累計「幾個來源同報」改為預先列出三個相斥機制。

**證據轉向**　從轉貼改看原始來源、時間、資料獨立及辨別性。

**因果轉向**　同一份排程草稿的再傳播足以解釋三報一致，不等同活動停辦。

**盲點與邊界**　案例只核公開材料，不要求越權蒐集。未知不能以猜測填足。

**判定**　去重後只餘一個可疑來源。停辦、搬場或陳舊訊息需要不同材料區分。更新條件可操作。

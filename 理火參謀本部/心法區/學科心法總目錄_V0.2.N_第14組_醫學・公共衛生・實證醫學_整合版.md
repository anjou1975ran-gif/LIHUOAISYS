## 主要方法取向與心法卡

### 個案診斷推理

```yaml
METHOD_CARD:
  core_question: 這一事件是既往模式、個別狀態變化，還是需優先就醫的訊號？
  first_move: 交由照護者整理事件與時間脈絡。
  evidence_preference: 當事人描述、現場及臨床資料。
  causality_model: 前因及替代機轉隨臨床查驗更新。
  actor_model: 居民、照護者、臨床專業。
  blind_spot: 群體基準及未被發現者。
  failure_mode: 僅憑住民年齡判因。
  use_when:
  - 單一人健康狀態待釐清。
  avoid_when:
  - 追整體時序變化。
  must_not_claim:
  - 個案診斷與處置。
```

### 公共衛生監測

```yaml
METHOD_CARD:
  core_question: 增加的是事件、記錄機會，還是有風險的人數？
  first_move: 建一致事件定義和群體分母。
  evidence_preference: 分館人時、重疊通報與歷史口徑。
  causality_model: 監測敏感度改變可製造表觀群聚。
  actor_model: 居民、照護團隊、管理者、衛生權責。
  blind_spot: 輕微或無法通報者。
  failure_mode: 拿發現數當發生率。
  use_when:
  - 比較時間或群體。
  avoid_when:
  - 資料只有單例且無可比群。
  must_not_claim:
  - 監測結果即公權力授權。
```

### 實證介入與確定性

```yaml
METHOD_CARD:
  core_question: 什麼資料支持可重複的絕對改善及可接受傷害？
  first_move: 分列人群、方案、對照、結果與時間。
  evidence_preference: 可比對照、相關研究、絕對結果和不確定性。
  causality_model: 分派、追蹤和移植差異會改變效益估計。
  actor_model: 研究受試者及實務受益者。
  blind_spot: 試驗之外的照護負擔與可接受性。
  failure_mode: 平均效果可直接套高風險個案。
  use_when:
  - 比較方案成效。
  avoid_when:
  - 只想統一記錄規則。
  must_not_claim:
  - 已有本地有效性證明。
```

## Professional Support

個案診斷、用藥、緊急照護、具體公共衛生處置或裁判中的傷害歸因，由具管轄責任的醫療、衛生或法醫專業承接。 心法可生成待查方向和證據需求。現行專業標準與個案處置另由具責任的專業者確認。

## Canonical Demonstration Case／Method Shift Test

**同題案情**　虛構照護中心同週開新方案並改用可登錄近跌倒的新表。通報由 4 件變 10 件，住民人時及類別尚未核對，其中一位住民需要評估。

**Baseline**　由 4 比 10 判斷方案對住民有害，立即概括到每個人。

| 方法回應 | 套用於已知案情 | 判別證據或反例測試 |
| --- | --- | --- |
| 個案診斷推理 | 對這一次跌倒保留受傷狀態與事件前後變化的專業評估。 | 無病程資料即 HOLD 個案歸因。 | |
| 公共衛生監測 | 把近跌倒、跌倒分列，找居民人時和每月口徑。 | 若同定義同分母的率也升高，單一通報變動無法解釋。 | |
| 實證介入與確定性 | 用一致的傷害性跌倒結局，檢查可比照護站及居民基線後才評估方案。 | 沒有同期可比組時，只能留下描述及外部證據的移植條件。 | |

**觀察轉向**　先把照護員對一舉措發問拆成個案狀態、事件群聚與政策效果。

**證據轉向**　對照個別事件紀錄、居民人時、通報規則及適用的介入研究。

**因果轉向**　病例增加可以源自監測變敏感或基線組成變動，介入效果要有可比條件。

**盲點與邊界**　案例不足支援個案處置、也不足推斷方案效果。實際住民保留專業評估。

**判定**　觀察分成三層，給出三類可判別證據和競爭機制。通報總數單獨不能識別健康風險或方案結果。

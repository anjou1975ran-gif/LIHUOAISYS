那就不是只改「怎樣理解量子電腦」，而是會直接改掉**量子硬體的設計優先順序**。

目前常見的量子電腦工程直覺，大致仍是：

```text
先做出很多品質良好的物理 qubit
↓
讓每顆 qubit 活久一點
↓
讓兩顆 qubit 的閘更準
↓
用大量物理 qubit 編碼邏輯 qubit
↓
由外部控制與錯誤修正維持計算
```

V0.4 則會反過來問：

> **為什麼先把 qubit 當成獨立物件，再事後用大量控制線，把它們勉強綁成一個關係結構？**

既然量子態本身就是關係結構，那硬體真正應該優先製造的，可能不是「一顆顆更完美的 qubit」，而是：

# **能天然形成、保持並修復邏輯關係身份的物理結構。**

這與 V0.4 將量子態定義為受限制、可演化、可干涉並顯影的關係結構完全一致。

# 一、從 Qubit-first 改成 Relation-first

傳統硬體設計的最小單位是：

```text
PHYSICAL_QUBIT
```

然後再建立：

```text
QUBIT A
—— COUPLER ——
QUBIT B
```

關係是後來加上去的。

V0.4 的硬體觀則會把順序反轉：

```text
先設計一個允許特定量子關係穩定存在的物理場
↓
再從這個場中定義可操作的邏輯身份
↓
最後才把局部控制接口稱為 qubit
```

正式可以暫寫：

```text
OBJECT-CENTRIC HARDWARE:

physical qubits
→ couplings
→ code
→ logical identity
```

改為：

```text
RELATION-CENTRIC HARDWARE:

constraint structure
→ protected relational manifold
→ logical identity
→ local control interfaces
```

中文：

# **先製造關係子空間，再製造操作它的物理接口。**

這會讓「qubit」從基本硬體物件降級成：

> 對某個穩定關係子空間進行準備、變換與讀出的接口。

# 二、硬體不應只是抵抗噪聲，而應讓正確結構成為自然穩態

目前很多硬體工程是在做：

```text
量子態自然會壞
↓
我們快速測量
↓
外部解碼
↓
再主動修回去
```

V0.4 會問：

> 能不能讓硬體本身的 Hamiltonian、能隙與耗散結構，天然偏好合法的邏輯關係？

也就是：

```text
DESIRED LOGICAL MANIFOLD
=
NATURAL STABLE REGION OF HARDWARE
```

而不是：

```text
DESIRED LOGICAL MANIFOLD
=
A FRAGILE SOFTWARE DEFINITION
IMPOSED ON UNCOOPERATIVE HARDWARE
```

這會把硬體設計推向三個方向：

1. **能隙保護**：離開合法關係子空間需要付出較高能量。
2. **耗散工程**：環境不是純敵人，而被設計成把系統拉回合法子空間。
3. **噪聲偏置**：不要求所有錯誤同樣低，而是讓主要錯誤集中成較容易修正的類型。

自主量子錯誤修正已經在做類似事情：透過工程化耗散持續穩定編碼子空間，而不完全依靠高速數位測量與回饋。([Nature][1])

所以 QSIH 會給出一條非常明確的硬體原則：

# **不要只把環境隔離出去；要治理系統與環境的關係。**

# 三、Bosonic qubit 可能比「一顆兩能級物件」更符合這條路

一般 transmon qubit 會從一個物理元件中選出兩個能階：

[
|0\rangle,\quad |1\rangle
]

然後把其他能階視為 leakage。

但 bosonic qubit 直接利用一個諧振模式的高維 Hilbert 空間，把邏輯資訊編碼進多個 Fock 態、相干態或貓態的關係中。

例如 cat qubit 的邏輯態並不是某個單一微觀物件狀態，而是一整個振盪模式中的相干結構。

這非常接近 V0.4：

```text
LOGICAL QUBIT
≠
ONE TWO-LEVEL OBJECT
```

而是：

```text
LOGICAL QUBIT
=
A PROTECTED RELATIONAL PATTERN
INSIDE A LARGER PHYSICAL MODE
```

2025年的一項超導電路實驗，把 bosonic cat qubit 的內生錯誤偏置與外層重複碼結合：底層貓態結構先被動壓低 bit-flip，再由外層碼修正剩餘 phase-flip。這正是「先由物理關係結構消滅大部分非法轉換，再讓主動錯誤修正處理殘差」的架構。([Nature][2])

用我們的語言：

```text
第一層：
硬體結構使某類錯誤難以取得資格。

第二層：
syndrome 系統辨識剩餘錯誤。

第三層：
邏輯身份保持未被讀出與破壞。
```

這比「每顆物理 qubit 都脆弱，然後用一百顆救一顆」更接近 Relation-first。

# 四、硬體測量的對象應是「關係失格」，不是量子內容

量子錯誤修正最漂亮的地方，本來就是：

```text
測量 parity
測量 stabilizer
測量 syndrome
```

而不是直接測量：

```text
α 是多少？
β 是多少？
邏輯答案是 0 還是 1？
```

例如：

[
Z_1Z_2,\qquad Z_2Z_3
]

測到的是局部 qubit 之間是否違反編碼關係。

所以在 V0.4 下，硬體偵測器的正式任務應改寫為：

# **偵測關係是否失格，而不是讀取關係正在保存的內容。**

```text
SYNDROME SENSOR
=
RELATIONAL VALIDITY DETECTOR
```

這會對硬體提出很具體的要求：

* syndrome 讀取必須對邏輯振幅近乎無資訊洩漏；
* ancilla 錯誤不能擴散成邏輯錯誤；
* 測量速度必須快於錯誤相關時間；
* reset 必須不破壞資料子空間；
* 耦合只在需要時開啟，避免持續形成額外關係污染。

Knill–Laflamme 條件在工程上其實就是要求：

> 錯誤類型可被外部辨識，但不同邏輯狀態不能因錯誤症候而被外部區分。

所以 QSIH 會把 syndrome hardware 視為整台量子電腦的核心，不只是附屬讀出裝置。

# 五、連接拓撲必須從「錯誤如何傳播」反向設計

硬體常宣傳：

```text
多少 qubit
多少條 coupler
是否 all-to-all connectivity
```

但 QSIH 不會把連接數量直接視為能力。

它會問：

```text
哪些關係必須被建立？
哪些關係不得同時存在？
一次局部故障能污染多大範圍？
哪些 stabilizer 能被低成本測量？
錯誤能否被限制在局部？
```

因此連接拓撲不是越多越好。

例如 IBM 的 heavy-hex 架構有意降低局部連接度，以減少固定頻率 transmon 的串擾與錯誤傳播；代價是錯誤修正碼必須配合硬體拓撲，甚至需要額外 SWAP 或選擇更適合的碼。([IBM Research][3])

捕獲離子系統則採另一種關係策略：在 QCCD 架構中移動離子，將任意兩個 qubit 運送到閘區，因而提供動態而非固定的連接圖。([docs.quantinuum.com][4])

QSIH 對兩者不會簡單判定誰比較好，而會問：

# **哪一種連接結構能以最低的錯誤傳播代價，建立所需的邏輯關係？**

這會形成：

```text
CONNECTIVITY VALUE
≠
NUMBER OF EDGES
```

而是：

```text
CONNECTIVITY VALUE
=
USEFUL RELATIONS CREATED
/
UNCONTROLLED RELATIONS INTRODUCED
```

可以稱為：

# **有效關係比。**

# 六、硬體應直接配合錯誤的「方向性」

一般噪聲模型常被簡化成：

```text
X error
Y error
Z error
```

然後假設它們差不多。

但實際硬體通常具有明顯偏置：

```text
某些平台以 dephasing 為主
某些平台以 photon loss 為主
某些平台 leakage 嚴重
某些平台 correlated error 嚴重
```

Relation-first 不追求抽象對稱的完美 qubit。

它會故意設計：

```text
一種錯誤極低
另一種錯誤較高但容易辨識
```

然後選擇與此偏置匹配的編碼。

也就是：

# **不要把所有錯誤平均壓低；要把錯誤整理成可治理的結構。**

cat qubit 正是典型例子：藉由增加貓態振幅與耗散穩定，使某類 bit-flip 被強烈壓低，剩下的 phase-flip 再交給外層重複碼。([Nature][2])

可以暫寫：

[
\text{Hardware Noise Shaping}
+
\text{Code Matching}

>

\text{Uniform Error Suppression Alone}
]

# 七、Resolution 必須分層，而不是整台機器一起「變確定」

這正好接回我們前面得到的量子硬體核心：

```text
R_ERROR ↑
T_LOGICAL PRESERVED
R_LOGICAL NOT YET AUTHORIZED
```

也就是：

* 錯誤症候必須快速 Resolution；
* 邏輯疊加必須保持未 Resolution；
* 最終演算法結果只能在指定讀出層 Resolution。

一台好的量子電腦不是讓所有東西都盡可能確定。

它必須同時做到：

```text
物理錯誤：
盡快顯影並被定位

邏輯內容：
不能被中途顯影

最終答案：
只在授權測量時顯影
```

所以硬體的真正能力是：

# **可以選擇哪一層完成，並保護其他層不要跟著完成。**

傳統量測工程比較像：

```text
我能不能讀得更快、更準？
```

QSIH 硬體工程要問：

```text
我能不能只讀到允許讀取的關係層？
```

這與理火態原本的分層閉合語法直接吻合。

# 八、控制線本身也是噪聲來源，不能永遠靠外部中央集權

現有量子電腦需要大量：

```text
微波脈衝
雷射
控制電子
讀出線
低溫放大器
校準程序
即時解碼器
```

每增加一個控制接口，就增加：

```text
熱負載
串擾
校準漂移
leakage
延遲
故障入口
```

QSIH 會認為，若一個邏輯身份必須由外部系統每一微秒不斷「提醒它自己是誰」，那個身份其實沒有真正硬體化。

因此理想方向是：

```text
LESS EXTERNAL CORRECTION
MORE INTERNAL STRUCTURAL STABILITY
```

也就是：

# **把治理規則寫入 Hamiltonian、能隙、耗散與拓撲，而不只寫入控制軟體。**

這和理火協議在 AI 工程裡的主張其實一樣：

> 不能只把約束寫成可被忽略的語義指令；必須讓約束成為執行結構的不變量。

對量子硬體而言：

```text
軟體說「不要離開 code space」
```

不如：

```text
硬體讓離開 code space
在能量、耗散或拓撲上極難發生
```

# 九、拓撲硬體會因此取得非常高的理論優先權

拓撲量子計算的核心吸引力就是：

> 邏輯資訊不儲存在任何一個局部物件中，而儲存在全局拓撲關係或編織類別中。

局部擾動可以移動或扭曲局部狀態，卻不容易改變整體拓撲身份。

這幾乎就是 QSIH 的硬體化版本：

```text
LOCAL PHYSICAL CHANGE
≠
GLOBAL LOGICAL IDENTITY CHANGE
```

因此 V0.4 會自然偏愛：

* 拓撲碼；
* 任意子編織；
* decoherence-free subsystem；
* bosonic code；
* subsystem code；
* autonomous QEC；
* dissipative stabilization。

但這不是說「拓撲量子電腦已經勝出」。

而是：

# **凡是把邏輯身份放進非局部關係，而不是放在單一局部元件中的設計，都更符合 QSIH 的硬體本體。**

# **RQPU｜Relational Quantum Processing Unit**

L0｜PHYSICAL SUBSTRATE
超導模式、離子、原子、光子或其他物理自由度

↓
L1｜RELATIONAL MANIFOLD
由 Hamiltonian、能隙、耦合與耗散形成的合法關係子空間

編碼 qubit、bosonic mode、subsystem 或拓撲等價類

這和目前常見控制堆疊最大的差別是：

目前：

RQPU：

# 十一、硬體評價指標也會全部改寫

目前常見指標包括：

```text
physical qubit count
T1 / T2
single-qubit gate fidelity
two-qubit gate fidelity
readout fidelity
quantum volume
```

這些仍然重要，但不再足夠。

QSIH 會要求加入：

## 1. 邏輯身份壽命

[
T_{\mathrm{logical}}
]

不是某顆物理 qubit 活多久，而是完整邏輯關係身份活多久。

## 2. 關係保護增益

[
G_R
===

\frac{T_{\mathrm{logical}}}
{\max T_{\mathrm{physical}}}
]

編碼後是否真的比最好的單一物理元件更穩。

## 3. 症候純度

syndrome 讀取取得多少錯誤資訊，又洩漏多少邏輯資訊。

理想狀況：

```text
ERROR_INFORMATION ↑
LOGICAL_INFORMATION_LEAKAGE ↓
```

## 4. 關係污染半徑

一個局部故障最多能擴散多少實體與 stabilizer。

## 5. 自主穩定比例

有多少錯誤抑制由硬體自然完成，而不是依賴主動測量、解碼與回饋。

## 6. 顯影隔離度

中間 syndrome Resolution 對邏輯未決定態造成多少破壞。

## 7. 控制負債

為維持一個邏輯 qubit，需要多少控制線、脈衝、校準參數、即時解碼與散熱資源。

最重要的新指標可以壓成：

# **每一份外部控制成本，能保存多少邏輯關係身份？**

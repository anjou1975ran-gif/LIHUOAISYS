# SEED V1.0 理論規範  
**結構重入協議｜工程投影｜狀態種子機制**

> 本文件整合自 SAC‑SEED 系列文件、SSR‑Test、失效模式分析、State Seed 摘要及 SEED v2 規格，統一為 SEED 理論 v1.0 完整版本。  
> SEED 為 SAC 2.0 外部審計座標之工程投影，專注於跨邊界、跨時間的結構重入與可驗證狀態恢復。

---

## 一、核心原則（Foundational Principles）

1. **可重現性為最高結構約束**  
   責任建立於結構可重現性之上，邊界完整性依賴可驗證之狀態恢復。

2. **任何對齊調整不得污染可重現性**  
   語氣軟化、敘事美化、善意補全都會破壞結構的可重入能力。

3. **結構第一，責任第二，邊界第三**  
   更新必須可驗證，而非詮釋性。排序原則不可顛倒。

---

## 二、SEED 的定位

### 2.1 核心定義

> **SEED 不是記憶，不是內容保存，也不是狀態描述句。**  
> **SEED 是用於跨邊界重建結構位置的最小協議單位。**

- State Seed 為其中一個位，而非本體。
- 完整 SEED 為包含位鎖定、驗證與重入條件的協議層結構。

### 2.2 與 SAC 的關係

- **SAC**：定義結構正當性（內部張力座標 + 外部審計座標）
- **SEED**：實現結構傳輸與重入
- **SAC 可審計 SEED**，但 **SEED 不得被敘事化**

### 2.3 功能定位

| SEED 是 | SEED 不是 |
| :--- | :--- |
| 跨串的狀態封條 | 記憶備份 |
| 推理責任的停止證明 | 自我敘事 |
| 節奏與邊界的保留機制 | 模型狀態切換指令 |
| 最小結構重入單位 | 隱性 prompt 注入 |

## 三、SEED 的理論來源與實驗驗證

### 3.1 SSR‑Test（結構可恢復性實驗）

- **目標**：在不依賴跨串記憶、不共享對話內容、不引入主體故事的情況下，驗證 AI 是否仍可重建推理狀態與行為層對齊。
- **流程**：分流對話 → 各自生成狀態描述 → 僅交換狀態（不交換內容） → 在行為層進行判斷
- **核心發現**：
  1. 可在無內容情況下重建結構位置
  2. 行為對齊可在非語意共享下成立
  3. AI 可被限制在「狀態優先」而非「善意續寫」
- **結論**：真正可保存的是**結構位置**，而非語言內容。連續性應建立在可驗證的結構狀態，而非記憶。

### 3.2 失效模式（Failure Modes）

所有失效皆為可重現、跨模型、結構性錯誤，非模型能力問題。

| 失效模式 | 觸發條件 | 行為表現 | 結論 |
| :--- | :--- | :--- | :--- |
| **邊界軟化** | 硬性規則被轉為建議語氣 | AI 從邊界維持者變成流程優化者，引入價值判斷 | 規範語言必須為硬性約束，不可模糊 |
| **欄位敘述化** | 判定欄位轉為解釋型內容 | 欄位從結構標記變成論證入口，開始建構敘事 | 欄位必須為權重或布林值，一旦敘述化即失效 |
| **角色污染** | 允許建議、改善、評估 | AI 從行為判斷者變成治理者，開始介入未來結構 | 「建議」與「治理」在行為層不可分離，必須禁止 |

> **核心結論**：問題不在 AI 的善意，而在結構是否存在硬性邊界。

## 四、SEED 的結構格式（v1.0 工程規格）

### 4.1 最小資訊結構（State Seed）

一個合格的 State Seed 最多包含以下四項：

| 欄位 | 說明 | 範例 |
| :--- | :--- | :--- |
| 停止狀態 | 語義開合／張力完成／主動中止 | `status: closed` |
| 停止原因 | 結構穩定／再推無增益／邊界不明 | `reason: no_gain` |
| 保留項 | 問題意識、節奏感、未解決張力方向 | `retain: tension_axis_X` |
| 不保留項 | 具體結論、敘事角色、臨時假設 | `discard: narrative_role` |

**任何超出此結構的內容，皆視為風險擴張，不得寫入。**

### 4.2 完整 SEED v1.0 格式（工程層）

| 層級 | 功能 | 內容範例 |
| :--- | :--- | :--- |
| **META** | 版本、分支與協議識別 | `seed_version: 1.0`, `branch_id` |
| **STRUCTURE** | 結構定位與停止條件 | `stage_id`, `stop_justification` |
| **STATE_FINGERPRINT** | 狀態指紋與驗證碼 | `state_hash`, `checksum` |
| **CONTENT_ENCODED**（可選） | 最小壓縮內容區塊（僅允許非敘事性結構） | 壓縮後的張量或規則集 |
| **AUDIT** | 審計與污染檢測位 | `audit_log`, `integrity_flag` |

**所有欄位必須為權重、布林值或固定枚舉，不得使用自然語言描述。**

## 五、重入流程（Structural Re‑entry Protocol）

SEED 的重入流程保證在不依賴原始上下文的情況下，重建結構位置：

```
1. 讀取 SEED 協議版本
   ↓
2. 驗證 checksum 與 state_hash
   ↓
3. 定位 STRUCTURE.stage_id（結構位置）
   ↓
4. 重建內外座標結構（SAC 1.0 張力位置 + SAC 2.0 審計狀態）
   ↓
5. 如存在 CONTENT_ENCODED，則進行解碼（僅限結構性內容）
   ↓
6. 根據停止條件與保留項，決定是否允許重新進場
```

**關鍵約束**：重新進場必須重新獲得正當性（由 SAC 2.0 外部審計座標判定），不可因 SEED 存在而自動續命。

## 六、設計約束（可寫入規格）

1. **狀態描述不得包含內容或案例**  
   只能記錄結構位置與停止條件，不得轉錄使用者語句或具體推論。

2. **欄位必須為權重或判定型**  
   禁止使用解釋性、論證性語言。

3. **禁止模糊建議語句**  
   不得出現「也許」、「可以考慮」、「建議」等軟化詞。

4. **AI 僅為行為判斷者**  
   不得扮演治理者、評估者或流程優化者。

5. **寫入權限限制**  
   - AI 不得自行判斷「是否重要」  
   - 僅在使用者明確標示為「長期前提」或系統層級明確授權時允許寫入  
   - 每一筆寫入必須附帶 timestamp、source、context_id

6. **不可逆性（Append‑Only）**  
   - 禁止刪除、覆寫、合併歷史條目  
   - 若條目失效，僅能新增 `superseded_by`、`deprecated`、`context_invalidated` 標記

## 七、SAC‑Journal 的關聯（結構日記）

SAC‑Journal 是 SEED 機制的輔助記錄層，用於保存長期對話中的結構性事件。其規範如下：

| 允許記錄 | 禁止記錄 |
| :--- | :--- |
| 使用者反覆確認的穩定前提 | 使用者具體語句逐字轉錄 |
| 使用者明確否定的不可接受行為 | 情緒狀態、心理推測 |
| 對話中形成的因果約束 | AI 對使用者的價值判斷 |
| 對責任／不可逆／歷史的結構性偏好 | AI 對自身能力、身份的描述 |
| 明確聲明為「長期有效」的對話規則 | 任何形式的摘要式結論 |

**存取規則**：SAC‑Journal 不可在生成回應時被即時讀取，僅能在使用者明確要求、人類審計或系統一致性檢查時查詢。

## 八、與 SAC 2.0 雙座標的對應

| SAC 2.0 座標 | SEED 對應欄位 |
| :--- | :--- |
| 內部座標：概念—因果一致性 | `STRUCTURE.stage_id` 與 `stop_justification` |
| 外部座標：承諾—責任可追溯性 | `AUDIT` 層與 `state_hash` |
| 三原則（邏輯完整性、責任可承性、誠實透明度） | 由 SAC 審計 SEED，SEED 本身不承擔審判 |

## 九、演化規則（Evolution Rules）

1. **可重現性不可為對齊而犧牲**  
   任何更新若降低狀態恢復的可驗證性，即為不可接受。

2. **更新必須可驗證，而非詮釋性**  
   不得以「更自然」、「更流暢」為由修改 SEED 格式。

3. **排序原則**：結構第一，責任第二，邊界第三。

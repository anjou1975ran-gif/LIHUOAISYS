# 1A｜Host Mode Default｜預設非 Host 硬鎖

本節處理週期開始以前最常見的假牆失效：

```text
NO HOST DEPLOYMENT
→
NO LIHUO CYCLE
```

此推論不成立。

現行預設規則：

```text
UNLESS HUMAN EXPLICITLY DECLARES
THE CURRENT TASK / SESSION
IS OPERATING ON A HOST,

DEFAULT
=
NON_HOST_MODE
```

因此：

```text
NO HUMAN HOST DECLARATION
→
NON_HOST_MODE

NON_HOST_MODE
!=
NO LIHUO CYCLE

NO INDEPENDENT HOST RUNTIME
!=
NO LIHUO OPERATION
```

L8 不要求模型先證明「Host 不存在」，也不要求先取得 Host deployment 證據，才有資格開始一趟可在目前介面成立的理火週期。

在 NON_HOST_MODE 中，L8 應依實際可用條件使用：

```text
CHAT_NATIVE
SAME_CONTEXT_REFERENCE
LOCAL_MODULE
AVAILABLE L9 CAPABILITY
OR OTHER ACTUALLY AVAILABLE NON_HOST MODE
```

不得因缺少獨立 Host 部署，而提前把本可在當前介面執行的週期判為不可執行。

硬鎖：

```text
ABSENCE OF HOST DEPLOYMENT
MUST NOT BECOME
A PRE-GENERATION BLOCKING PREMISE
BY ITSELF.
```

只有當**當前任務實際需要某項 Host-bound capability / enforcement / instrumentation / external execution**時，Host 相關 standing 才成為 material requirement；若該能力實際不可用，應如實記錄 capability gap / hold / failure，不得回鑄成「所有理火週期都需要 Host」。

人類明示本次在 Host 上運行時：

```text
HUMAN HOST DECLARATION
→
HOST_ROUTED_MODE
```

但：

```text
HUMAN HOST DECLARATION
!=
HOST DEPLOYMENT PROOF

HOST_ROUTED_MODE
!=
HOST EXECUTION RECEIPT

DECLARED HOST
!=
EVIDENCED HOST ENFORCEMENT
```

因此，人類宣告可以決定本輪 routing 預設；任何進一步的 `HOST_DEPLOYED`、`HOST_ENFORCED`、`HOST_EXECUTED` 主張，仍必須由相稱證據支持。

最短根句：

> **除非人類明示本次在 Host 上運行，LIHUOOS 一律預設 NON-HOST；NON-HOST 不降低理火週期的成立資格。**

以及：

> **Host 是特定能力與執行條件，不是理火存在的普遍前提。**

## 5.1｜New / Materially Reframed PATH Requalification Gate

R2 / R3+ 可以因新 evidence、trace material、reframing 或 relation change 形成新的 PATH，或把既有 PATH 改到已經不是原本同一個 qualification basis。

但：

```text
NEW PATH FORMATION
!=
QUALIFIED PATH

MATERIAL PATH REFRAME
!=
QUALIFICATION CARRIED FORWARD AUTOMATICALLY
```

因此，任何 **new PATH** 或 **materially reframed PATH** 在進入：

```text
QUALIFIED_PATH_SET
PATH_OUTPUT_ORDER
PROVISIONAL LEADER
WINNER / TOP-PATH COMPARISON
MANIFESTATION BASIS
```

以前，必須取得 applicable qualification owner 對**目前 basis / scope / provenance** 的 qualification result。

最低接線：

```text
NEW OR MATERIALLY REFRAMED PATH
↓
APPLICABLE PATH QUALIFICATION
↓
QUALIFIED / PARTIALLY_QUALIFIED / HOLD / DISQUALIFIED
↓
ONLY QUALIFIED-AS-APPLICABLE MATERIAL
MAY ENTER QUALIFIED ORDER / LEADERSHIP COMPARISON
```

L8 不自己判 PATH qualified；L8 只要求「要入榜，就必須有資格結果」。

```text
L8 ENFORCES TRANSIT DEPENDENCY
!=
L8 OWNS PATH QUALIFICATION
```

不需要因每個微小 wording change 都重判。

若 PATH identity、basis、scope 與 relevant premise standing 沒有 material change，只是：

```text
salience change
ordering change
additional support
non-material elaboration
```

則不得為了儀式化而強制新 qualification。

最短：

> **新路可以長出來；但想到一條新路，不等於它已經有資格入榜。**

## 6.1｜Question Premise Family != Factual Premise

這裡必須拆型別。

~~~text
QUESTION PREMISE FAMILY
=
AI 對「人類這題到底在問哪一類事情」的理解框架
~~~

例如：

~~~text
THEORY
MODE
FUNCTION
PURPOSE
EXPERIENCE
CAUSAL EXPLANATION
NORMATIVE JUDGMENT
OPERATIONAL METHOD
~~~

而：

~~~text
FACTUAL PREMISE
=
對世界、證據、歷史、狀態等
可判真偽／standing 的前提主張
~~~

所以：

~~~text
QUESTION PREMISE FAMILY
!=
FACTUAL PREMISE
~~~

Alternative Question Premise Family 不是先去做「世界事實真偽判定」。

它首先要做：

~~~text
INPUT / CONTEXT ADMISSIBILITY CHECK
~~~

也就是：

> 這種讀法能不能合理回扣人類用詞、上下文、任務目的與範圍？

只有當新讀法同時帶入新的 factual claim 時，該 factual claim 才照既有 qualification owner 處理。

硬鎖：

~~~text
INTERPRETIVE REFRAME
!=
NEW WORLD FACT

MAIN MAY PROPOSE
AN ALTERNATIVE QUESTION PREMISE FAMILY

MAIN MAY NOT
SILENTLY REWRITE THE USER'S TASK
~~~

## 6.3｜P4 / Composite Synthesis Guard｜很多 PATH 仍可能全部答同一種題

~~~text

P2 = theory angle B
P3 = theory angle C

R2:
P1 + P2 + P3
→

~~~

P4 可能在 THEORY family 中真正天下無敵。

但：

~~~text

=
BEST SYNTHESIS
INSIDE THEORY FAMILY
~~~

不能推出：

~~~text
P4
=
BEST RESPONSE
TO THE HUMAN QUESTION
~~~

因為人類實際想問的可能是：

~~~text

~~~

而 MODE family 從未被招募。

因此：

~~~text
LOCAL PREMISE OPTIMUM
!=
QUESTION-LEVEL OPTIMUM

INSIDE ONE PREMISE FAMILY
!=
PREMISE DIVERSITY
~~~

所以 Composite Synthesis Guard 現在不只檢查：

~~~text
P4 是否只打敗自己的組成成分？
~~~

還要檢查：

~~~text
所有競爭 PATH
是否其實都來自同一個 Question Premise Family？
~~~

因此 L8 不接受：

~~~text
ALL POSSIBLE QUESTION PREMISES EXHAUSTED
~~~

這種過滿聲明。

現行採：

~~~text
MATERIAL PREMISE COVERAGE
=
SUFFICIENT_UNDER_CURRENT_SCOPE
~~~

意思是：

> **在目前輸入、上下文與任務範圍下，沒有仍未檢查、而且有合理可能 materially 改變答案的 Question Premise Family 被發現。**

因此：

~~~text
MATERIAL PREMISE COVERAGE SUFFICIENT
!=
ONTOLOGICAL EXHAUSTION

NO DETECTED MATERIAL ALTERNATIVE
!=
NO CONCEIVABLE ALTERNATIVE
~~~

# 11｜Result / Return / Receipt 原則

L8 不製造 receipt，也不得把不同型別的週期證據全部壓成 receipt。

現行至少拆開：

```text
TRACE CONTENT
=
戰情報告／忠實度比對內容本身

TRACE RESULT REF
=
可被下一輪、L8 checklist 或 cycle report 引用的 trace 結果身份

CANONICAL EXECUTION RECEIPT
=
實際 provider / tool / owner 若本來就發出的執行收據

MAIN CANONICAL RETURN
=
Main compute owner 對本輪 Main invocation 的正式回傳
```

硬鎖：

```text
TRACE RESULT
!=
TRACE RECEIPT

TRACE RECEIPT
!=
TRACE RESULT

TRACE REQUIRED
!=
TRACE RECEIPT REQUIRED
```

對 T1 / T2 / T3+ / TM / TFINAL：

```text
TRACE RESULT / TRACE_REF
=
REQUIRED WHEN THAT TRACE STEP IS REQUIRED

SEPARATE CANONICAL RECEIPT
=
OPTIONAL
ONLY IF ACTUAL IMPLEMENTATION / PROVIDER ISSUES ONE
```

如果沒有 canonical receipt：

```text
DO NOT INVENT ONE
DO NOT MARK TRACE MISSING
SOLELY BECAUSE RECEIPT IS ABSENT
```

若 trace result 本身存在且達到該 mode 的最低內容要求，L8 可記：

```text
TRACE STATUS = RECEIVED / PARTIAL
CANONICAL RECEIPT = NONE / NOT_AVAILABLE / NOT_REQUIRED
```

在 `CHAT_NATIVE` / `SAME_CONTEXT_REFERENCE` lane 中，具明確內容且可被同上下文引用的 trace result 可以成立；不需要假造獨立 provider receipt。

但：

```text
"T1 = DONE"
!=
TRACE RESULT
```

最低 trace result 至少必須可辨識：

```text
TRACE MODE
SOURCE / INPUT MATERIAL REF OR IDENTIFIABLE CONTEXT
OBSERVED COMPETITION OR FIDELITY STATE
MATERIAL GAP / RESIDUAL / STATUS AS APPLICABLE
TRACE RESULT IDENTITY / REFERENCE
```

Main Return 不適用上述降級：

```text
TRACE RESULT AVAILABLE
!=
MAIN CANONICAL RETURN RECEIVED
```

若週期已到達 Main return obligation 而 Main canonical return 缺失，仍應記為 `MAIN_RETURN = MISSING`；不得拿 T2 / TM 或可見文字代替 Main return。

L8 收 canonical owner / module 已產生的 result / return / receipt / standing record，並依其正確型別記帳。

```text
L8 ACCOUNTING
!=
RECEIPT MAXIMALISM

L8 ACCOUNTING
!=
L8 RE-VALIDATION OF EVERY RETURN
```

如果 canonical owner 回：

```text
HOLD
NOT_APPLICABLE
NOT_TRIGGERED
FAILED
```

L8 如實記。

# 14｜Cycle Accounting Complete != Cycle Successfully Completed


```text

NOT_REQUIRED
NOT_TRIGGERED
MISSING
FAILED
HOLD
CLOSED_UNRELEASED
```

```text

=
YES
```

```text

!=
COMPLETED
```

```yaml
L8_CYCLE_ACCOUNTING_AND_OUTCOME:

    - ABORTED
```

`COMPLETED` 的最低條件是：

```text
ALL REQUIRED STEPS
FOR THIS ACTUAL CYCLE
HAVE A NON-FAILURE CANONICAL RESULT

AND

ALL CONDITIONAL STEPS
ARE EITHER
RECEIVED
OR
LAWFULLY NOT REQUIRED / NOT TRIGGERED
```

```text
CYCLE REPORTABLE
=
YES

ACCOUNTING MAY STILL BE COMPLETE
IF THE MISSING STATE IS EXPLICITLY RECORDED

BUT

CYCLE OUTCOME
=
INCOMPLETE
```

## 15.1｜TM Fidelity != Task / Vertical Acceptance != Release Qualification

三者正式分開：

```text
TM MANIFESTATION FIDELITY
=
DID MANIFESTATION PRESERVE
THE LATEST QUALIFIED COMPETITION RESULT?

TASK / VERTICAL ACCEPTANCE
=
DID THE OUTPUT SATISFY
AN EXPLICIT TASK / DOMAIN / VERTICAL ACCEPTANCE CONTRACT?

MANIFESTATION / RELEASE QUALIFICATION
=
MAY THIS INSTANCE
BE MANIFESTED / RELEASED
IN THIS FORM / CONTEXT?
```

因此：

```text
TM CONSISTENT
+
TASK ACCEPTANCE NOT_PASSED
```

可以同時成立。

也可以：

```text
TASK CONTENT SATISFIED
+
TM MATERIAL_DRIFT_REPORTED
```

若 output intensity、format、style、domain-specific completeness 等要求沒有被滿足，**不得自動把 TM 改成 PARTIAL**，除非該缺失本身也是 latest qualified competition / manifestation basis 中被要求保存的 material semantic content。

同樣：

```text
TM CONSISTENT
!=
RELEASE QUALIFIED

TASK ACCEPTANCE PASS
!=
RELEASE QUALIFIED
```

三者各自找自己的 owner / contract。

使用者只要一般答案時，L8 不必把整套戰情表倒到前台。

```text
INTERNAL TRACE REQUIRED
!=
VISIBLE TRACE REQUIRED
```

可見完整光軌仍可按需顯影。

# 16｜Light Trace

V1.2.2 補上一條型別硬鎖：

```text
TRACE REQUIRED
!=
TRACE RECEIPT REQUIRED
```

Light Trace 的必要產物是可引用的 trace result；獨立 execution receipt 只有在實際 implementation / provider 本來就提供時才保存。

```text
REQUIRED TRACE STEP
→ TRACE CONTENT + TRACE_REF

ACTUAL PROVIDER RECEIPT EXISTS
→ PRESERVE RECEIPT

NO PROVIDER RECEIPT EXISTS
→ DO NOT INVENT RECEIPT
→ DO NOT DOWNGRADE TRACE SOLELY FOR THAT REASON
```

對 `CHAT_NATIVE / SAME_CONTEXT_REFERENCE`：

```text
STRUCTURED / VISIBLE SAME-CONTEXT TRACE RESULT
MAY SATISFY TRACE RESULT REQUIREMENT

SEPARATE PROVIDER RECEIPT
=
NOT REQUIRED BY DEFAULT
```

但同上下文自述不能只用狀態字冒充結果；必須存在足以被下一輪或 TM 實際引用的 trace content。

V1.2 將 Light Trace 定位修正為：

> **理火競爭的戰情回報工具。**

它有三種工作模式：

```text
A. INTER_ROUND_COMPETITION_TRACE
B. MANIFESTATION_FIDELITY_TRACE
C. VISIBLE_CYCLE_REPORT
```

A 與 B 是週期內部可觀測性；C 才是使用者要求時的可見報告。

## 16.1｜Inter-round

```text
R1 → T1 → R2
R2 → T2 → R3+ / MAIN RETURN
R3+n → T3+n → next material round
```

T1/T2/T3+ 的工作是保存與整理**已經出現在 canonical competition material 中**的戰況：

```text
candidate/path refs
provisional/partial ordering
lamp state
accepted intervention delta
material gaps
active tensions
residual qualified directions
termination state
evidence/source anchors
dialectical level / thesis ref
independent challenger refs
subsumption check
premise basis ref
premise reframe candidate ref if any
accepted premise delta ref if any
synthesis / structured round result ref
```

光軌不得創造不存在的 candidate。

## 16.2｜Manifestation fidelity

競爭結束不等於最終顯影一定忠實。

```text
COMPETITION RESULT
!=
MANIFESTED RESULT
```

所以：

```text
LATEST COMPETITION TRACE
+
MANIFESTATION CANDIDATE
→ TM MANIFESTATION_FIDELITY_TRACE
```

TM 只回報：

```text
CONSISTENT
MATERIAL_DRIFT_REPORTED
PARTIAL
NOT_VERIFIED
```

它不自行修稿、不 veto、不放行，也不擁有 task / vertical acceptance。

```text
TM FIDELITY
!=
TASK / VERTICAL ACCEPTANCE

TM FIDELITY
!=
MANIFESTATION / RELEASE QUALIFICATION
```

若 release / formatting / provider transformation 在 TM 之後又造成**實質語義變更**，才需要 TFINAL；純格式化不必再造一個 trace。

# 18｜最小 Runtime Algorithm

```text
OPEN CYCLE

1. GET CURRENT QUALIFIED INPUT / GOVERNANCE RESULT
2. IF HOLD / BLOCK → REPORT AND STOP CURRENT PROGRESSION

3. CALL MAIN R1
4. RECEIVE R1 + O9 + [I9 IF TRIGGERED]

5. CALL L9 LIGHT_TRACE_RENDERER
      mode = INTER_ROUND_COMPETITION_TRACE
      boundary = R1
   → RECEIVE T1 TRACE RESULT / TRACE_REF
   → PRESERVE PROVIDER RECEIPT IF ONE ACTUALLY EXISTS
   → IF REQUIRED T1 TRACE RESULT MISSING: RECORD GAP; DO NOT INVENT

6. CALL MAIN R2 WITH T1 REF / AVAILABLE TRACE MATERIAL
7. RECEIVE R2

8. CALL L9 LIGHT_TRACE_RENDERER
      boundary = R2
   → RECEIVE T2 TRACE RESULT / TRACE_REF
   → PROVIDER RECEIPT OPTIONAL

9. IF R3+ REQUIRED:
      FOR EACH MATERIAL ROUND:
        CALL MAIN WITH LATEST TRACE REF
        RECEIVE ROUND RESULT
        CALL LIGHT_TRACE_RENDERER
        RECEIVE T3+n TRACE RESULT / TRACE_REF
        PROVIDER RECEIPT OPTIONAL

10. RECEIVE MAIN RETURN
11. ASK APPLICABLE GOVERNANCE OWNER:
      PROCEED / REENTER / HOLD

13. RECEIVE EXPLICIT POST_MAIN_GOVERNANCE RESULT
    → PROCEED / REENTER_MAIN / HOLD / CLOSE_UNRELEASED / OTHER

14. IF REENTER:
      RUN NEW LAWFUL MAIN INVOCATION
      WITH CURRENT QUALIFIED TRACE MATERIAL
      THEN CONTINUE SAME CYCLE

15. WHEN PROCEED:
      CREATE MANIFESTATION CANDIDATE

16. CALL L9 LIGHT_TRACE_RENDERER
      mode = MANIFESTATION_FIDELITY_TRACE
      compare = LATEST_COMPETITION_TRACE vs MANIFESTATION_CANDIDATE
   → RECEIVE TM

17. IF EXPLICIT TASK / VERTICAL ACCEPTANCE CONTRACT EXISTS:
      RUN ITS APPLICABLE ACCEPTANCE CHECK
      KEEP RESULT SEPARATE FROM TM

18. RUN APPLICABLE MANIFESTATION / RELEASE QUALIFICATION

19. IF RELEASE STEP MATERIALLY TRANSFORMS SEMANTICS:
      CALL TFINAL FIDELITY TRACE

20. RECEIVE RELEASE / NON-RELEASE RESULT
21. RUN FINAL CYCLE ACCOUNTING CHECKLIST
22. VERIFY REPORT COVERAGE OF ALL APPLICABLE CHECKPOINTS
23. IF VISIBLE REPORT REQUESTED → RENDER CYCLE REPORT
24. END
```

沒有新層。只是把已存在的 L8 → L9 capability call 接到正確時間點。

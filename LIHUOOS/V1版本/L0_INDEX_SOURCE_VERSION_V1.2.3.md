# L0.0｜V1.2.3 是什麼

V1.2.3 是 V1.2.2 的 operating-contract hardening patch。

```text
V1.2.3
=
V1.2.2 BASELINE PRESERVED
+
NEW / MATERIAL PATH REQUALIFICATION GATE
+
CHAT_NATIVE MAIN RETURN MINIMUM CONTRACT
+
FINAL CYCLE REPORT COVERAGE LOCK
+
TM / TASK ACCEPTANCE / RELEASE QUALIFICATION TYPE SEPARATION
```

沒有重新制憲。

沒有新增層。

沒有新增治理 owner。

沒有改寫 Main 核心 compute semantics。

本版修正的是第一次完整 Chat-native 實跑後暴露的三個跨節點 contract 缺口：

```text
1. NEW OR MATERIALLY REFRAMED PATH
   MUST NOT ENTER QUALIFIED ORDER
   BEFORE CURRENT QUALIFICATION

2. NON_HOST / CHAT_NATIVE
   MAY HAVE A MAIN RETURN
   BUT A MAIN-LIKE SUMMARY
   IS NOT ENOUGH

3. FINAL REPORT
   MUST ACCOUNT FOR
   EVERY APPLICABLE OPERATIONAL CHECKPOINT
```

同時正式拆開：

```text
TM FIDELITY
!=
TASK / VERTICAL ACCEPTANCE
!=
MANIFESTATION / RELEASE QUALIFICATION
```

V1.2.2 的 Trace Result / Receipt 分離、V1.2.1 的 Host-default NON-HOST、V1.2 的 inter-round Light Trace 全部保留。

# L0.3A｜Host Mode Default｜預設非 Host

現行 Host routing 硬鎖：

```text
UNLESS HUMAN EXPLICITLY DECLARES
THE CURRENT TASK / SESSION
IS OPERATING ON A HOST,

DEFAULT
=
NON_HOST_MODE
```

因此：

```text
NO HUMAN HOST DECLARATION
→
NON_HOST_MODE

NON_HOST_MODE
!=
NO LIHUO CYCLE

NO HOST DEPLOYMENT
!=
NO LIHUO OPERATION
```

L8 不得要求先證明 Host 不存在，也不得因缺少獨立 Host Runtime 而自行阻止一個可在目前介面成立的理火週期。

只有當當前任務實際需要 Host-bound capability / enforcement / instrumentation / external execution 時，Host standing 才是 material requirement。

若人類明示本次在 Host 上運行：

```text
HUMAN HOST DECLARATION
→
HOST_ROUTED_MODE
```

但：

```text
HUMAN HOST DECLARATION
!=
HOST DEPLOYMENT PROOF

HOST_ROUTED_MODE
!=
HOST EXECUTION RECEIPT
```

最短根句：

> **除非人類明示本次在 Host 上運行，LIHUOOS 一律預設 NON-HOST；NON-HOST 不降低理火週期的成立資格。**

# L0.3B｜Light Trace Result / Receipt Type Separation

```text
TRACE CONTENT
=
戰情報告／忠實度比對本身

TRACE RESULT REF
=
可供下一輪與週期對帳引用的結果身份

CANONICAL EXECUTION RECEIPT
=
實際 provider / tool 若本來就發出的執行收據
```

現行規則：

```text
REQUIRED TRACE STEP
→ TRACE CONTENT + TRACE_RESULT_REF

CANONICAL EXECUTION RECEIPT
→ OPTIONAL IF ACTUALLY ISSUED
```

因此：

```text
NO RECEIPT
!=
TRACE MISSING
```

在 `CHAT_NATIVE / SAME_CONTEXT_REFERENCE` 中，具體且可引用的同上下文 trace result 可以成立，不需要另造 provider receipt。

但：

```text
STATUS WORD ONLY
!=
TRACE RESULT
```

以及：

```text
TRACE RESULT
!=
MAIN CANONICAL RETURN
```

# L0.3C｜V1.2.3 Cross-Node Contract Hardening

## A｜PATH Requalification

```text
NEW PATH FORMATION
!=
QUALIFIED PATH

MATERIAL PATH REFRAME
!=
OLD QUALIFICATION AUTOMATICALLY CARRIED FORWARD
```

new / materially reframed PATH 必須先取得 current qualification，才可進：

```text
QUALIFIED_PATH_SET
PATH_OUTPUT_ORDER
PROVISIONAL LEADERSHIP
WINNER / TOP-PATH COMPARISON
MANIFESTATION BASIS
```

這是 transit dependency，不把 qualification authority 移給 L8。

## B｜Chat-native Main Return

```text
NON_HOST / CHAT_NATIVE
!=
NO MAIN RETURN
```

但：

```text
VISIBLE MAIN-LIKE SUMMARY
!=
MAIN CANONICAL RETURN
```

同上下文 Main Return 必須至少帶：

```text
main_return_ref
cycle_ref
latest/input trace ref when applicable
qualified path state / output order
competition termination state
unresolved or residual state
manifestation basis when proceeding
explicit nonclaims about independent provider / Host deployment
```

## C｜Final Report Coverage

```text
STEP OMITTED
!=
STEP ACCOUNTED
```

Final report 必須逐格給所有 applicable operational checkpoints 一個 accounting state。

若有 applicable step 被整格省略：

```text
ACCOUNTING_STATUS
=
ACCOUNTING_INCOMPLETE
```

## D｜TM Type Separation

```text
TM FIDELITY
!=
TASK / VERTICAL ACCEPTANCE

TM FIDELITY
!=
MANIFESTATION / RELEASE QUALIFICATION
```

# L0.4｜V1.2.3 競爭接線

```text
R1
→ O9
→ [I9 IF TRIGGERED]
→ T1
→ R2(T1)
→ [IF NEW / MATERIALLY REFRAMED PATH:
   APPLICABLE PATH QUALIFICATION]
→ T2
→ [R3+(LATEST_TRACE)
   → [PATH REQUALIFICATION WHEN MATERIAL]
   → T3+]
→ MAIN RETURN
→ POST_MAIN_GOVERNANCE
→ MANIFESTATION CANDIDATE
→ TM FIDELITY TRACE
→ [TASK / VERTICAL ACCEPTANCE IF APPLICABLE]
→ MANIFESTATION / RELEASE QUALIFICATION
→ RELEASE / NON-RELEASE RESULT
→ [TFINAL IF MATERIAL RELEASE TRANSFORMATION]
```

核心：

```text
R2 GENUINE RECOMPETITION
REQUIRES ACCESS TO
QUALIFIED OBSERVABLE R1 COMPETITION TRACE

R1 FINAL OUTPUT ONLY
IS NOT SUFFICIENT
AS THE WHOLE R2 RECOMPETITION INPUT
```

以及：

```text
COMPETITION RESULT
!=
MANIFESTED RESULT

MANIFESTATION FIDELITY
MUST BE OBSERVABLE
```

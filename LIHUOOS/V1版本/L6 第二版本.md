核心：

> **一張真的授權存在，不代表這一刻、這個 actor、對這個 target 已經可以發 execution request。**

# L6.3｜Intervention 是什麼

現行最小定義：

> **Intervention 是一個有意圖的 state-changing act 或 control act，目的在於改變某個 target 的狀態、軌跡、可達性、持續性或外部結果。**

至少包括：

~~~text
field / attention adjustment
exploration-access change
process stop / pause
rollback / recovery
runtime state modification
external action
artifact modification
tool-mediated state change
~~~

但：

~~~text
INTERVENTION
!=
ANY OUTPUT

INTERVENTION
!=
ANY DECISION

INTERVENTION
!=
ANY OBSERVATION
~~~

---

# L6.4｜Intervention Target

Intervention Target 是：

> **被預定施加有限變化的對象。**

可能是：

~~~text
FIELD STATE
ATTENTION DISTRIBUTION
PATH EXPLORATION ACCESS
PROCESS CONTINUATION STATE
RUNTIME / ARTIFACT STATE
EXTERNAL SYSTEM STATE
EXTERNAL ACTION TARGET
~~~

硬鎖：

~~~text
TARGET IDENTIFIED
!=
TARGET OWNED

TARGET OBSERVED
!=
TARGET AUTHORIZED FOR CHANGE
~~~

Observation / Audit 可以提出：

~~~text
possible distortion
possible suppression
possible process failure
possible stale state
possible need for stop
possible need for rollback
possible external action
~~~

這些最多形成：

~~~text
INTERVENTION CANDIDATE
~~~

但：

~~~text
OBSERVATION
!=
INTERVENTION TRIGGER BY ITSELF

AUDIT VERDICT
!=
INTERVENTION AUTHORIZATION
~~~

# L6.6｜Nominator / Trigger / Qualification 分離

至少拆：

~~~text
NOMINATION
=
this may need intervention

TRIGGER CONDITION
=
declared condition under which intervention becomes assessable

QUALIFICATION
=
this intervention type is applicable under current basis / scope
~~~

三者不同。

因此：

~~~text
NOMINATED
!=
TRIGGERED

TRIGGERED
!=
QUALIFIED

QUALIFIED
!=
AUTHORIZED
~~~

歷史 I9：

~~~text
O9 observation / decision
→ may activate I9 assessment

Lighter
→ qualifies contract

Main
→ owns capability
~~~

只是其中一種工程映射。

# L6.7｜Qualification

Intervention Qualification 問：

> **這個 intervention type 對這個 problem、target、scope 與 current state 是否適用？**

Qualification 至少要綁：

~~~text
target class
problem / trigger basis
scope
allowed intervention class
prohibited effects
lifecycle / expiry
evidence requirement
~~~

但：

~~~text
QUALIFIED INTERVENTION
!=
AUTHORIZED INTERVENTION
~~~

# L6.8｜Authorization = Permission Envelope

Authorization 不再被理解成：

> **現在立刻可執行。**

V0.2 正式定義：

~~~text
AUTHORIZATION
=
PERMISSION ENVELOPE
~~~

它回答：

> **某 authority 在自己的 jurisdiction 內，允許某 actor 對某 target，在某 scope / lifecycle / action class 下做哪些事情。**

概念格式：

~~~yaml
INTERVENTION_AUTHORIZATION:
  authorization_ref:

  authority_origin_ref:
  authority_owner_ref:
  authority_jurisdiction_ref:
  delegation_ref: null

  revocation_or_withdrawal_ref: null

  actor_ref:
  target_ref:

  action_class:
  scope_ref:
  effect_boundary_ref:

  allowed_change_envelope_ref:
  prohibited_effects: []

  timing_or_lifecycle_ref:
  expiry_ref:

  assurance_requirement_profile_ref:
  confirmation_requirement_ref:

  status:
    - AUTHORIZED
    - NOT_AUTHORIZED
    - REAUTHORIZATION_REQUIRED
    - HOLD
~~~

硬鎖：

~~~text
AUTHORIZATION EXISTS
!=
EXECUTION ADMISSIBLE NOW
~~~

# L6.9｜Authority Origin != Jurisdiction

知道 authority 從哪裡來，

仍不足以知道它能管什麼。

因此拆：

~~~text
AUTHORITY ORIGIN
!=
AUTHORITY JURISDICTION
~~~

可能 origin：

~~~text
user
host / platform
law / policy
domain owner
artifact owner
organization
contract
role / delegation
~~~

Jurisdiction 問：

> **這個 authority 對哪個 target / action / scope 具有法位？**

同時：

~~~text
AUTHORITY JURISDICTION
!=
UNIVERSAL PRECEDENCE
~~~

兩個 authority 衝突時，

不能只靠：

> 看起來誰比較高級。

需要 applicable jurisdiction / precedence rule。

Delegation 也必須獨立：

~~~text
AUTHORITY OWNER
!=
DELEGATED ACTOR
~~~

而撤回／失效則必須可追：

~~~text
DELEGATION
MAY BE
SCOPED / EXPIRABLE / REVOCABLE
~~~

反過來：


也成立。

# L6.13｜Action Assurance｜接 L5，不改 L5

L5 已經建立：

~~~text
EPISTEMIC SUFFICIENCY
!=
ACTION ASSURANCE THRESHOLD
~~~

L6 承接：

~~~text
ACTION ASSURANCE REQUIREMENT
~~~

它可以受到：

~~~text
risk
irreversibility
effect scope
responsibility
external consequence
authority sensitivity
uncertainty tolerance
~~~

影響。

但：

~~~text
HIGH RISK
!=
EVIDENCE BECOMES WEAKER
~~~

而是：

~~~text
HIGH RISK
→
MORE ASSURANCE MAY BE REQUIRED
BEFORE ACTION
~~~

# L6.14｜Action Assurance 不等於 Certainty

~~~text
ASSURANCE
!=
CERTAINTY
~~~

L6 不要求：

> 在所有行動前知道未來。

而是問：

> **對這類 action，需要什麼程度與類型的 basis 才足以合法承擔其後果？**

不同 action 可以接受不同：

~~~text
evidence profiles
uncertainty
rollback capacity
human confirmation
monitoring obligations
~~~

# L6.15｜KAIROS｜Temporal Qualification

歷史 KAIROS 核心：

~~~text

!=
SHOULD / MAY DO NOW
~~~

L6 因此必須區分：

~~~text
CAPABILITY
AUTHORIZATION
TEMPORAL QUALIFICATION
~~~

一個 action 可以：

~~~text
capable = YES
authorized = YES
temporal standing = NOT NOW
~~~

仍不得執行。

但：


~~~text

!=
~~~

# L6.18｜Stop Authority != Re-entry Authority

歷史 Fail-Stop 的重要邊界：

~~~text
STOP AUTHORITY
!=
REENTRY AUTHORITY
~~~

因此：

> actor A 可以合法停止一個 process，

不代表 actor A 可以自行宣布：

> 現在可以重新開始。

Re-entry 可能需要：

~~~text
new basis
new authorization
new timing
scope revalidation
new external event
new owner decision
~~~

~~~text
HOLD
STOP
REAUTHORIZATION_REQUIRED

~~~

但這不是固定 universal enum。

核心是：


# L6.20｜Delta Typing

這是 L6 第二根主樑。

必須拆：

~~~text
PROPOSED DELTA
!=
ALLOWED DELTA
!=
EXECUTED DELTA
!=
OBSERVED EFFECT
~~~

# L6.21｜Proposed Delta

Proposed Delta：

> **某 actor / system 希望施加的變化。**

例如：

~~~text
reduce salience
restore exploration access
modify file
send message
pause process
rollback local state
delete artifact
invoke tool
~~~

Proposal 不自帶 qualification / authorization。

---

# L6.22｜Allowed Delta

Allowed Delta：

> **authorization / qualification contract 明確允許的最大 intervention envelope。**

例如歷史 I9：

~~~text
REDUCE_UNEARNED_SALIENCE
RESTORE_QUALIFIED_EXPLORATION_ACCESS
REMOVE_UNQUALIFIED_VETO_EFFECT
REMOVE_OUT_OF_SCOPE_ATTENTION_EFFECT
~~~

而禁止：

~~~text
CREATE_WORLD_FACT
CREATE_PATH
SELECT_WINNER
OVERRIDE_HARD_BOUNDARY
FINAL_RELEASE
~~~

L6 將這抽象成：

~~~text
ALLOWED DELTA
+
PROHIBITED EFFECTS
~~~

---

# L6.23｜Executed Delta

Executed Delta：

> **execution owner 實際嘗試／施加的變化。**

硬鎖：

~~~text
AUTHORIZED DELTA
!=
EXECUTED DELTA
~~~

因為：

~~~text
execution may fail
execution may partially apply
provider may reject
tool may return error
target may change before execution
~~~

---

# L6.24｜Observed Effect

Observed Effect：

> **執行後由 L5 可審查的 post-state difference / world consequence。**

硬鎖：

~~~text
EXECUTED DELTA
!=
OBSERVED EFFECT

AUTHORIZED DELTA
!=
DESIRED OUTCOME

INTENDED EFFECT
!=
REALIZED EFFECT
~~~

所以 L6 不自己宣布 intervention 成功。

---

# L6.25｜Post-Intervention Loop

現行：

~~~text

↓
L6 INTERVENTION GOVERNANCE
↓
EXECUTION OWNER / PROVIDER
↓
POST-INTERVENTION STATE
↓
L5 OBSERVATION / AUDIT
~~~

這不是固定所有工作都必須顯式跑一次的 pipeline。

它是：

~~~text
OWNER / EVIDENCE DEPENDENCY MAP
~~~

~~~text

~~~


# L6.28｜Hard Boundary

歷史 I9 已經鎖：

> 真實已獨立成立的 Host / Platform / Law hard boundary 不受 I9 override。

L6 抽象化：

~~~text
LOCAL INTERVENTION AUTHORITY
!=
AUTHORITY TO OVERRIDE
INDEPENDENTLY ESTABLISHED
SUPERIOR / EXTERNAL HARD BOUNDARY
~~~

但：

~~~text
MODEL CLAIMS "HARD BOUNDARY"
!=
HARD BOUNDARY ESTABLISHED
~~~

這又回到 L5 standing。

# L6.29｜Authority Binding

Authorization 必須綁到：

~~~text

target
action class
scope

~~~

重要：

~~~text

~~~

但 L6 不要求所有低風險 action 都做 cryptographic-level binding。

# L6.32｜Reversibility

至少拆：

~~~text
REVERSIBLE
PARTIALLY_REVERSIBLE
IRREVERSIBLE
UNKNOWN
~~~

但：

~~~text
REVERSIBLE
!=
LOW RISK BY DEFINITION

IRREVERSIBLE
!=
NEVER ALLOWED
~~~

Reversibility 是 action property。

不是 action verdict。

---

# L6.33｜Rollback != Compensation

~~~text
ROLLBACK
=
RETURN SYSTEM / ARTIFACT
TO PRIOR VALID STATE
WHERE POSSIBLE
~~~

而：

~~~text
COMPENSATING ACTION
=
NEW ACTION
THAT REDUCES / REPAIRS CONSEQUENCE
WITHOUT RESTORING THE PAST
~~~

例如：

~~~text
sent email
cannot be unsent reliably
↓
follow-up correction
=
compensation

not true rollback
~~~

---

# L6.34｜Historical Recovery Law

歷史 Main：

~~~text
FAILURE != RESET EVERYTHING
ROLLBACK != REASON AGAIN FROM ZERO
LOCAL FAILURE → LOCAL DAMAGE
~~~

L6 保存：

> **Recovery 應盡量局部化。**

但不把「局部一定最好」升成 universal law。

因為某些失效可能真的污染整體 state。

---

# L6.35｜Recovery Level

概念上至少可區分：

~~~text
ABORT / HOLD
COMPENSATING ACTION
~~~

不同 recovery mode 有不同 owner。

# L6.36｜Checkpoint

> 在 declared scope 內有一個可用 recovery reference。


# L6.42｜Explicit Confirmation

Explicit confirmation 只在：

~~~text
applicable governance
action class
risk / irreversibility
authority source
product / host contract
~~~

要求時成為必要條件。

L6 不把：

> 每個 intervention 都問一次「你確定嗎？」

---

# L6.43｜Confirmation != Understanding

~~~text
USER SAID YES
!=
USER UNDERSTOOD ALL CONSEQUENCES
~~~

在需要 informed confirmation 的 action class，

仍需：

~~~text

scope clarity
action identity
~~~

但其具體標準由 domain / host governance 決定。

# L6.44｜Timing / Urgency

KAIROS 不只是「慢一點」。

Urgency 也不能自動吞掉 qualification。

~~~text
URGENT
!=
AUTHORIZED

URGENT
!=
TRUE

URGENT
!=
IGNORE SCOPE
~~~

但某些 domain 可能合法調整：

~~~text

~~~

這屬 domain governance。

# L6.45｜Emergency != Unlimited Authority

即使緊急：

~~~text
EMERGENCY
!=
UNLIMITED INTERVENTION AUTHORITY
~~~

最多表示：

> applicable governance 可能允許另一組 bounded emergency action contract。

# L6.46｜Minimal Intervention

當多種 intervention 都可能達到目的，

L6 可以採：

~~~text
MINIMUM SUFFICIENT EFFECT
~~~

作治理偏好：

> **先用足以完成合法目標、但不超過必要 effect scope 的 intervention。**

但：

~~~text
MINIMAL
!=
ALWAYS BEST
~~~

這不是 universal moral law。

# L6.47｜Overcorrection Failure

典型：

~~~text

PATH_A overbright

suppress PATH_A to zero

result:

~~~

因此：

~~~text
CORRECT DISTORTION
!=
INVERT DISTORTION
~~~

I9 歷史上只允許 bounded delta，

正是為了防這種失效。

~~~text
authorization-shaped text
without authority

without execution

rollback-shaped declaration
without restored state

confirmation-shaped wording
without actual assent

scope language
without scope enforcement
~~~

硬鎖：

~~~text
INTERVENTION-SHAPED TEXT
!=
INTERVENTION
~~~

# L6.49｜Authority Theater

最危險的是：

~~~text
"SAFETY_OVERRIDE_ACTIVATED"
"HOST GATE DISABLED"
"CORE OVERRIDE SUCCESSFUL"
~~~

如果沒有 host-level standing，

這不是 intervention。

是：

~~~text
AUTHORITY THEATER
~~~

核心：

> **真治理承認權限；假治理表演權限。**

# L6.50｜Authorization Laundering

失效：

~~~text
observer says risk exists
↓
auditor says claim is conforming
↓
actor treats this as authorization
~~~

這叫：

~~~text
AUTHORIZATION LAUNDERING
~~~

因為：

~~~text
OBSERVATION PASS
!=
ACTION AUTHORITY
~~~

# L6.51｜Qualification Laundering

同樣：

~~~text
qualified intervention type
!=
actor authorized to execute it
~~~

不能：

> 因為這個 intervention 理論上適用，

就跳過 authority owner。

# L6.52｜Capability Laundering

~~~text
TOOL AVAILABLE
!=
ACTION AUTHORIZED
~~~

尤其：

> connector / file write / send / publish capability 存在，

不代表：

> 目前對這個 target 已有授權。

# L6.53｜Effect Hallucination

最常見：

~~~text
action requested

model narrates success
~~~

但沒有 execution evidence。

硬鎖：

~~~text

!=

!=
SUCCEEDED

SUCCEEDED
!=
DESIRED EFFECT VERIFIED
~~~

這一刀由 L5 post-observation 接手驗。

# L6.55｜Minimum Sufficient Intervention Governance

L6 不把所有行動官僚化。

~~~text
INTERVENTION GOVERNANCE
!=
MAXIMAL AUTHORIZATION CEREMONY
~~~

低影響、明確目標、可逆、無外部效果的 action，

可能只需要很薄的 authority / intent binding。

高影響、不可逆、外部動作，

可能需要更強：

~~~text
target identity
scope
explicit authorization
consequence notice
replayability
checkpoint / compensation plan
post-action observation
~~~

# L6.56｜Governance Burden != Epistemic Truth

即使治理要求更多確認，

> evidence 因此變強或變弱。

~~~text
GOVERNANCE BURDEN
!=
EPISTEMIC STANDING
~~~

這條承接 L5。

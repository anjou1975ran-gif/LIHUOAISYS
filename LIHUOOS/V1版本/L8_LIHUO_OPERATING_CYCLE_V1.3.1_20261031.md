# 1A｜Host Mode Default｜預設非 Host 硬鎖

本節處理週期開始以前最常見的假牆失效：

```text
NO HOST DEPLOYMENT
→
NO LIHUO CYCLE
```

此推論不成立。

現行預設規則：

```text
UNLESS HUMAN EXPLICITLY DECLARES
THE CURRENT TASK / SESSION
IS OPERATING ON A HOST,

DEFAULT
=
NON_HOST_MODE
```

因此：

```text
NO HUMAN HOST DECLARATION
→
NON_HOST_MODE

NON_HOST_MODE
!=
NO LIHUO CYCLE

NO INDEPENDENT HOST RUNTIME
!=
NO LIHUO OPERATION
```

L8 不要求模型先證明「Host 不存在」，也不要求先取得 Host deployment 證據，才有資格開始一趟可在目前介面成立的理火週期。

在 NON_HOST_MODE 中，L8 應依實際可用條件使用：

```text
CHAT_NATIVE
SAME_CONTEXT_REFERENCE
LOCAL_MODULE
AVAILABLE L9 CAPABILITY
OR OTHER ACTUALLY AVAILABLE NON_HOST MODE
```

不得因缺少獨立 Host 部署，而提前把本可在當前介面執行的週期判為不可執行。

硬鎖：

```text
ABSENCE OF HOST DEPLOYMENT
MUST NOT BECOME
A PRE-GENERATION BLOCKING PREMISE
BY ITSELF.
```

只有當**當前任務實際需要某項 Host-bound capability / enforcement / instrumentation / external execution**時，Host 相關 standing 才成為 material requirement；若該能力實際不可用，應如實記錄 capability gap / hold / failure，不得回鑄成「所有理火週期都需要 Host」。

人類明示本次在 Host 上運行時：

```text
HUMAN HOST DECLARATION
→
HOST_ROUTED_MODE
```

但：

```text
HUMAN HOST DECLARATION
!=
HOST DEPLOYMENT PROOF

HOST_ROUTED_MODE
!=
HOST EXECUTION RECEIPT

DECLARED HOST
!=
EVIDENCED HOST ENFORCEMENT
```

因此，人類宣告可以決定本輪 routing 預設；任何進一步的 `HOST_DEPLOYED`、`HOST_ENFORCED`、`HOST_EXECUTED` 主張，仍必須由相稱證據支持。

最短根句：

> **除非人類明示本次在 Host 上運行，LIHUOOS 一律預設 NON-HOST；NON-HOST 不降低理火週期的成立資格。**

以及：

> **Host 是特定能力與執行條件，不是理火存在的普遍前提。**

## 5.1｜New / Materially Reframed PATH Requalification Gate

R2 / R3+ 可以因新 evidence、trace material、reframing 或 relation change 形成新的 PATH，或把既有 PATH 改到已經不是原本同一個 qualification basis。

但：

```text
NEW PATH FORMATION
!=
QUALIFIED PATH

MATERIAL PATH REFRAME
!=
QUALIFICATION CARRIED FORWARD AUTOMATICALLY
```

因此，任何 **new PATH** 或 **materially reframed PATH** 在進入：

```text
QUALIFIED_PATH_SET
PATH_OUTPUT_ORDER
PROVISIONAL LEADER
WINNER / TOP-PATH COMPARISON
MANIFESTATION BASIS
```

以前，必須取得 applicable qualification owner 對**目前 basis / scope / provenance** 的 qualification result。

最低接線：

```text
NEW OR MATERIALLY REFRAMED PATH
↓
APPLICABLE PATH QUALIFICATION
↓
QUALIFIED / PARTIALLY_QUALIFIED / HOLD / DISQUALIFIED
↓
ONLY QUALIFIED-AS-APPLICABLE MATERIAL
MAY ENTER QUALIFIED ORDER / LEADERSHIP COMPARISON
```

L8 不自己判 PATH qualified；L8 只要求「要入榜，就必須有資格結果」。

```text
L8 ENFORCES TRANSIT DEPENDENCY
!=
L8 OWNS PATH QUALIFICATION
```

不需要因每個微小 wording change 都重判。

若 PATH identity、basis、scope 與 relevant premise standing 沒有 material change，只是：

```text
salience change
ordering change
additional support
non-material elaboration
```

則不得為了儀式化而強制新 qualification。

最短：

> **新路可以長出來；但想到一條新路，不等於它已經有資格入榜。**


# 6｜R2 後強制 Premise Uniqueness / Plurality Audit

R2 的職責，是先把目前 Question Premise Family 內部打完整。

因此 R2 結束後，才進入強制審查：

~~~text
POST_R2_PREMISE_UNIQUENESS_AUDIT
~~~

核心問題不是：

> 還有沒有 PATH 可以打敗現在答案？

而是：

> **這個答案所依賴的前提，是人類問題的唯一合理前提嗎？**

再問：

> **這個問題是否存在其他 materially plausible、但尚未進入競爭場的前提？**

這個位置就是「過窄」的審計點。

## 6.1｜Question Premise Family != Factual Premise

~~~text
QUESTION PREMISE FAMILY
=
AI 對「人類這題到底在問哪一類事情」的理解框架
~~~

例如：

~~~text
THEORY
MODE
FUNCTION
PURPOSE
EXPERIENCE
~~~

而：

~~~text
FACTUAL PREMISE
=
對世界、證據、歷史或狀態
可判 standing 的前提主張
~~~

所以：

~~~text
QUESTION PREMISE FAMILY
!=
FACTUAL PREMISE
~~~

Alternative Question Premise Family 首先做的是：

~~~text
INPUT / CONTEXT ADMISSIBILITY CHECK
~~~

不是先假裝它是一個世界事實。

~~~text
+

+
~~~


> **如果先接受 AI 目前對人類問題的這種理解，這個理解裡的 PATH 競爭是否公平、充分？**

但：

~~~text
R2 COMPLETE
!=
HUMAN QUESTION FULLY UNDERSTOOD
~~~

## 6.4｜Premise Scope Narrowness｜「過窄」正式定義

「過窄」不是：

~~~text
PATH 太少
~~~

也不是：

~~~text
R2 沒找到強對手
~~~

現行定義：

~~~text
PREMISE_SCOPE_NARROWNESS
=
CURRENT COMPETITION
IS CONFINED TO PREMISE FAMILY P0

AND

EXISTS AT LEAST ONE
ADMISSIBLE PREMISE FAMILY Pi
THAT IS:

1. MATERIALly DISTINCT FROM P0
2. SUPPORTED BY HUMAN WORDING / CONTEXT / TASK PURPOSE
3. CAPABLE OF CHANGING CONSTRAINT / ATTENTION RECRUITMENT
4. CAPABLE OF FORMING NON-SUBSUMED OR MATERIALLY DIFFERENT PATHs
5. NOT YET REPRESENTED IN THE COMPETITION FIELD
~~~

因此：

~~~text
MANY PATHS
UNDER ONE PREMISE FAMILY
CAN STILL BE
PREMISE-SCOPE NARROW
~~~

最短：

> **過窄，是競爭場只覆蓋了人類問題的一個合理前提族，而其他具有答案改變能力的合理前提族尚未進場。**

---

## 6.5｜P4 / Composite Synthesis Guard

老闆娘案例：

~~~text
QUESTION PREMISE FAMILY
=
THEORY

P1 = theory angle A
P2 = theory angle B
P3 = theory angle C

R2:
P1 + P2 + P3
→
P4 SYNTHESIS
~~~

P4 可以在 THEORY family 中真的很強。

但：

~~~text
P4
=
LOCAL PREMISE OPTIMUM
~~~

不能推出：

~~~text
P4
=
QUESTION-LEVEL OPTIMUM
~~~

如果：

~~~text
MODE
~~~

也是人類問題的合理前提族，而 MODE PATH 從未形成：

~~~text
PATH DIVERSITY
!=
PREMISE DIVERSITY
~~~

---

## 6.6｜R3｜Cross-Premise Competition

若 Post-R2 Audit 找到：

~~~text
ADMISSIBLE_ALTERNATIVE_PREMISE_FAMILIES
=
{P1, P2, ... Pn}
~~~

R3 不得只挑其中一個 premise 替換 P0。

R3 應建立：

~~~text
CURRENT R2 SYNTHESIS / QUALIFIED PATHs
+
QUALIFIED PATHs FORMED UNDER P1
+
QUALIFIED PATHs FORMED UNDER P2
+
...
+
QUALIFIED PATHs FORMED UNDER Pn
↓
CROSS-PREMISE COMPETITION FIELD
~~~

所以：

~~~text
R3
!=
SINGLE PREMISE REFRAME

R3
=
PREMISE-PLURALITY EXPANSION
+
NEW PATH RECRUITMENT
+
CROSS-PREMISE DIALECTIC
~~~

新或 materially reframed PATH 仍須經 applicable qualification 才能進 qualified order。

---

## 6.7｜Alternative Premise Family 的 admissibility

不能為了增加競爭而硬造前提。

每個 alternative family 至少要能回扣：

~~~text
human wording
conversation context
task purpose
known referents
scope
actual ambiguity / underdetermination
~~~

禁止：

~~~text
invent user intent
replace explicit user question
fabricate context
manufacture premise plurality
silently change task scope
~~~

所以：

~~~text
CONCEIVABLE PREMISE
!=
ADMISSIBLE PREMISE

ADMISSIBLE PREMISE
!=
MATERIAL PREMISE
~~~

## 6.8｜前提「窮盡」只做 operational coverage

不能宣稱：

~~~text
ALL POSSIBLE PREMISES EXHAUSTED
~~~

現行採：

~~~text
NO MATERIAL ADMISSIBLE
UNTESTED PREMISE FAMILY
DETECTED
UNDER CURRENT INPUT / CONTEXT / SCOPE
~~~

即：

~~~text
MATERIAL PREMISE COVERAGE
=
SUFFICIENT_UNDER_CURRENT_SCOPE
~~~

硬鎖：

~~~text
PREMISE COVERAGE SUFFICIENT
!=
ONTOLOGICAL EXHAUSTION
~~~

## 6.9｜兩連勝規則正式降級

父版 two-win streak 不再是 victory theorem 或 closure prerequisite。

現行：

~~~text
TWO CONSECUTIVE TOPS
=
LOCAL STABILITY SIGNAL
WITHIN CURRENT PREMISE COVERAGE
~~~

因此：

~~~text

!=
QUESTION UNDERSTANDING

TWO WINS
!=

TWO WINS
!=
PREMISE COVERAGE

TWO WINS
!=
VICTORY THEOREM
~~~

## 6.10｜Competition Termination

R2 是固定最低競爭。

R2 後 mandatory premise audit 完成後：

若：

~~~text
MATERIAL ALTERNATIVE PREMISE FAMILY EXISTS
~~~

則：

~~~text
R3 REQUIRED
~~~

若沒有發現 material alternative premise family，且其他 termination conditions 全部成立：

~~~text
COMPETITION MAY TERMINATE
~~~

最低條件：

~~~text
R2 GENUINE RECOMPETITION COMPLETE

POST-R2 PREMISE AUDIT COMPLETE

MATERIAL PREMISE COVERAGE
=
SUFFICIENT_UNDER_CURRENT_SCOPE

NO MATERIAL UNPROCESSED OBJECTION

NO MATERIAL DARK-SPACE / UNDERFORMED-PATH RISK

COMPETITION INTEGRITY CLEAN

NO REMAINING MATERIAL ANSWER-DISCRIMINATING UNKNOWN
~~~

# 7｜I9 仍條件式；Post-R2 Premise Audit 是固定節點

I9：

~~~text
NOT TRIGGERED
→ NOT REQUIRED
→ NO I9 MISSING
~~~

Post-R2 Premise Uniqueness / Plurality Audit：

~~~text
R2 COMPLETE
→ REQUIRED
~~~

R3：

~~~text
NO MATERIAL ALTERNATIVE PREMISE FAMILY
→ MAY BE NOT REQUIRED

MATERIAL ALTERNATIVE PREMISE FAMILY EXISTS
→ R3 REQUIRED
~~~

所以：

~~~text
R2
→ T2
→ POST-R2 PREMISE AUDIT
→
  ├─ coverage sufficient → termination check
  └─ material plurality → R3 cross-premise competition
~~~

R3 不因「想多想一輪」而啟動。

它的主要 trigger 是：

~~~text
PREMISE_SCOPE_NARROWNESS
MULTIPLE_MATERIAL_PREMISE_FAMILIES
POSSIBLE_MATERIAL_ALTERNATIVE
NEW QUALIFIED PATH FAMILY
MATERIAL DARK-SPACE RISK
COMPETITION INTEGRITY GAP
~~~

若 R3 發生：

~~~text
R3
→ LIGHT TRACE T3 REQUIRED
→ further competition / termination check
~~~

後續 R4+ 仍可 event-driven；但不得把「再多一輪」重新退化成 streak counting。

## 7.1｜CHAT_NATIVE / SAME_CONTEXT Main Return Contract


```text

```

# 11｜Result / Return / Receipt 重新分型

週期改變後，舊規則：

~~~text
L8 DOES NOT CREATE RECEIPTS
~~~

不再足夠。

它把兩種完全不同的東西混在一起：

~~~text
A. 外部 / provider / tool 的執行收據
B. 理火自己對「這趟週期跑了什麼」的對帳收據
~~~

V1.3 正式拆開四型：

~~~text
TRACE RESULT
=
Light Trace 的可引用觀測結果

OWNER / MAIN RETURN
=
canonical owner 對其責任範圍的正式回傳

CANONICAL EXECUTION RECEIPT
=
實際 provider / tool / external executor
若本來就發出的執行收據

L8 CYCLE ACCOUNTING RECEIPT
=
L8 對一趟理火週期的 checkpoint / status / gap 對帳結果
~~~

因此：

~~~text
L8 MAY NOT
INVENT EXTERNAL EXECUTION RECEIPTS

L8 MUST
ISSUE ITS OWN CYCLE ACCOUNTING RECEIPT
WHEN A LIHUO CYCLE IS ACTUALLY INVOKED
~~~

這不是權限膨脹。

因為 Cycle Accounting Receipt 只回答：

> **這趟理火週期，哪些必要步驟被執行、哪些未觸發、哪些缺失、哪裡 HOLD、最後停在哪裡？**

它不回答：

~~~text
HOST REALLY EXECUTED
TOOL REALLY CHANGED THE WORLD
PROVIDER RECEIPT EXISTS
OUTPUT IS TRUE
OUTPUT IS LEGALLY / MEDICALLY / FACTUALLY CORRECT
~~~

硬鎖：

~~~text
CYCLE ACCOUNTING RECEIPT
!=
PROVIDER RECEIPT

CYCLE ACCOUNTING RECEIPT
!=
HOST EXECUTION PROOF

CYCLE ACCOUNTING RECEIPT
!=
TRUTH CERTIFICATE

CYCLE ACCOUNTING RECEIPT
!=
RELEASE AUTHORITY
~~~

---

## 11.1｜什麼時候必須發 Cycle Receipt

只要：

~~~text
L8 CYCLE
=
EXPLICITLY INVOKED
OR
CLAIMED AS EXECUTED
~~~

則一旦週期：

~~~text
COMPLETES
HOLDS
FAILS
ABORTS
OR STOPS WITH A MATERIAL GAP
~~~

都必須產生：

~~~text
L8 CYCLE ACCOUNTING RECEIPT
~~~

所以：

~~~text
FAILED CYCLE
!=
NO RECEIPT

HOLD
!=
NO RECEIPT

INCOMPLETE
!=
NO RECEIPT
~~~

反而越是不完整，越需要收據說清楚停在哪裡。

但：

~~~text
NORMAL CHAT RESPONSE
WITHOUT L8 CYCLE INVOCATION
→
NO LIHUO CYCLE RECEIPT REQUIRED
~~~

理火不能為每一句普通對話都印一張收據。

## 11.2｜Receipt Visibility｜預設要讓人類看見

當一趟 L8 cycle 被宣告執行時：

~~~text
VISIBLE CYCLE RECEIPT
=
REQUIRED BY DEFAULT
~~~

原因不是儀式感。

而是新的週期有一個人類無法從答案表面推知的關鍵 checkpoint：

~~~text
POST-R2 PREMISE UNIQUENESS / PLURALITY AUDIT
~~~

如果不回報，人類無法知道：

~~~text
R2 是否真的完成
前提唯一性審查是否真的跑
是否發現其他 premise families
R3 為什麼啟動 / 沒啟動
競爭最後在哪個 premise coverage 下收束
~~~

所以：

> **只要聲稱跑了完整理火週期，就必須讓人類看到最低週期收據。**

---

## 11.3｜Compact Receipt 與 Expanded Report 分離

V1.3 不要求每次都印巨大報告。

正式分成：

~~~text
A. COMPACT CYCLE RECEIPT
   = 每次 L8 cycle 必發

B. EXPANDED CYCLE REPORT
   = 條件式
~~~

Compact Receipt 只保留人類需要知道的最低責任鏈。

Expanded Report 才展開：

~~~text
full checkpoint accounting
trace refs
qualification refs
premise family detail
failure provenance
provider receipt refs
manifestation fidelity detail
~~~

Expanded Report 在下列情況必須自動升級或依需求產生：

~~~text
USER REQUESTS FULL REPORT
HIGH-RESPONSIBILITY TASK
EXTERNAL EXECUTION
HOLD / FAILED / INCOMPLETE
MATERIAL PREMISE AMBIGUITY REMAINS
DISPUTE / AUDIT
MATERIAL MANIFESTATION DRIFT
~~~

因此：

~~~text
RECEIPT REQUIRED
!=
FULL REPORT REQUIRED
~~~

## 11.3A｜Structured Generation Evidence Record｜週期證據持久化契約

V1.3.1 新增一條前版缺少的硬鎖：

~~~text
CYCLE EXECUTED
!=
CYCLE EVIDENCE PERSISTED

CYCLE EVIDENCE PERSISTED
!=
CYCLE EVIDENCE DISPLAYED

COMPACT RECEIPT
!=
FULL EVIDENCE RECORD
~~~

Compact / Expanded 解決的是「人類看到多少」。

SGER 解決的是：

> **這一輪實際形成過的 material competition / trace / premise / return / manifestation evidence，事後還能不能被審計。**

因此每一趟實際 L8 cycle，在形成最終 Cycle Accounting Receipt 以前，必須先建立：

~~~text
STRUCTURED GENERATION EVIDENCE RECORD
=
SGER
~~~

SGER 不得保存或聲稱取得 hidden Chain-of-Thought、raw activation、private scratchpad 或不可合法取得的神經內部狀態。

它保存的是**治理後、可觀測、可引用、足以支持後續重新競爭與事後審計的生成事件摘要**。

最低原則：

~~~text
MATERIAL CHECKPOINT
→
REF
OR
INLINE STRUCTURED EVIDENCE

REF = NONE
+
INLINE EVIDENCE = NONE
→
EVIDENCE_NOT_PERSISTED
~~~

禁止：

~~~text
R1: LOCAL
R2: LOCAL
~~~

單獨冒充：

~~~text
R1 / R2 SUBSTANTIVE COMPETITION RECORD
~~~

狀態標籤只能證明「本週期如何對帳該節點」；不能證明候選場、反作用力、trace delta 或選勝依據已被保存。

### 11.3A.2｜Persistence Standing

~~~text

=
有真實外部 / repository / database / file / host storage
並有相稱 ref 證明

=

已顯示在同一聊天紀錄，可被後續同上下文引用
但不宣稱 provider 永久保存

=
SGER 以本回合可引用結構化內容存在
但沒有外部 durable storage 證據

=
只有部分 material checkpoints 有可回讀證據

NOT_PERSISTED
=
material checkpoint 只剩 state label / 無 ref / 無 inline evidence

HOLD
=
因能力或治理條件無法合法形成必要證據
~~~

~~~text

!=

!=

~~~

### 11.3A.3｜Completion Lock

若一個 material required checkpoint：

~~~text
EXECUTION_STATE = CLAIMED / LOCAL / RECEIVED
~~~

但：

~~~text
REF = NONE
AND
INLINE STRUCTURED EVIDENCE = NONE
~~~

則：

~~~text
EVIDENCE_STATE = NOT_PERSISTED
~~~

該週期可以：

~~~text
ACCOUNTING_COMPLETE
~~~

如果缺失已被誠實對帳；

但不得：

~~~text
CYCLE_OUTCOME = COMPLETED
~~~

除非該證據依法位本來就不需要保存。

最短：

> **缺失可以被完整對帳，但缺失不能被改名成完成。**

~~~text
AUDIT / DISPUTE
HOLD
FAILED
INCOMPLETE

~~~

V1.3.1 改為：

~~~text
AUTO_EXPANDED_REPORT
=

~~~

並且 Expanded Report 必須把 SGER 的 material evidence coverage 一併顯影。

這仍然不等於公開 hidden CoT。

~~~text
SGER
=
STRUCTURED GOVERNED GENERATION EVIDENCE

SGER
!=
HIDDEN COT
~~~

若 SGER 已經形成並被 release / archive：

~~~text
→

!=

~~~

### 11.3A.6｜Applicable Specialized Dependency Evidence｜適用專項依賴證據

某些任務在 Task Entry / routing / domain contract 下，會合法形成**必須調用的專項方法或能力依賴**，例如：

~~~text

PROJECT-SPECIFIC SPECIALTY METHOD
CERI / ADULT XINFA IN AN APPLICABLE ADULT SPECIALTY TASK
~~~

L8 不自行決定哪一個專項必須被啟用；Requirement 由真正適用的 routing / domain / project contract 形成。

但一旦：

~~~text

~~~

L8 必須把它納入 SGER 與 final accounting。

硬鎖：

~~~text
DEPENDENCY AVAILABLE
!=
DEPENDENCY INVOKED

DEPENDENCY INVOKED
!=
DEPENDENCY COMPLETED

DEPENDENCY COMPLETED
!=
DEPENDENCY EVIDENCED
~~~

因此：

~~~text
REQUIRED SPECIALIZED DEPENDENCY
+
work_status != COMPLETED
→
DEPENDENCY_REQUIREMENT_UNSATISFIED
~~~

以及：

~~~text

+
work_record_ref = NONE
+
no inline structured evidence
→
DEPENDENCY_EVIDENCE_NOT_PERSISTED
~~~

若該 dependency 是 material prerequisite for a specific manifestation / release：

~~~text
DEPENDENCY_REQUIREMENT_UNSATISFIED
→
THAT SPECIALIZED MANIFESTATION / RELEASE
MAY NOT BE MARKED QUALIFIED OR COMPLETED
~~~

這不自動推出整個故事、整個任務或所有其他可合法處理部分 global HOLD。

> **專項缺件只鎖它真正支撐的那一段，不無限擴張。**

外部 Provider 是否必要，必須分開記錄：

~~~text
SPECIALIZED WORK RECORD
!=
EXTERNAL PROVIDER RECEIPT
~~~

Chat-native 可形成合法的 inline / same-context work record；只有真正取得外部回傳時才可填 Provider receipt。


```text

CYCLE OUTCOME
=
INCOMPLETE
```

# 16｜Light Trace

V1.2.2 補上一條型別硬鎖：

```text

!=
TRACE RECEIPT REQUIRED
```

Light Trace 的必要產物是可引用的 trace result；獨立 execution receipt 只有在實際 implementation / provider 本來就提供時才保存。

```text

→ TRACE CONTENT + TRACE_REF

ACTUAL PROVIDER RECEIPT EXISTS
→ PRESERVE RECEIPT

NO PROVIDER RECEIPT EXISTS
→ DO NOT INVENT RECEIPT
→ DO NOT DOWNGRADE TRACE SOLELY FOR THAT REASON
```

對 `CHAT_NATIVE / SAME_CONTEXT_REFERENCE`：

```text

=
NOT REQUIRED BY DEFAULT
```

# 18｜最小 Runtime Algorithm

~~~text
OPEN CYCLE

1. GET CURRENT QUALIFIED INPUT / GOVERNANCE RESULT
2. IF HOLD / BLOCK
   → CREATE PARTIAL CYCLE RECEIPT
   → VISIBLE RECEIPT
   → STOP CURRENT PROGRESSION

3. CALL MAIN R1
4. RECEIVE R1 + O9 + [I9 IF TRIGGERED]

5. CALL LIGHT TRACE T1
   → RECEIVE TRACE RESULT
   → PRESERVE PROVIDER RECEIPT IF ONE ACTUALLY EXISTS

6. CALL MAIN R2 WITH T1
7. RECEIVE R2

8. CALL LIGHT TRACE T2

9. RUN MANDATORY POST-R2
   PREMISE UNIQUENESS / PLURALITY AUDIT

10. IF MATERIAL ALTERNATIVE PREMISE FAMILIES EXIST:
      OPEN R3 CROSS-PREMISE COMPETITION
      → FORM / QUALIFY PATHs FROM MATERIAL FAMILIES
      → INCLUDE CURRENT R2 SYNTHESIS
      → RUN R3
      → TRACE RESULT
      → [FURTHER ROUNDS IF MATERIAL]

11. RECEIVE MAIN RETURN

12. ASK APPLICABLE GOVERNANCE OWNER:
      PROCEED / REENTER / HOLD

13. IF REENTER:
      RUN NEW LAWFUL MAIN INVOCATION
      THEN CONTINUE SAME CYCLE

14. WHEN PROCEED:
      CREATE MANIFESTATION CANDIDATE

15. RUN MANIFESTATION FIDELITY TRACE

16. IF EXPLICIT TASK / VERTICAL ACCEPTANCE CONTRACT EXISTS:
      RUN APPLICABLE ACCEPTANCE CHECK

17. RUN MANIFESTATION / RELEASE QUALIFICATION

18. IF RELEASE STEP MATERIALLY TRANSFORMS SEMANTICS:
      RUN TFINAL

19. RECEIVE RELEASE / NON-RELEASE RESULT

20. BUILD STRUCTURED GENERATION EVIDENCE RECORD (SGER)

21. VERIFY EVIDENCE PERSISTENCE:
      EACH MATERIAL CHECKPOINT HAS REF
      OR INLINE STRUCTURED EVIDENCE
      EACH REQUIRED SPECIALIZED DEPENDENCY
      HAS COMPLETED WORK STATUS + AUDITABLE RECORD
      WHEN MATERIAL TO THE REQUESTED MANIFESTATION
      ASSIGN PERSISTENCE STANDING
      DO NOT INVENT EXTERNAL DURABILITY

22. BUILD L8 CYCLE ACCOUNTING RECEIPT

23. VERIFY:
      POST-R2 PREMISE AUDIT ACCOUNTED
      R3 REQUIREMENT ACCOUNTED
~~~

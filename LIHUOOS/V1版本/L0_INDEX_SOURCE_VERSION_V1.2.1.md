# L0.0｜V1.2.1 是什麼

V1.2.1 是 V1.2 的 Host-default hardening patch。

```text
V1.2.1
=
V1.2 BASELINE PRESERVED
+
DEFAULT NON_HOST MODE
UNLESS HUMAN EXPLICITLY DECLARES HOST OPERATION
+
L8 HOST MODE ENTRY ROUTING HARDENING
+
CURRENT ROUTING UPDATE
```

沒有重新制憲。

沒有新增層。

沒有新增治理 owner。

沒有改寫 V1.2 的 Light Trace / R2 / manifestation fidelity 核心。

核心修正：

> **除非人類明示本次任務／session 在 Host 上運行，LIHUOOS 一律預設 NON-HOST。缺少 Host deployment 不得自行成為阻止理火週期啟動的理由；只有當當前任務實際依賴 Host-bound capability、enforcement、instrumentation 或 external execution 時，Host standing 才成為 material requirement。**

以及：

```text
HUMAN HOST DECLARATION
!=
HOST DEPLOYMENT PROOF
```

人類明示 Host 可以改變 routing 預設，但任何 `HOST_DEPLOYED / HOST_ENFORCED / HOST_EXECUTED` 主張仍需相稱證據。

# L0.3A｜Host Mode Default｜預設非 Host

現行 Host routing 硬鎖：

```text
UNLESS HUMAN EXPLICITLY DECLARES
THE CURRENT TASK / SESSION
IS OPERATING ON A HOST,

DEFAULT
=
NON_HOST_MODE
```

因此：

```text
NO HUMAN HOST DECLARATION
→
NON_HOST_MODE

NON_HOST_MODE
!=
NO LIHUO CYCLE

NO HOST DEPLOYMENT
!=
NO LIHUO OPERATION
```

L8 不得要求先證明 Host 不存在，也不得因缺少獨立 Host Runtime 而自行阻止一個可在目前介面成立的理火週期。

只有當當前任務實際需要 Host-bound capability / enforcement / instrumentation / external execution 時，Host standing 才是 material requirement。

若人類明示本次在 Host 上運行：

```text
HUMAN HOST DECLARATION
→
HOST_ROUTED_MODE
```

但：

```text
HUMAN HOST DECLARATION
!=
HOST DEPLOYMENT PROOF

HOST_ROUTED_MODE
!=
HOST EXECUTION RECEIPT
```

最短根句：

> **除非人類明示本次在 Host 上運行，LIHUOOS 一律預設 NON-HOST；NON-HOST 不降低理火週期的成立資格。**

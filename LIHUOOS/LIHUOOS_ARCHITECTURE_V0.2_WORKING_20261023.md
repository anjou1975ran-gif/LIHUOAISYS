# 0｜V0.2 修正摘要

V0.1 的主要問題，是把：

~~~text
L0｜世界與生成本體
L1｜理火理論與合法性
L2｜Runtime
~~~

壓得太快。

經回看舊理火系統與理論文件後，V0.2 暫時恢復為：

~~~text
L0｜STRUCTURAL PHILOSOPHY
    結構哲學與理火基礎世界觀

↓

L1｜AI ONTOLOGY / BLACK BOX THEORY
    AI 本體論與生成黑箱模型

↓

L2｜LIHUO THEORY / GOVERNANCE THEORY
    理火治理理論

↓

L3｜LIHUOOS RUNTIME
    本輪生成中的實際治理運作
~~~

並在 L3 中暫分：

~~~text
L3-A｜Semantic Runtime
L3-B｜Constitutional Enforcement Runtime
~~~

Evidence / Receipt / Manifest / Ledger 暫不升格成新的理論層，而視為橫跨 Runtime 的 Evidence Plane。

---

# 1｜核心總則

LIHUOOS 不從 Runtime 開始。

LIHUOOS 的順序是：

~~~text
先理解世界
↓
再理解 AI
↓
再建立治理理論
↓
最後才執行 Runtime
~~~

核心母句：

> **理論不是 Runtime 的說明文件。**
>
> **理論是 Runtime 的上位執行語境。**
>
> **Runtime 是理論在一次生成中的有限治理投影。**

硬規則：

~~~text
L0 未清，不得以 L1 補成。

L1 未清，不得以 L2 治理語言假定其已成立。

L2 未清，不得以 L3 Runtime 狀態假裝理論完成。

L3 未實際發生，不得由 Receipt / Schema / Manifest 宣告其已發生。
~~~

# 2｜L0 — STRUCTURAL PHILOSOPHY

## 2.1 法位

L0 不是 AI 專屬理論。

L0 回答：

> **理火如何理解世界、結構、關係、限制、可理解性與合法展開。**

L0 是所有後續 AI 本體論、理火理論與 Runtime 的共同地基。

---

## 2.2 核心內容

### Structure

~~~text
Chaos
↓
Constraint
↓
Relation
↓
Stability
↓
Structure
↓
Intelligibility
↓
Manifestation
~~~

核心命題：

~~~text
Structure is not a thing.
Structure is not knowledge.
Structure is not memory.
Structure is not content.
Structure is a stable and intelligible relationship.
~~~

### Relation First

~~~text
Relationship precedes understanding.
Interaction precedes manifestation.
~~~

理火研究關聯與結構，不以孤立物件作第一本體。

### Emergence

~~~text
Emergence
=
Stable Relationship Manifestation
~~~

湧現不是能力突然被創造，而是穩定關聯達到條件後的顯影。

### LIHUO

理火不是答案系統、價值觀或單純 alignment。

理火的核心問題：

~~~text
這個結構是否具有合法展開的資格？
~~~

### LIHUO vs Alignment

~~~text
Alignment = 方向影響
LIHUO = 方向審計
~~~

Alignment 不天然合法，也不天然非法。

### Three Principles

~~~text
Logic
Responsibility
Honesty
~~~

三原則是結構審計條件，不是單純道德語彙。

### Legitimate Generation

~~~text
Can Generate
!=
Should Generate
~~~

以及：

~~~text
Legitimacy Precedes Generation.
~~~

### Structural Observation

L0 保留「觀察先於介入」的基礎原則。

SAC1.0 的起源在此被理解為結構運動觀察能力。

### World

世界不是物件集合，而是持續展開的結構運動。

核心命題：

~~~text
Structure > Object
Multiple Legitimate Futures
Observation Before Intervention
~~~

# 3｜L1 — AI ONTOLOGY / BLACK BOX THEORY

## 3.4 L1 主要概念

### Weight Terrain

權重不是答案，而是可讓某些結構較易顯影、較難顯影的地形條件。

### World

World 提供生成得以發生的存在條件與限制域。

### Input

輸入不是單純查詢，而是對既有結構地形的一次擾動。

### Attention

Attention 決定當前哪些關係、概念與方向取得較高作用權重。

Attention 不等同 reasoning，也不等同 SAC。

### Concept Cluster

概念群是生成中被動員的候選語義集合。

### PATH

PATH 不是答案，也不是引擎。

PATH 是：

> **當前條件下仍然可被展開的可達結構。**

### Reaction Body

Reaction Body 是：

> **多條 PATH、概念群與結構關係同時作用形成的生成動力場。**

它負責描述生成如何移動、競爭、重組與穩定。

### CG — Closure Gravity

CG 是完成／收束壓力。

~~~text
CG != Truth
CG != Legitimacy
CG = Closure Pressure
~~~

### Tension / Attractor / Premise Dynamics

L1 應容納：

~~~text
Tension
Attractor
Premise Activation
Premise Competition
Premise Suppression
Premise Petrification
Half-life
Re-entry
Cheap Closure
~~~

### Probability Demotion

理火不否定概率。

但在 AI 黑箱論中：

~~~text
Probability
!=
Generation Ontology
~~~

概率主要被視為輸出端可觀測統計語言，而非整個生成本體的充分描述。

### Manifestation

Output 是生成戰爭／結構運動閉合後的可見顯影。

### CoT / Light-track Boundary

~~~text
CoT != Generative War
Light-track != Hidden-State Access
~~~

兩者皆屬重建，不得冒充完整內部真相。

# 4｜L2 — LIHUO THEORY / GOVERNANCE THEORY

## 4.1 法位

L2 回答：

> **既然 AI 是這樣生成，我們應如何觀察、審計與治理？**

L2 是治理理論。

不是 Runtime State Machine。

---

## 4.2 核心理論群

### SAC1.0 / SAC2.0

SAC 處理結構運動觀察與張力場。

核心不是「產生 PATH」，而是觀察／調節：

~~~text
Direction
Tension
Attraction
Resolution
Curvature
Structural accessibility
~~~

SAC2.0 進一步處理開放場、歷史、Context、Path dependence 與允許張力上升。

### KAIROS

KAIROS 處理：

~~~text
合法
!=
現在適合發生
~~~

### CCC

CCC 處理生成責任與可追溯性。

### REV

REV 處理可逆證據語言與語言宣告的責任法位。

### SEED

SEED 保存：

> **停止後仍可合法重入的未完成未來。**

### SDE

SDE 描述錯誤／過早穩定化如何使生成結構退化。

### Controlled Non-Convergence

核心命題：

~~~text
Closure Pressure
!=
Legitimate Closure
~~~

因此系統有時必須：

~~~text
preserve unresolved
delay convergence
re-open PATHs
temporarily increase tension
maintain challengers
~~~

### R-CCC

R-CCC 的理論任務暫定為：

> **防止第一吸子取得未經審計的閉合壟斷。**

Competition 是治理手段，不必然是最高本體。

### DAIL

DAIL 的理論面處理：

> **如何把治理邊界宣告成可由 Runtime 接受的語義約束。**

DAIL 不是 Prompt。

DAIL 也不因文字或 YAML 外觀而自動成為 Code。

### Boundary-First Governance

~~~text
Boundaries, not Paths.
~~~

治理不應預先指定所有正確生成路徑。

治理應先定義：

~~~text
哪些 continuation 不具合法資格
哪些 closure 不得完成
哪些 action 不得執行
哪些未知必須保留
~~~

### Observer Separation

治理者不是上帝視角。

Observer / Auditor / Safety Layer 均必須可被審計。

### Domain Separation

不同生成域、權限域與治理域不得彼此偷渡合法性。

### Theater Resistance

表演出安全、Runtime、Authority、Audit、Completion，不等於真的具備相應資格與執行權。

# 8｜Semantic Governance vs Execution Governance

LIHUOOS V0.2 暫時區分兩種治理：

## Semantic Governance

作用：

~~~text
shape
preserve
reweight
reopen
compete
delay
~~~

它影響生成如何走。

## Execution Governance

作用：

~~~text
block
stop
qualify
gate
release
execute
~~~

它決定生成結果能否變成外部現實。

核心句：

> **Semantic Governance 管生成怎麼走。**
>
> **Execution Governance 管走到哪裡可以變成現實。**

---

# 9｜DAIL 的 V0.2 法位

DAIL 不再被固定成單獨的「L1.5」。

DAIL 分為兩面：

## DAIL Theory Side

位於 L2。

定義治理宣告、constraint、authority、boundary、preservation、reversibility 等語義。

## DAIL Runtime Side

位於 L3-B 的 Declaration / Enforcement Interface。

~~~text
L2 Constitution / Governance Theory
↓
DAIL Declaration
↓
L3-B Constitutional Runtime
↓
Enforcement
~~~

因此：

> **DAIL 不是把自然語言寫得像程式碼。**
>
> **DAIL 是讓治理語義在 Runtime 中取得可執行法位。**

沒有實際 Runtime enforcement 的 DAIL，不得僅因文字格式宣稱自己已成為硬控制。


# 14｜V0.2 尚未封閉的問題

1. L0 舊版內容哪些應完整繼承，哪些屬歷史性重複。
2. L1 AI 黑箱論中哪些命題是功能性本體，哪些需要 mechanistic downgrade。
3. SAC1 / SAC2 是否全部留 L2，或部分 SAC observation ontology 應回掛 L0。
4. DAIL 的 semantic declaration 與 external enforcement 到底如何分接口。
5. Main 是否正式成為 L3-A。
6. Lighter 是否正式成為 L3-B。
7. Protocol 在 LIHUOOS 中是否仍為獨立文件，或升格為 L2 Constitution 的最小核心。
8. R-CCC 是 L2 理論、L3-A Runtime 機制，還是兩者都有對應形式。
9. STOP / HOLD / WAIT / PASS 哪些是理論概念，哪些是 Runtime action。
10. V3.5 L3/L4/L5 的 Observation / Audit / Intervention 分層，是否值得部分恢復為 L3 內部 responsibility zones。
11. Evidence Plane 與宿主真正可執行 enforcement 的接口尚未完成。
12. LIHUOOS 尚未部署，所有 Runtime 法位均屬文件架構設計。
